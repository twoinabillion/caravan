# 재플레이 2차 · 새 seed의 분기와 재접속 경계

Sang의 “다시 해줘, 플레이한 다음 이상한 점 발견해서 고쳐” 요청으로 진행했다.
기존 정책을 같은 seed로 반복한 검사가 아니다. 새 seed181101–181110과 경주
우회·휴식/탐색 정책을 사용해 실제 엔진을 처음부터 종결까지 실행하고 로그를 읽었다.
별도 에이전트를 새로 만들지는 않았다.

## 확인하고 고친 것

1. **경주 밤의 ‘하루/낮잠’.** before/player01 n28은23:25에 ‘하루 쉰다’를
   골랐지만300분 뒤였다. 선택은 ‘쉬어간다 (5시간)’, 본문은 ‘한동안 눈을
   붙였다’로 바꿨다. 시간·회복·식량 효과와 아이/주인공 화자5개는 같다.
2. **레버를 당기면 된다 → 준비물이 없어 철수.** before/player05 n158은
   맨손 접근 성공을 당기기만 하면 된다고 읽었고, n159는 쇠파이프·은수·화염병이
   없어 철수만 가능했다. 진입에서 지렛대를 먼저 밝히고 관찰/정비/접근 성공도
   필요한 준비가 남았다고 쓴다. 기존 준비 조건·판정·철수 경로는 유지했다.
3. **하루 굶었다는 추정.** 허기 위기는 두 번의 끼니 실패로도 올라오므로
   24시간을 단정하지 않고 끼니를 걸렀다고 쓴다. 위기 발생/식량 보급 효과는 같다.
4. **실제 변화량과 다른 결과표.** before/player05 n239는 연료3.788831L가
   남았는데 결과표는 -4L였다. player10 n168은 차체100에서 중재 +3%가 표시됐다.
   고철7에서 -8을 요구하는 별도 재현도 같은 원인이었다. 숫자 효과 주인의
   fuel/scrap/hull 처리에서 실제 post-minus-pre를 표시하게 수정했다. 상태 계산은
   그대로고 부동소수점 표현만 정리한다. 가짜 행정소 실패 본문도 지급액8을
   고정하지 않는다. 기존 깎기 특기로6만 내는 경우도 함께 확인했다.
5. **첫 읽기 캡처 전 지급 결과가 새 원문을 빌림.** 선택을 지불한 뒤 첫 UI
   캡처 전에 저장/재시작하고 정의가 달라지는 경계를 단위 재현했다. 예전에는
   비용은 재지불하지 않아도 새로운 대사·화자·scene marker가 나왔다. 지급 시
   authoredView에 내용만 고정하고, 실제 레이아웃/커서는 기존 UI view가 맡는다.
   legacy text-only 결과는 저장 문장을 읽고 오늘의 턴/화자 배열을 가져오지 않는다.
   내용 생성이 실패해도 지급 결과를 먼저 잠그고 정본 문자열로 계속할 수 있다.

게임 디렉터/대화 시스템 기준으로 말투와 비용은 유지하며 연결을 수정했다.
human-voice 기준도 필요한 사실을 고치는 데만 적용했다. 새 줄거리·보상·쉬운
성공 판정·시각 자산·CSS/레이아웃은 추가하지 않았다.
