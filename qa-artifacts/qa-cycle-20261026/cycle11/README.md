원정 후 아래 문제를 수선했다. 수정 후 새 원정은 12차로 분리한다.

1. 레오·재이 공연이 이동 없이 다음 정착지에서 완료됐다는 결과. 현재 공연으로 맞추고, 장터 삽화와 일치하도록 신규 발견을 정착지 탐색에 한정했다. 이미 열었거나 지급된 저장은 이어 읽는다. [근거](survival/busking-fix/README.md)
2. 수리 전 고장 난 라디오에서 트로트가 나온다는 짧은 대사. 기존 `radio_fixed` 조건을 적용했다. [근거](systems/report.md)
3. 재이가 처음 렌치를 정리하는 대사가 다음 날 다시 발생. 일회성 대화로 바꾸고 저장 후 반복을 차단했다. 이전 버전에서 추적하지 않은 과거 재생을 추측해 지우지는 않는다. [근거](systems/report.md)
4. 양어장 잉어 방생 결과의 주인공 발화가 실제 UI에서 `???`로 표시. `me`를 명시했다. 본문·효과·확률 및 과거 지급 문구는 유지한다. [근거](story/REPORT.md)
5. 그림 확대 버튼의 CSS가 클릭을 아래의 대사 넘김 버튼으로 통과시킴. 기존 소유 규칙 두 곳을 고쳤다. 실제 Chrome에서 진입/결과 확대·닫기 후 읽던 단계가 유지됐다. [근거](survival/scene-zoom-fix/README.md)

무인 양어장·살아 있는 온실·폐 김치공장의 사람·시설 불일치 세 곳을 고쳤고, 밤손님은 장면을 더 구체적으로 보여 주는 전용 그림을 추가했다. 밤손님의 실제 옛 연결은 운전대와 앞길만 보이는 exhaustion-v2다. 처음 검토한 두 사람이 나오는 exhaustion.webp는 이 키에 쓰이지 않아, 밤손님을 부재 동료 오류로 세지 않는다. 전용 그림은 총 네 장이다. 네 필수 canonical reference를 붙여 생성한 master를 보존하고 1024×576 sRGB WebP로 내보냈다. 실제 `/__live/assets`에서 먼저 확인한 뒤 연결했고, 정상 공개 행동으로 도달한 새 진입 저장을 실제 Chrome에 불러 확인했다. [그림 출처·검수](visual/provenance.json), [자산 미리보기](visual/gallery-before-wiring.png).

실제 화면에서는 네 장면의 진입→선택→결과→길 복귀를 확인했다. 양어장 결과는 새로고침 후에도 화자·그림·지급 결과를 보존했다. 기존 읽던 장면의 저장된 그림 키는 그대로 유지하므로, 새 그림 검수에는 같은 정상 경로의 부분 재생을 사용했다. 부분 재생/발화 캡처 보완 재생은 모두 cohort에서 제외했다. Live 화면은 무한자원 모드이므로 비용 검증으로 세지 않는다.

480px 사건 그림 영역에서 핵심 대상과 문장을 직접 확인했다. 브라우저 뷰포트 조절이 timeout으로 실패했고 로컬 QA 미리보기 파일 접근도 브라우저 URL 보안 정책에서 차단됐다. 우회하지 않았으며 360px 실제 화면은 이번 차수에서 미검증이다. 실물 휴대폰 검증도 아니다. `fishfarm-after-desktop.png`는 옛 저장 키가 보존된 중간 화면이며 새 그림 통과 증거가 아니다. `fishfarm-result-speaker-after-reload.png`는 reload 도중 초기 화면이며, 복원 완료 증거는 [fishfarm-result-restored.png](visual/fishfarm-result-restored.png)다.

11차 전체 소스 검사를 실행하는 동안 확대 버튼의 red 회귀가 추가되어 중간 실행은 1건 실패했다. 이 실패 로그를 보존했으며 수선 후 12차 동결본에서 전체1,246/1,246을 재검증했다. [중간 실패](test-source.log), [동결 후 통과](../cycle12/test-source.log).
