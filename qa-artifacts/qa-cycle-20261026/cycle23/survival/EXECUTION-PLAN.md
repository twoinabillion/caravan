# 23차 survival 실행 전 계획

현재 상태: **계획만 작성, 게임 실행 0회**. Root의 cycle23 동결 파일과 명시적 시작 신호를 모두 받기 전에는 게임 VM, 정책 테스트, 부분 재생을 실행하지 않는다. 생산 소스도 편집하지 않는다.

## 정상 새 여정

- seed: `283001`. 새 게임부터 본편 엔딩까지 1회가 기본이다. 목표는 민지·박선생·은수와 `core_quarantine` 공동감시다. 실제 영입·엔딩이 다르면 그대로 보고하며 목표 달성으로 바꾸어 기록하지 않는다.
- C22의 용량·disabled·실패 상태 차단 정책을 이어 쓰되, 목표 동료와 방문 우선순위는 밀양 민지 → 전주 박선생 → 대전 은수로 바꾼다. 현재 공개 경로와 영입 목표가 우선이고, 알려진 정착지가 연결되지 않으면 공개 지도에 나타나는 경로를 따른다.
- 영입 전에 공개 정비소에서 필요한 좌석을 마련한다. 실제 잔여 좌석·기존 승객·진행 중 영입 상태를 확인하고 화면에 제시된 초대와 합류만 수락한다. 영입 과제의 다음 행동은 현재 준비 조건을 읽고, 야영을 요구하면 정상 야영 뒤 진행한다. C22의 하룻밤 전 readiness false 두 건을 성공 행동으로 세지 않았던 원칙을 유지한다.
- 기본 준비물은 이전 성공 여정과 같은 food pack을 사용한다. 다른 선택을 늘리려고 보급을 낮추지 않는다. 식량·물·연료는 현재 보유량·상한·전체 묶음 수납 가능·가격·enabled를 함께 확인해 구매한다. 목표 재고는 물 `min(max, 인원×7)`, 식량 `min(max, 인원×6)`, 연료 `min(max, 50)` 범위다.
- 보급 긴급 기준은 물 인원×3 미만, 식량 인원×2 미만, 연료 15 미만이다. 현재 시장 구매를 경로 변경보다 먼저 시도하고, 관측한 시장으로 가는 최단 공개 경로를 사용한다. 더 긴 우회로로 재고를 소진하지 않는다. 필요한 경우에만 현재 공개 도보 연료 회복 또는 제한된 지역 탐색을 사용한다.
- 같은 물품·보유량·상한·묶음·가격 상태에서 교환이 거절되면 시간만 바뀌었다고 반복하지 않는다. 임의 자원·좌석·flags·사건 주입, 숨은 이동, 고정 RNG 밀기, 유리한 결과를 위한 reload는 하지 않는다.
- 피로 64 초과 또는 정상 밤 휴식 기회에 야영한다. 차량 상태가 낮을 때 소유 부품으로 수리한다. 공동감시가 공개 조건을 충족하도록 현재 동료의 건강·기분·보급을 실제 행동으로 돌본다. 결말 선택 화면에서 enabled 조건과 준비로 돌아갈 수 있는 공개 선택을 읽고 결정한다.

## 선택과 기능의 다양성

- 이전 primary 원정의 정규화 event/choice 노출 횟수를 읽어 덜 선택한 공개·enabled branch를 우선한다. 생존, 정상 영입, 본편 진행이 희귀 선택 수보다 우선이다. 과거 로그를 알고 만든 목표형 QA이며 블라인드 플레이로 주장하지 않는다.
- 목표 동료의 고유 선택, 현재 참여 가능한 야영 대화, 하루 한 번 범위의 일반 대화와 표시된 능력·장비 기회를 활용한다. 필요 자원을 실제로 소유했을 때만 공개 제작을 한 번 이상 시도할 수 있다. 전투는 정상 경로에서 발생하면 처리하며 검증 수를 늘리려고 강제하지 않는다.
- 진행 방향과 맞는 공개 배달·편지 의뢰 한 건, 표시된 지역 주민 첫인사와 후속 응답, 보급을 위한 지역 일감을 사용한다. 라디오는 해당 공개 도구와 진공관 등 조건이 실제로 갖춰질 때만 진행한다. 가용 기회·실행·성공을 분리 집계한다.
- 보리는 이번 세 동료 조합의 필수 목표가 아니다. 희귀 후속을 쫓아 좌석·자원을 소모하지 않는다. 자연 노출이 있으면 보존하지만 미발생은 그대로 남긴다.
- 최종 `seoul_decision`에서 실제 활성화된 코어 보존 선택을 우선한다. 비활성 선택을 API로 강행하지 않는다. 목표 조건을 정상적으로 회복할 수 없으면 실제 도달한 결말과 이유를 보고한다.

## 관측·저장·리로드

- 새 원정 시작 시 동결 manifest의 40개 src 해시와 엔진 LF hash를 확인한다. runtime 종료, 전체 읽기 종료에도 각각 새 파일로 저장해 비교한다. 알고리즘은 동결 `engineFiles` 순서의 UTF-8 내용을 한 LF로 이어 붙이며 파일명은 넣지 않는다.
- 모든 사건은 선택 전 정상 export를 보존한다. 진입 reader를 실제 `buildStoryTurns` 경로로 캡처한 뒤 entry reload, 선택·결과 reader·receipt 캡처 뒤 paid reload를 수행한다. 동일 소스 reload 연속성으로 보고하며 과거 버전 legacy 검증으로 부풀리지 않는다.
- 실제 reader의 `knownSpeaker`, authored turns, record 매체, displayName, 현재 scene keys를 기록한다. `UI.speak`, 주행 짧은말, NPC 첫인사와 후속 전체, 노트, 일감·능력·제작 응답과 엔딩까지 읽는다. 객체 키 순서가 다른 것을 화자 불일치로 세지 않고 deep equality를 사용한다.
- paid reload는 자원·시간·flags·노트가 다시 지급되지 않는지 확인한다. 로드 실패, 실제 생략, 출력 실패도 원본 그대로 보존하고 실제 entry/paid 횟수·누락 사유를 따로 보고한다.
- 모든 trace와 attempt 디렉터리는 새 이름으로 생성한다. 실패·사망 원본을 덮어쓰지 않는다. 별도 재시도가 필요하면 root 지시와 원인 판정 뒤 분리하며 정상 새 여정 수와 혼합하지 않는다.

## 전편 및 실제 그림 검수

- 엔딩 도달 뒤 전체 선택 카드·진입문·결과·노트·짧은말·NPC·결말을 실제 읽는다. 이전 본문과 같은 항목도 동일성 대조 근거를 남긴다. 새 문장, 명시된 과거 행동, 시간 경과, 획득 출처, 현재 인원과 역할을 우선 확인한다.
- 실제 runtime scene key를 현재 resolver/alias에 따라 최종 파일로 풀어 unique 파일 목록과 해시를 만든다. 모든 고유 파일을 contact sheet로 확인하고 의심하거나 새 매핑인 장면은 실제 원본을 확대한다. key 존재 검사와 픽셀 검수는 분리한다.
- 신규 그림은 그 사건의 모든 결과·노트와도 대조해 선택 전 그림이 결과를 선행하지 않는지 확인한다. 본 원정에서 안 뜬 장면을 자연 검수에 포함하지 않는다. 실제 브라우저·모바일 CSS crop 검수로 주장하지 않는다.
- 확정 결함, 명료성, 취향, 정적 파생, 정책 실패를 구분한다. 새로운 문제는 증거와 재현 가능성부터 root에게 보고하고 생산 수정은 하지 않는다.

## 현재 준비 범위

C22 정책·observer·adapter·보고서, C19/C20의 민지/은수 영입 목표 설정을 읽고 이 계획을 작성했다. 게임·정책 체크·source 해시 실행은 하지 않았다. 동결본을 받은 뒤에만 QA 전용 runner/policy를 준비하고 시작 전 guard를 통과시킨다.


## 23차 실행 승인 반영

Root 동결·실행 승인을 받았다. 40src 엔진 hash `8cb29d99d11f89115ad974f7021b59d8373f85f8a7cf37fdbca18102fb9730f3`; 22차 대비 03-data만 바뀌며 그림 18개 신규와 레오 재사용안은 이번에 연결하지 않는다. C22 기존 prior-choice-counts를 그대로 사용하고, 새 정적 coverage 계획 때문에 정책을 바꾸지 않는다. 같은 날 follow 단계의 공개 CTA가 야영을 안내하면 recruitstep API를 호출하지 않는 관측 guard만 추가한다. 이전 정책의 변경 허용 범위는 위에서 계획한 목표 동료·방문지·결말이다. 기존 seed UI 부분 재생은 현재 불필요하므로 실행하지 않는다. 브라우저 실제 화면 검증은 pending이다.
