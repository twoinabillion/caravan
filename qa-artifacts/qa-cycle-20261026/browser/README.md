# 실제 Chrome 화면 검수

기존 Studio 앱이 실행 중이지 않아 그 화면을 검수했다고 주장하지 않는다. 기존 프로젝트의 `dev:live` 설정으로 4319 미리보기를 열고, 저장이 없는 QA 탭에서 `가온`이라는 새 여정을 만들었다. 사용자 개인 저장을 가져오지 않았다. 브라우저는 live의 무한 자원 모드이므로 비용·생존 검증은 별도 유한 자원 엔진 원정과 경계 검사에 근거한다.

## 직접 조작한 흐름

- 모바일 390×844 설정으로 준비 → 도윤과 수리·이름·민원·부모님 기록·열쇠 선택 → 작별 → 부산 DAY1 09:45까지 실제 버튼으로 진행했다. 읽기/선택/결과 재접속을 확인했다.
- 작별 장면에서 민원 사본을 이미 챙긴 분기와 중복되는 건네기를 발견했다. 현재 작별은 도윤이 자기 원본을 접어 넣는다. 옛 지급 기록은 유지한다.
- 정차 지역지도 → 전체 여정 → 새로고침 → 전체지도와 지역지도 각각 보존 → 전체지도 닫기 → 지역지도 닫기/다음 출발 접근을 확인했다. 복원 대상을 안정적인 도구 ID로 수정했다.
- 메뉴의 실제 내보내기로 생긴 파일을 `opening-normal-browser-backup.json`에 보관했다. 파일 복원 미리보기·명시적 확인·현재 여정 교체를 실제 UI로 실행했다.
- cycle3/story/attempt02의 자연 획득 세이브로 진료대와 등대에 진입했다. 두 그림의 실제 모바일 크롭, 본문, 선택지, 결과, 길 복귀를 확인했다. 강제로 사건 ID를 주입한 화면이 아니다.
- cycle2/story/attempt01의 정상 결정 직전 저장에서 세 동료가 자격을 갖춘 공동감시 선택 → 에필로그 → 상위망 후일담 → 엄마와 재회 → SESSION1END → 여정 마무리까지 버튼으로 완독했다. 브라우저에서 캠페인 전체를 완주한 것은 아니다.
- 그 과정에서 가사 기록 뒤 레오의 말에 화자명이 생략되는 문제를 발견했다. 문서/방송 출처가 끼어들면 이름을 다시 표시하도록 수정하고, 같은 저장·같은 페이지에 최신 코드를 적용해 이름 복구와 읽기 위치 보존을 확인했다. 문서·대사 원문과 지급 결과를 변경하지 않는다.
- 종료 후 새로고침은 타이틀로 돌아가며 `지난 여정 기록`에 DAY14·1204km·동료·노선 완주 기록이 보존됐다. 완료 저장 제거/요약 보관이라는 기존 계약이다. 이후 보관했던 `가온` DAY1 09:45 QA 세이브를 UI로 복원했다.
- 정상 과거 원정의 조달 활성 저장(DAY91 대구, 고철0, 부품17)을 재개해 허브에 들어가기만 해도 부품2가 소모되고 고철24가 자동 지급되는 오류를 재현했다. 허브의 자동 완료 호출을 제거한 뒤 같은 저장으로 재검사했다. 허브/장터 진입은 고철0·활성 의뢰를 유지했고, 해당 카드의 `전달한다`를 눌러야 고철24와 새 제안이 나타났다. 길로 돌아가기 → 새로고침 → 장터 재진입 뒤에도 고철24로 유지됐다. 유한 자원 비용·상태 및 종료 방어는 별도 엔진/UI 회귀 검사로 확인했다.
- 활성 의뢰 카드는 다음 행동만 보여 주고, 수락 전 제안에는 약속한 보상을 유지했다. 실제 시장 소문의 `밀양 장터은` 조사도 `밀양 장터에서는`으로 고쳤다.
- 같은 정상 저장에서 제작대의 화염병을 선택해 필요 연료5L·소모2L·남길3L 안내와 실제 제작 → 접기 흐름을 확인했다. Live 무한 자원 화면이므로 이 화면을 비용 정산의 증거로 세지 않는다.
- 게시판 검수를 마친 뒤 보관했던 `가온` DAY1 09:45 시작 저장을 다시 UI로 복원했다.
- 지하상가 위험 안내는 seed265002를 현재 코드의 공개 행동으로 재생해 얻은 공식 export에서 확인했다. 원래 5차 trace322 직전의 시각·자원·위치·동료와 일치하는 별도 재현 저장이며, 원본 저장이나 새 독립 여정으로 세지 않는다. 실제 선택 화면과 접근성 이름 모두 `위험` 한 번만 표시되고 무료 철수 → 결과 → 길 복귀가 이어졌다. 기존 민지의 탐색 퍼크 부품 보너스는 별도로 유지됐다. 검수 후 `가온` 시작 저장을 다시 복원했고 임시 모바일 크기 설정도 해제했다.
- 6차 시스템 원정의 정상 `entry-81-seoul_core-export.json`으로 코어의 ‘143년의 흔적’ 선택을 실제로 읽었다. 수정 전에는 미소지 응원봉/사진을 꺼내 놓고 부재한 재이가 말하던 화면을 재현했다. 수정 코드를 적용해도 이미 지급된 결과는 옛 문구·커서를 유지했다. 이후 비용 토론 → 최종 결정 → 수원에서 준비(60분)의 공개 복귀를 거쳐 같은 미지급 백업을 다시 불러왔다. 수정 후 결과는 실제 발견한 기록을 수첩에서 읽고 현재 화자인 상혁이 말하며, 없는 물건·동료를 만들지 않았다. 결과 → 비용 토론 → 결정 → 수원 준비까지 다음 행동도 실제로 이어졌다. 마지막에는 직접 보관한 `가온 DAY1 부산 09:45` QA 시작 파일을 명시 확인으로 복원했다. 이는 정상 엔진 원정 저장의 브라우저 분기 검증이며 새 브라우저 캠페인 완주로 세지 않는다.
- 실제 브라우저 로그의 관측 오류는 다른 Chrome 확장 content.js에서 발생한 includes TypeError 4개였다. 게임 출처 오류로 합산하지 않았다.

10차 고정본을 실제 적용 배지로 반영한 뒤 최신 코드 상태와 `가온 DAY1 부산 09:45` 보존을 확인했다. [마지막 미리보기](final-preview-cycle10.jpg). 임시 모바일 viewport는 해제된 상태다.

## 도구 문제와 한계

download 대기를 한 호출 안에서 클릭과 함께 기다리다가 도구 응답이 장시간 지연됐다. 파일은 실제로 생성됐으며 이를 성공적인 즉시 다운로드 검사로 기록하지 않는다. filechooser도 같은 형태에서 약25분 지연됐고, 이후 **선택 대기 등록+클릭 / 다음 호출에서 chooser에 파일 지정**으로 나누어 정상 응답을 얻었다. 기존 chooser 재사용은 unknown ID로 실패하여 재사용하지 않았다. native Chrome 창은 제어 도구에서 찾지 못했다. 실패를 게임 오류로 세지 않는다.

실물 휴대폰·터치·음성 청취·패키지 설치·전체 그림 전수/모든 무작위 분기 검수는 하지 않았다. 실제 화면 검사와 엔진/마크업 검사, 원본 그림 검수를 구분한다.
