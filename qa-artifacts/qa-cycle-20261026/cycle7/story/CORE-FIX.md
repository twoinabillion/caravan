# 코어 앞 흔적의 소유 근거 수선

7차 여정 실행 전 수선이다. 아래 검증은 명시적 fixture이며 새 자연 여정으로 세지 않는다.

6차 systems `player02/attempt03/player02-trace.json`의 n82에서 `143년의 흔적을 펼친다`를 실제 선택했다. 획득 흔적은 이송표·서울말·세 가설·이송로·동의문 다섯 개였지만, 결과는 응원봉·물병·네 컷 사진 실물을 나란히 놓았다고 서술했다. 원본 행은 `core-original-natural-finding.json`으로 보존했다.

근본 원인은 `req.traces:5`가 흔적을 알고 있다는 조건인데 실물 소유 조건처럼 쓰인 데 있다. 이송표 원본은 면사무소에 남을 수 있고, 네 컷 사진의 두 선택은 기록하거나 제단에 돌려놓는 행동이다. 응원봉도 수리해 소지하거나 분해해 축전지만 쓰는 두 선택으로 나뉜다.

`src/03-data.js`의 해당 결과만 수첩에 남긴 실제 획득 흔적 목록으로 바꿨다. 청록 응원봉은 `trace_cortis`와 현재 소지품 수량이 모두 있을 때만 수첩 옆에 놓는다. 사진·물병·이송표 실물을 새로 소유한 것으로 처리하지 않는다. 재이는 현재 동료일 때만 기록을 짚으며, 동적 화자 경로도 같은 조건을 따른다. 실제 `07-ui.js`의 `buildStoryTurns`를 호출해 재이 부재 시 세 인간 대사가 모두 주인공에게 배정되는 것을 확인했다. 과거에는 첫 대사가 재이로 남았다.

선택 순서·라벨·조건·확률·FX·노트는 전부 이전과 동일하다. 이미 지급한 결과의 본문과 저장된 reader turn은 현재 조건이나 새 본문으로 다시 만들지 않는다. `03m-finale-reading.js`는 이 선택 결과를 덮어쓰지 않으므로 수정하지 않았다.

검증 범위:

- 수정 전 12개 회귀 중 8개 실패, 수정 후 12개 통과. 다섯 지식 흔적만 있는 실제 발견 조합, 재이 유무 × 미발견/분해/현재 소지/소지품 제거 8조합, 사진 두 실제 선택을 실행한 뒤 코어 결과, 9개 흔적 중 5개 이상인 256조합을 확인했다.
- entry reload, 현재 결과 reader 저장 후 reload, 과거 결과 본문·reader 보존과 재지급 방지, 다음 `seoul_costs` 연결을 확인했다.
- 관련 결말·기존 수선 검사 37개 통과. 전체 quote corpus는 삭제된 중복 대안 1개(q11→10)만 정확히 투영한다. 전체 해시를 갱신하지 않았다.
- 실제 브라우저 화면·그림·crop 검수는 root 담당이다. 본 문서의 reader 검증은 같은 파서에 대한 VM 검증이며 화면 검수로 세지 않는다.

증거: `core-before.json`, `core-after.json`, `regression-red.txt`, `regression-green.txt`, `related-tests.txt`, `regression-and-dialogue-green.txt`. 동시에 진행한 다른 담당자의 소스 변화가 있어 whole-engine hash를 이 수선만의 hash라고 해석하지 않는다. 7차 시작 hash는 동결 통지 뒤 별도로 남긴다.
