# 20차 준비 — 아직 원정 미실행

seed280001, player48. 박 선생·레오·은수를 정상 영입하고 `core_transfer`를 우선한다. 접근 가능한 공개 지도에서 광주→전주→대전의 영입 기회를 보되 실제 임시 동행의 목적지와 자원 조건을 우선한다. 초반 선택도 19차와 달리 이름 기록·작업장 열쇠 맡기기·서쪽 장터길을 우선하도록 준비했다. 동료나 엔딩 조건을 강제로 주입하지 않는다.

19차 교환 거절 69회 원인을 QA 정책에서 교정했다. 관측에 실제 공급 최대량과 `G.canStoreSupply`·고철 보유량으로 계산한 일반 판매 행의 활성 여부를 추가했다. 이는 현재 UI가 쓰는 공개 판단이다. 미래 사건이나 숨은 결과는 읽지 않는다. 물물교환 행은 이 정책에서 사용하지 않으며 일반 판매와 혼동하지 않도록 비활성으로 관측한다.

정책 목표량은 현재 용량으로 제한하고, 활성·적재 가능 행만 고른다. 예기치 않게 거절된 판매는 장소·행·해당 재고·최대량·묶음 수량·가격·구매 가능 조건을 기억한다. 시각이나 다른 물품 지출만 바뀌었다고 같은 거절을 반복하지 않는다. 실제 용량이나 관련 재고가 달라지면 다시 시도할 수 있다. 일반 행동의 동일 상태 재시도 차단에도 용량을 포함했다.

`preparation-check-final.txt`에서 비활성·가득 참·정확한 잔여 공간·거절 재시도·실제 용량 변경과 관측 코드 컴파일을 확인했다. 이는 합성 정책 입력 검사이며 게임 원정이 아니다. 초기 준비 로그 둘은 용량 변경을 누락한 일반 상태 서명과 기존 관측 hook 위치를 바로잡기 전 실패이므로 그대로 보존했다. `reader-code.js`는 관측 코드 생성 과정의 파일이다. `G.newGame`이나 `runPersona`는 실행하지 않았다.

이전 선택 비교 입력은 primary69개 segment이며 19차 세 정상 원정까지 포함한다. 별도 분기·부분 재생·C2 별도 재검사는 제외한다. 실제 시작은 root의 20차 freeze와 40src hash를 받은 뒤에만 한다.
