# Player 05 — 미지급 진입과 지급 결과 재접속

실제 소스 엔진을 독립 메모리 저장소에서 실행했다. 브라우저 클릭이나 사람 플레이가 아니다. 공개 라벨과 활성 조건만 보고 이전에 덜 누른 선택을 우선했다. 자원·동료·플래그 주입은 없고, 보급/노동/이동은 기존 생존형 정책을 이용했다.

첫 시도에서 DAY 5, 553km, `story_done / core_transfer`까지 완료했다. 선택 54회, 이전 보존 baseline 대비 새 `eventId:index` 7개. 전체 236행의 행동 전후 상태와 54개 선택의 진입·결과 본문을 검토했다. 재시도는 하지 않았다.

## 저장과 다음 행동 검증

- 선택 전 미지급 진입 재접속 55회: 모든 관측 상태 동일.
- 지급 결과 재접속 54회: 전부 `applied:false`, 관측 상태 동일, 중복 비용/효과 0회.
- trace 217에서 서울 준비 복귀를 한 번 선택했다. DAY 4 20:57 서울 → 21:57 수원, 정확히 60분. 다음 날 야영 종료 뒤 34km를 정당하게 운전하여 서울로 돌아갔다.
- 돌아온 뒤 trace 226은 `seoul_decision`으로 바로 이어졌다. 앞의 5개 서울 지점을 다시 결제하거나 읽지 않았다. 최종 결정 이후 목표도 aftermath → ending으로 정상 진행했다.

이것은 공개 상태 스냅샷 검증이다. 숨은 RNG 상태와 타이머가 같다는 뜻이 아니며, 재접속 뒤 다른 우연 조우가 나오는 현상을 상태 손실로 세지 않았다.

## 검토 요청 1건

`camp_visitor` 밤 손님이 실제 엔진 순서상 기상 뒤 열린다. trace 118에서 DAY 3 22:00 야영 → DAY 4 06:30, trace 120의 진입에는 “밤길”, 거절 결과에는 “어둠 속으로 사라졌다”가 남는다. `G.camp`가 먼저 수면 시각을 진행한 뒤 위험 사건을 선택하고, `presentCampEvent`가 직접 사건을 연다. 비용 중복이나 진행 막힘은 없었다.

과거 밤의 회상으로 보여 주는 별도 표지가 실제 UI에 있는지는 보지 못했다. 따라서 엔진 순서는 확인됐지만, 시각·출처의 최종 모순은 주 디렉터 확인 전까지 P2 후보로 둔다. 이 이유로 밤 사건을 전부 없애거나 수면 비용을 바꾸면 안 된다.

## 취향 의견 1건 — 버그로 세지 않음

trace 91에서 우편부에게 “원칙대로 하세요”를 골라 편지를 맡지 않았다. 뒤의 `seoul_han` 녹음은 “아직 임자를 못 찾았다 / 나는 여기까지 / 나머지는 부탁”이라고 한다. 미소지 편지를 꺼내는 선택은 막혀 있으므로 아이템 모순은 없다. 다만 그 요청을 묵례로 지나간 뒤 엔딩에 가면 우편부의 작은 약속이 열린 채 끝났다는 느낌은 있다. 새 배달 퀘스트나 무료 편지 지급이 필요한 버그라는 주장은 하지 않는다.

자세한 진입·선택·결과·상태·확신도는 `findings.json`, 원본 증거는 `attempt01/player05-trace.json`이다. 생산 코드, 실제 사용자 화면/저장, 공용 실행기와 과거 기록은 바꾸지 않았다.
