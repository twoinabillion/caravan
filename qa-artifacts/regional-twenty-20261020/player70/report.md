# player70 답사 감사

첫 시도에서 메인 스토리의 실제 `SESSION 1 END`까지 도달했다. `storyDone=true`, `ending=story_done`, 선택한 결론은 `core_transfer`다. 8일·633km를 달렸고 사망·중단·재시도는 없었다. 엔진 시뮬레이션 결과이며 실제 사용자 화면을 조작하거나 생산 코드를 수정하지 않았다.

진주(n=45, D1 19:50) → 무주(n=88, D3 18:05) → 청주(n=137, D5 11:29) → 이천(n=158, D6 10:05)을 모두 방문했다. 이천에서 첫 답사를 마친 뒤 공개 메인 목표를 따라 충주·청주로 돌아가 증거를 모으고, 천안·평택·수원을 거쳐 서울에 들어갔다. 재이는 만나 정보만 샀고 동료는 합류하지 않았다.

## 검토 범위와 실행 증거

`attempt01/player70-trace.json`의 304행 전부를 1–35, 36–70, 71–105, 106–140, 141–175, 176–210, 211–245, 246–275, 276–304로 나눠 순서대로 읽었다. 선택 67회와 그때 제시된 가시 선택 122개(비활성5개 포함), 입장·전체 결과·비용·요구·메시지·앞뒤 시간/자원/동료/소지품·다음 행동을 함께 확인했다. 반복 재로드도 각 발생의 문맥과 변화 여부를 확인했다. 화자 오류는 주장하지 않았고 실제 `buildStoryTurns` 검증도 수행하지 않았다.

입장 전 재로드67회는 모두 성공했고, 유료 결과 재로드67회는 모두 `replayed=true`, `applied=false`였다. n=303 결과에 `〔 서울까지 400km · SESSION 1 END 〕`가 실제 출력됐고, n=304 결과 재로드 뒤 최종 요약에 `ended=true`와 `storyDone=true`가 남았다. 연료 최저0L, 물7, 식량2, 고철1, 차체71.38%였다. 자원을 주입하지 않았다.

신규 정책은 게임과 독립된 seed PRNG를 쓴다. 다중 활성 선택 때25% 확률로 균등 표본을 뽑고 나머지는 듣기·협의·확인·도움을 선호하되 모든 대안에 양수 가중치를 남겼다. 다중 선택43회 중 균등11회, 성격 가중32회였고 단일 선택은24회였다. 실현 비율25.58%를 맞추기 위한 재시도는 하지 않았다. 28일 또는900km에 관광을 중단하는 예산을 미리 선언했으며 실제로는 D6·417km에 네 곳 답사를 끝냈다.

## 발견

확정 결함은 없었다. 후보1건은 늦게 도착한 출발 방송이다. n=102, D4 07:40·236.2km, 무주에서 영동으로 가는 길에 처음 나온 「부산 뒤에 남은 방송」은 “부산 항만 방송이 잡음 속으로 멀어질 즈음”으로 시작한다. 부산 출발 뒤 이미 세 번 야영한 시점이라 출발 직후 장면처럼 읽힐 여지가 있었다. 현재 장면의 `origin`은 null이다. 선택1은 이름을 받아 적었고 피로1이 늘었으며 재로드 후 정상적으로 영동에 도착했다.

플레이가 모두 끝난 뒤 해당 사건을 확인했다. `src/03i-story-expansion.js`의 본문은 관측문과 같고, 비트에는32km 하한만 있다. 비트 큐의 우선순위 때문에 지연될 수 있다. 다만 부산 방송이 중계되거나 멀리 잡히는 설정을 배제할 근거는 없어 지리 오류로 확정하지 않았다. 늦게 도착할 때 방송 출처나 지난 출발과의 관계가 조금 더 분명하면 좋겠다는 후보이며, 실제 화면의 시각·그림은 검증하지 않았다.

취향 의견은 n=195의 서진 첫 등장이다. 직전 n=192는 이음망 연락소의 전달자와 원본을 대조하기로 했고, 곧바로 “북부 연락소에서 서진이…”가 나온다. 이 경로에서는 이름을 처음 들었으므로 같은 연락소 사람이라는 짧은 연결이 있으면 이해하기 쉽겠다. 이름과 행동만으로 인물을 소개하는 방식 자체는 가능하므로 오류로 세지 않았다. 소스의 서진 초상 지정은 확인했지만 실제 초상·이름 노출은 보지 못했다.

정책 오류1건은 연료 예보를 경로 점수에 반영하지 않은 것이다. n=79는 연료0.05L에 무주42km·예상11L, “연료11L 부족”을 공개했는데도 출발했다. n=82·115·218에서 실제 고갈을 겪어 각각5·11·10시간을 썼다. n=211도 예상5L에2.61L로 평택을 향했다. 게임은 위험을 이미 알려 줬다. 이 손실을 제품 결함으로 세지 않았고, 성공 뒤 정책을 고치거나 재실행하지 않았다.

## 소스 노출과 한계

모든 자연 플레이가 끝나기 전에는 지침·본인 항목·허용된 runner/harness와 공개 관측 투영만 읽었다. 기존 정책·발견·보고서와 미래 소스/효과는 보지 않았다. 이후 실제 본 방송 및 상자→서진 장면을 찾는 과정에서 `src/03i-story-expansion.js:640–680,888–915`, `src/03-data.js:12630–12685,12815–12865`, `src/03l-main-recovery.js:1–78`의 인접 미관측 분기·북부 recovery 대체 서사·두 줄의 동료 banter까지 노출됐다. 초상표와 비트 큐의 인접 ID/게이트, 파서 API 검색 출력의 관련 없는 회귀 테스트 ID·짧은 인용도 보았다. 이 노출 뒤 추가 플레이는 없었고, 미관측 부분을 실제 본 분기로 집계하거나 새 발견으로 만들지 않았다. 자세한 노출은 `findings.json`에 적었다.

실제 UI·모바일·시각·입력·오디오·취소/Escape는 검사하지 않았다. 저장 검증은 엔진의 입장/유료 결과 재로드 범위다. raw 메인 메타데이터를 실제 수첩 UI로 간주하지 않았고, raw 칩 소수점이나 회상 origin의 시각을 화면 결함으로 세지 않았다. 동료가 없는 한 경로이므로 동료 반대·동료/캠프 대화·치료·개조·일자리·실제 배달 분기는 확인하지 못했다.

보존 파일은 `policy-attempt01.cjs`, `review-trace.cjs`, `attempt01/player70-{trace,summary,save}.json`, `attempt01/policy-evidence.json`, `findings.json`이다. 생산 코드와 사용자 save/Studio/서버/탭/build/apply는 변경하지 않았다.
