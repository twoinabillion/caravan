# player54 — 산길과 작은 마을을 고르는 등산가

첫 시도에서 거창·무주·남원을 모두 방문하고 세 곳의 주변 탐색을 마친 뒤 메인 엔딩까지 도달했다. DAY 8, 615km, 최종 방식은 집행권 인계(`core_transfer`)다. n219의 실제 결과에 `〔 서울까지 400km · SESSION 1 END 〕`가 있고 최종 요약은 `ended=true`, `storyDone=true`다. 실패·재시도는 없다.

진행을 막는 확정 결함이나 지급 결과의 중복 적용은 발견하지 못했다. 서술의 기록 획득 경위에 관한 후보 1건과 관계 호칭의 명료성 의견 1건을 남겼다. 여러 차례 겪은 연료 고갈·탈진은 내 정책이 공개 예보와 보급 수단을 충분히 쓰지 않은 결과여서 결함 수에 넣지 않았다.

## 실행과 검토 범위

- 신원/시드: `player54` / `205054`, 이름 상혁, 준비물 `provisions`.
- 새 정책: [policy.cjs](policy.cjs). 게임 RNG와 `Math.random`을 쓰지 않는 별도 LCG로 복수 활성 선택의 25%를 균등 추첨하고 나머지를 탐색·기록·대화·안전 선호로 가중했다. 모든 대안에 양수 가중치를 남겼다.
- 실제 복수 활성 선택 38회 중 균등 모드 9회, 가중 모드 29회. 단일 활성 선택 27회. 비율을 맞추려 재플레이하지 않았다. [선택 모드 증거](policy-evidence.json)는 보존된 관측을 정책에 다시 넣어 65개 선택과 준비 버튼 1회가 일치함을 확인한 기록이며 엔진 재실행이 아니다.
- 자연 플레이는 `node qa-artifacts/regional-twenty-20261020/player54/policy.cjs attempt01`로 실제 소스 엔진을 구동했다. 자원은 유한하고 상태 주입이나 결과 강제는 없었다.
- [원본 220행 기록](attempt01/player54-trace.json), [완료 요약](attempt01/player54-summary.json), [최종 격리 저장](attempt01/player54-save.json)을 보존했다. 본문 진입·제공 선택의 라벨/비용/요건/활성 여부·선택·결과·전후 시간/장소/동료/자원·메시지·인접 행동을 n1부터 n220까지 읽었다. 잘린 출력 n21–29, n43–50은 별도 범위로 다시 읽었다.
- 65회 지급 결과 재불러오기는 모두 `loaded=true`, `replayed=true`, `applied=false`다. 마지막 n220에서도 결과가 다시 지급되지 않았고 이어서 엔진의 실제 종료 상태에 도달했다. 브라우저 새로고침/포커스/읽기 화면 검증과는 구별한다.

## 후보 P54-C01 — 자동 메인 기록의 전달 경위가 비어 보인다

n83, `parents_diversion_manifest`, DAY 4 06:36, 누적325.3km, 거창→무주 주행 중이다. 동료0, 연료3.27L, 물9, 식량3, 고철16, 차체78.10%, 피로65.85%였다.

> 남쪽 환승소에서 찾은 운행표와 분류 기록을 나란히 펼쳤다.

직전 공개 메인 안내는 김천 갈림길에서 「오지 않은 다음 차」를 주변 탐색하라는 내용이었다. 이 경로는 김천에 들르지 않았고, n1–82에 운행표를 전달받는 장면도 없었다. 그럼에도 이 사건이 자동으로 열려 선택0 「왜 두 사람을 갈라놓았는지 확인한다」를 해결했고 목표가 청주로 진행됐다. 다음 행동 n85는 같은 거창→무주 구간의 주행이었다.

기록의 작성 장소와 현재 차의 위치가 다르다는 이유로 오류를 부르는 것은 아니다. `storyOrigin`은 「발견한 기록 / 남쪽 환승소 운행표」라서 타지 기록을 읽는 상황일 수 있다. 다만 그 기록이 왜 지금 차에 있는지 연결 문장이 보이지 않았다. 자동 메인 비트에서 획득을 암묵적으로 처리하는 것이 의도된 설계일 수도 있어 **확정 결함 대신 중간 신뢰도의 서술 출처 후보**로 남긴다.

자연 플레이와 전체 기록 검토를 끝낸 다음 이 관측에 한해 소스를 확인했다. `src/03-data.js:13039`는 실제 본문과 같았다. `G.beatReady`는 누적 거리와 공통 위치 판단을 사용하고, `src/04g-engine-evidence.js:60`의 위치 판단은 이 사건을 김천에 한정하지 않는다. 반면 수동 주변 탐색 경로는 김천을 가리킨다. 두 진입 경로가 존재한다는 사실까지 확인했으며, 어느 경로가 의도에 어긋나는지는 이 테스트만으로 단정하지 않는다.

가장 큰 문제는 안전 경로를 `check.ok`로만 고른 것이다. n58 거창에서 남원으로 갈 때 연료11.23L와 「연료 여유1L」 경고가 보였지만 이후 보급 계획 없이 출발했다. 남원에 도착한 잔량은1.52L였다. n67에는 아예 「연료9L 부족 · 험로 대응 없음」이 표시돼도 거창으로 출발했다. n69·77·86·102·155·204의 여섯 연료 위기를 경로 결함으로 보고하지 않는다.

생존 수단을 놓친 점도 있다. n93 무주에는 「물2통 ⇄ 식량1」 교환이 있었지만 내 구매 코드는 일반 자원 키만 처리했다. n112 대전의 배급 화이트보드·축전지, n164 수원의 망루 교대·성문 평형추도 제한적인 일거리 정규식에 걸리지 않았다. n198에서는 인계가 이미 활성인데 한 번 준비하러 내려온 뒤 n202에서 보급 없이 다시 출발했다. 공개 수단이 있는데 정책이 쓰지 않은 것이므로 결식·탈진·추가 연료 위기는 게임의 불가피한 소프트락이 아니다.

## 한계와 보존

이것은 표현·음향·타이머를 대체한 Node VM의 엔진 플레이다. 사람의 실제 플레이, 브라우저·모바일·화면·입력·음향 검증으로 해석하면 안 된다. 동료 영입, 동료 이야기, 게시판 의뢰, 업그레이드, 다른 최종 방식은 실제로 수행하지 않았다. 원시 메인 메타데이터를 실제 목표 수첩 UI로 간주하지 않았고 원시 소수점 칩을 화면 표시 결함으로 취급하지 않았다.
