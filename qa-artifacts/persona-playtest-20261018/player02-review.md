# player02 · 공감형 격리 엔진 플레이

## 모집 경로를 포함한 재실행 — 최종 대표 런

초기 runner가 마을의 실제 모집 접점을 정책에 노출하지 않아 초기 런은 동료0명이었다. 이것은 게임 결함이 아니라 하네스의 행동 커버리지 누락이다. root가 실제 UI와 동일한 모집 표시·G.openRecruitMeet·공개 지도거리를 노출한 뒤, 동일 seed와 동일 선택 성향에 seekCompanions/followRecruit를 켜서 처음부터 다시 실행했다. 초기 로그를 덮어 감추지 않고 `player02-initial-trace.json`/`player02-initial-summary.json`/`player02-initial-save.json`/`player02-initial-policy.cjs`로 보존했다.

- 최종 대표 결과: `ended:true`, `story_done`, `core_transfer`, DAY8 11:19, 530km, 212기록/78선택, 오류0. 민지·강우2명 동행.
- 최종 자원: 연료30.61L, 물14, 식량9, 고철2, 차체100, 부품8, 의약품1.
- 경로: 부산 → 양산 → 밀양 → 양산 → 울산 → 경주 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울.
- 밀양에서 민지 부탁을 받아 울산으로 우회(n29~41), 경주에서 합류(n51), 대구에서 강우를 만나 돔의 후임·감시표식 문제를 해결(n69~82), 이후 대화를 지속했다. 실제 모집이 된 경로다.
- 대표 trace는 이제 `player02-trace.json`이다. 아래 이전 검토의 n번호는 명시적으로 `player02-initial-trace.json`에 해당한다.
- 재런 저장/로드14회 모두 true, 공개 snap 전후 동일. 이는 화면·읽기 cursor 복원 검수가 아니다.

### 재런에서 추가 확인한 우선 문제 A: 강우의 거부가 즉시 찬성으로 바뀌고 인원도 모자라다

- 재런 n208 `seoul_costs` 본문에서 강우는 “보존은 안 된다…나는 근무표에 사람을 갈아 넣으면서 그걸 ‘지킨다’고 부르는 곳을 나왔다. 다시 들어가진 않아.”라고 명시적으로 반대한다.
- `근무표에 이름을 적을 사람을 먼저 묻는다`를 누르면 결과가 “민지, 강우이 차례로 고개를 끄덕였다”로 바뀐다. 강우가 마음을 바꾼 계기나 대답이 없다. `강우이` 조사도 틀렸다.
- 이어 “빈칸 세 개짜리 근무표…채워지는 건 오늘”이라고 하지만 다음 n209 실제 보존 선택은 `감시 근무를 설 사람 2/3`으로 disabled다.
- 도달 가능성 자체는 정상(다른 인계/수면 선택으로 진행 가능). 문제는 선택 안내 결과가 캐릭터 의사·실제 gate와 어긋나는 것이다.

### 재런에서 추가 확인한 우선 문제 B: 즉시 중재 결과가 미래 일주일을 완료한다

- 재런 n186 `pair_mj_kw_1`에서 `중재한다` 선택.
- before/after 모두 DAY8 08:10, 경과0분이다. 실제 결과 chip은 차체+3%, 민지·강우 사기+3, 유대+2다.
- 결과 본문은 “민지식 변속을 일주일 시험” 제안 직후 “사흘째에 강우가…”, “일주일째엔 민지가 험지에서…”까지 이미 일어난 일로 서술한다.
- 이 시점은 아직 DAY8이고 그날11:19에 엔딩에 도달했다. 과거 교습을 회상한다는 진입도 없었다. 약속은 약속으로 남기거나 실제 시간이 지난 후 별도 callback으로 받아야 한다.

### 초기 문제의 재런 대조

- 구조 인과는 재런 n102~103에서도 문제: 업고 오르기에 실패해 원래 자리보다 아래로 떨어졌는데 다음 장면은 “사람 셋은 올라왔다”고 한다. 초기 런은 성공했는데 같은 부상자가 아래에 다시 남았고, 재런은 실패했는데 세 번째 사람이 언제 올라왔는지 없다. 어느 결과에서도 다음 공용 진입이 직전 상황을 충분히 보존하지 못한다.
- 문경의 미소개 상대는 재런에서는 민지·강우가 있어 성립할 여지가 있다. **동료0명이었던 초기 n69만 확정 재현**이다.
- 사본 분기(n5→8), 해도 첫 소개(n10)는 재런에서도 동일했다. 한강 순서는 재런 n195→197→199에서 동일했다. 아래 중간/낮은 확신 후보는 여전히 추정 단계다.

## 증거가 있는 문제 후보

### 1. 구조한 부상자가 바로 다음 장면에서 다시 아래에 남는다 — 높은 확신

- n59 `route_ridge_rescue`: 어른3명+아이1명이며 발목 부상자는1명이라고 소개한다.
- n60 `route_ridge_anchor`: 아이와 첫 어른이 올라온 뒤, `다친 사람을 업고 짧게 치고 오른다`를 선택했다. 결과는 “다친 사람을 등에 묶고 … 올렸다.”
- n61 `route_ridge_extract`: “사람 셋은 올라왔다. 아래에는 발목을 다친 여자와 수레가 남았다.”고 다시 말한다.
- 먼저 올라온2명 뒤 부상자를 올렸으므로 남은1명이 같은 발목 부상자일 수 없다. 다음 장면의 남은 사람/대사만 직전 선택 결과에 맞춰야 한다. 구조 성공 자체는 이어져 엔딩을 막지 않았다.

### 2. 혼자 간 문경에서 소개되지 않은 대화 상대가 생긴다 — 높은 확신

- n69 `loc_mungyeong`: 공개 본문은 옛길, 무인 주막 터의 나무판, 앞선 여행자들이 적어 둔 답만 소개한다. before/after 모두 party=[]이다.
- `한 줄 적는다` 결과가 “뭐 적었어요?” / “안 알려줘.” / “에이.” / “…나중에.”로 이어진다.
- 현재 대화를 건 사람이 등장하지 않았다. 현장 여행자를 실제 본문에 소개하거나 혼자일 때의 결과가 필요하다. 동료가 없는 상태를 무명 답변으로 메워서도 안 된다.

### 3. 첫 탐색에서 이미 이음망의 차·흰X인 듯 취급된다 — 중간 확신, 부모의 소스 확인 필요

- n1~8에서 실제 읽은 본문은 부산 수리 호출·가족 버스·민원·검증키·작업장 출발이다. 이음망 접선이나 흰X 도색은 소개되지 않았다.
- n9 첫 부산 탐색 뒤 n10 `cell_sea_meet`는 “노인이 달구지의 흰 X를 확인”하고 “이음망에서 말한 차가 맞구먼”이라고 한다.
- n38 `cell_dome_meet`도 “이음망 통신 받았어. 종이로.”라고 한다. 이 런에는 그 전에 이음망에 전달된 과정이 없었다.
- 조직이 플레이어보다 먼저 알아볼 수는 있다. 다만 첫 등장의 의문/설명이 없어서 서사 선행조건이 빠져 보인다. 엔진 플래그 결함으로 단정하지 않고 신규 인터랙티브 진입의 인과를 확인할 후보로 남긴다.

### 4. 한강 진입 위치와 목표 문구가 전후로 되돌아간다 — 중간 확신

- n131 `han_bridge`: “다리를 건넌다”를 골라 “달구지가 다리에 올라섰다”, 지나온 가로등이 꺼진다고 읽는다.
- n133 `seoul_open`: 다시 “한강 남쪽 진입 관문”, “강을 건너 남산으로 오르는 길이 열렸다”를 읽는다.
- n135 `seoul_han`: 다시 다리 한복판에 서고 결과에서 다리를 “천천히 건넜다”고 한다. 이때 메인 목표의 다음 행동은 “한강 관문에서 막힌 길을 열고…”다.
- n131은 초입 진입으로 볼 여지가 있어 이중횡단으로 확정하지 않는다. 그러나 관문 해제 후 목표가 여전히 막힌 길 해제를 말하는 점은 실제 현재 행동과 어긋난다. 도착 전 초입/남쪽 관문/통과 뒤 구간을 동일한 단계 언어로 묶을 필요가 있다.

### 5. 이름 기록 분기 직후, 복사하지 않은 이송표 사본이 생긴다 — 낮음~중간 확신

- n5는 `record_names`를 골라 허락받은 세 이름만 기록한다. 선택하지 않은 다른 라벨은 `거절 응답과 이송표를 함께 복사한다`다.
- n8 `opening_farewell`: “도윤은 가족의 이송표 사본을 조수석 수첩 위에 올려놓았다.”
- 도윤이 별도 사본을 줬다는 새 행동 자체가 불가능하지는 않다. 다만 두 선택의 차이를 흐린다. 사본을 별도로 준비하는 연결이 있는지 소스 확인 후, 없다면 이름 쪽 분기는 기록한 이름/원래 표를 가리키도록 맞추는 후보.

## 잘 이어진 부분과 검증 한계

- 부모 기록 → 분리 절차 → 당사자 증언 → 발신 원본 → 엄마 재회 → 거점 수락 → 코어 결정은 이 런에서 순서대로 읽혔고 막히지 않았다. 마지막에 하진에게 “이번에는 하진 씨가 정하시면 돼요”라고 돌려주는 응답은 초반의 허락·이름 기록 선택과 주제상 이어진다. 이 평가는 문장/인과 검토이지 실제 사람의 감정 반응이 아니다.
- 초기 런은 도움을 자주 골라도 동료0명으로 끝났다. 공용 runner의 실제 거점 모집 접점 노출 누락이 원인이었다. 이를 고친 재런에서는 민지·강우가 합류했다. 동료를 얻기 어렵다는 게임 결함으로 보고하지 않는다. 모집의 실제 UI 발견 가능성은 별도 검수 대상이다.
- n116 연료 부족에서 지나가는 차를 기다려 실제 비용을 내고 복구했다. 강제 자원·무한 연료는 쓰지 않았다. 생존 실패 없이 종료한 한 seed일 뿐 난이도 전체를 보장하지 않는다.
- 사진·폰트·터치·페이지 이동·목소리·애니메이션·실제 Studio 저장은 관찰/조작하지 않았다. Node VM의 UI·음향·타이머 stub 실행이므로 브라우저 플레이나 실제 유저10명의 평가로 표현해서는 안 된다.
