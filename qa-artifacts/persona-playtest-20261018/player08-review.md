# player08 · 동료와 이동식 집 우선

## 결과와 범위

최종 재실행은 정상 종장까지 도달했다. seed181008, 수리 꾸러미, Day12 10:09, 1,068km, 336행동·122선택. 최종 동료는 민지·강우·은수3명이며 선택은 `집행은 멈추되, 기록을 열 때까지 코어를 보존한다` → `core_quarantine` → `story_done`이다. 후미 레일 좌석칸(n27), 서스펜션 강화(n140), 거주구 2차 증축(n299)을 실제 구매했다. 종료 시 좌석4/동료3이며 박 선생은 앞선 좌석부족 이후 합류대기로 남았다. 따라서 전 동료 수집 성공이라고 주장하지 않는다.

현재 선택·본문·목표·가격·잠금 사유만 보고 판단했다. 미래 결과·효과를 정책에 넣지 않았다. 실제 엔진을 격리 메모리에서 실행했고 사용자 저장/화면/서버와 production source는 변경하지 않았다. 브라우저, 이미지, 한국어 음성, 입력감, UI 컷 전환을 체험한 결과가 아니다.

주요 파일: `player08-policy.cjs`, `player08-trace.json`, `player08-summary.json`, `player08-save.json`.

## 우선 확인할 체험 문제

1. **P1 후보 — 자리가 없는데 ‘탔다’는 결과가 먼저 나온다.** 최종 trace n245·248의 `rq_parkss_join`은 김천, 민지·강우·은수3명/좌석3명 상태에서 `왕진 가방이 흔들리지 않을 자리를 비운다`가 활성이다. 결과는 ‘가방이 먼저 실리고, 박 선생이 그다음에 오른다’라고 확정하지만 바로 다음 n246·249의 실제 `doRecruit('parkss')`는 false이고 명단은3명 그대로다. 모집 제안과 실제 합류를 나누는 UI가 있더라도 완료형 본문은 실제 합류 이전이다. 자리를 마련할 때까지의 기다림/돌아오기와 실제 탑승 결과를 분리해 확인할 필요가 있다. 원문 위치 `src/03-data.js:4720`. 아래 하네스의 왕복 루프와 달리, 이 상태·본문 불일치는 수정 하네스에서도 남았다.

2. **P2 — 자원 사건의 시간이 실제 자원 상태와 다르다.** n172 `crisis_hungry`는 ‘식량이 떨어진 지 하루가 넘었다’라고 하지만 n170 Day7 19:08까지 식량2가 있었고 사건은 Day8 06:30이다. 굶은 기간은 길게 잡아도11시간22분이다. n294에서도 같은 본문이 나오는데 사건 진입 식량은2다. 0이 된 즉시부터인지, 예약된 위기 사건인지 구분하여 조건 재검증 또는 수치/경과에 맞는 문구가 필요하다. 원문 `src/03-data.js:4461`. 식량2가 반드시 하루 충분하다는 뜻은 아니지만 ‘떨어진 지 하루’는 확인된 상태와 맞지 않는다.

3. **P2 검수 항목 — 종장의 시간 생략을 알려 줄 경계가 필요하다.** n333 결정부터 n334 `남산의 밤` 및 결과의 ‘새벽’, n336 수원 중계소로 돌아간 결말까지 엔진 상태는 Day12 10:09/서울로 고정이다. 종장을 압축해서 보여 주는 연출 자체는 문제라 단정하지 않는다. 다만 오전 진입 플레이에서 밤→새벽→수원은 명백한 서사 시간 이동이다. 현재 게임의 시간표시/이미지/전환이 이를 어떻게 구분하는지는 이 하네스로 확인할 수 없으므로 실제 읽기 화면에서 확인해야 한다. 상단 현재 시계와 과거/후일담을 같은 현재로 읽게 만들지 않는지 볼 것.

4. **편집 제안 — 개별 대사는 좋아졌지만 세 인물의 불안을 같은 몸짓으로 거듭 설명한다.** n40 민지는 이미 확인한 공구함 잠금쇠를 다시 확인한다. 강우 합류는 비상문·잠금을 확인하고 ‘확인한 걸 한 번 더 확인한다’. 박 선생의 진료 결과는 상자를 닫고 잠금쇠를 한 번 더 누르고, 합류에서는 가방끈을 줄였다 늘린다. 마지막 n334도 민지 잠금쇠·강우 차단기·은수 방송 재확인이 한꺼번에 나온다. 정비/경계/관제의 버릇이 맞아 캐릭터 설정 오류는 아니지만, 긴 동료 중심 루트에서는 동일한 ‘만졌다→확인→한 번 더’ 리듬이 눈에 띈다. 사실/동기/말투는 보존하면서 일부를 다른 사람에게 일을 맡기거나 기다리는 행동으로 바꾸면 관계 변화가 더 보일 것 같다.

## 잘 작동한 것

- 임시 동행→같이 해결한 일→다음 정차→자기 자리를 만드는 절차가 민지(울산→경주), 강우(대구→구미), 은수(대전→청주→대전)에서 분명하다. ‘한 번 친절하면 바로 승차’가 아니라 각자의 남은 책임을 마친 뒤 정식 동료가 된다. 앞서 읽은 인물 버릇이 종장 감시조로 이어져, 보존 선택이 숫자3 충족 이상의 의미를 가진다.
- 종장 첫 화면은 실제 연결된4거점만 부르고, 실제 동료인 은수·민지·강우가 감시조에 이름을 썼다. 박 선생을 합류시키지 못한 이번 결말에 그를 감시조로 발명하지 않았다. 첫 시도의 다른 동료 조합(강우·은수·박 선생)과 구별된다.
- 오프닝에서 맡긴 열쇠가 종장 n334의 ‘돌아가면 문을 두드려야 한다’로 회수된다. 끝 n336은 하진에게 돌아갈지 스스로 정하라고 말하고, 엄마와 할아버지 이야기를 시작한다. 출발 이유·길에서 지킨 자율성·가족 이야기의 끝이 연결된다.

## 시도 이력과 하네스 한계

- `attempt01-*`: Day10 19:30, 888km, 강우·은수·박 선생3인 보존 엔딩. 그러나 초판 정책이 ‘함께 가기 어렵다’를 긍정 키워드로 오독하여 민지를 거절했다. 파일은 전부 보존했고, 이를 순수 동료우선 성격의 최종 결과로 쓰지 않았다.
- `attempt02-*`: 그 부정어 처리와 공개 upgrade `status.why` 해석을 고친 시도. 박 선생 가입대기에서 하네스 기본 길찾기가 ready를 미완료 작업처럼 추적해 김천↔영동 반복, Day16 탈수사. 이는 실제 UI 자동귀환 증거가 아니라 하네스 결함이다. 실패 기록을 삭제하지 않았다.
- 최종 `player08-*`: root가 ready 강제추적을 제거한 runner로 같은seed·같은 수정정책을 다시 시작하여 정상 종장. 자원/플래그 주입 없음. sourceHash는 모든 시도 `93d692d18f7c5bd45878c5fb330db5930283ed39a049d175a9ae7d7fad7df2d2`; 최종 runnerHash `44a29dd545557cd8a6429ad06866763f04734bb12427b724a35c4afd0046907b`.

수정 하네스에서 남은 가입대기 중복 재진입(n245/n248)도 자동 루프/별도 UI 클릭 여부는 구분해서 보아야 한다. 여기서 확정한 게임 후보는 ‘탑승 완료 원문이 실제 영입 성공보다 먼저 나온다’까지이며, 브라우저 소프트락이나 반복 클릭을 관찰했다고 주장하지 않는다.
