# 적용 후 10명 독립 성향 감사

게임 디렉터 지침으로 진행하는 발견 전용 감사. 생산 코드와 실제 사용자 저장은 수정하지 않는다.
10개의 새 서브에이전트를 동시 한도에 맞춰 순차 조로 실행한다. 각 담당자는 한 성향만 맡는다.
실제 소스 엔진/격리 메모리 저장소의 자동 플레이이며 사람·브라우저·시각·청취 검수가 아니다.

## 공통 규칙

- 먼저 AGENTS.md와 docs/DEVELOPMENT_GUARDRAILS.md를 읽는다.
- 지정된 playerNN 폴더만 작성한다. 공용 harness/다른 담당자/기존 QA/생산 파일 변경 금지.
- 선택 전 성향·방문 목표·선택 기준을 선언하고 policy.cjs에 공개 관측 기반 정책을 작성한다.
- 실제 엔딩까지 진행한다. 사망·한도·막힘은 보존하고, 필요한 정책 수정 재시도는 새 attemptNN으로 구분한다.
- 결과/효과/숨은 조건을 미리 보고 선택하지 않는다. 돈·물·동료·플래그·아이템 주입, 확률 조작, 무한 자원 금지.
- run(config, attemptNN)는 기존 관측 어댑터와 실제 엔진의 새 실행을 사용한다. choose/decide는 관측만 받는다.
- config.reloadAfterChoice=true로 지급 후 재접속을 검사한다. 실패 시 게임 오류와 어댑터 오류를 구분한다.
- 이전 정책을 참고할 수 있지만 새 성향으로 새 실행해야 한다. 이전 trace를 새 플레이로 제출하면 안 된다.
- 선택은 가능한 여러 분기를 밟되, 모든 분기를 봤다고 주장하지 않는다. 엔딩 선호 비율은 밸런스 근거가 아니다.
- findings.json: id, category(bug/contradiction/opinion/harness), severity, eventId, attempt, traceN,
  observed, expected, evidence, impact, confidence, suggestedScope. 0건도 정직하게 기록한다.
- report.md에는 전체 플레이를 읽고 느낀 점, 확정 후보와 해석/취향, 미검증 범위 및 엔딩 증거를 남긴다.
- 로컬 원문으로 검증하되 실제 밟지 않은 사건을 자연 관측으로 세지 않는다. 이전 수선 제보를 새 버그로 반복하지 않는다.
- UI 표시를 보지 않고 레이아웃 버그를 확정하지 않는다. 원시 목표 객체의 미표시 문구도 제품 UI라고 단정하지 않는다.

root는 중복을 합치고 실제 소유자/전후 맥락/기한/저장/공책 투영을 대조해 묶음 수선 목록을 판정한다.
이번 라운드는 발견·판정·기록까지이며 실제 수정은 이 결과를 기준으로 별도 일괄 작업한다.
