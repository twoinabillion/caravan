# player01 · 공략을 모르는 신중한 초보

새 실행 `attempt01`에서 실제 본편 엔딩 `SESSION 1 END`까지 완주했다. 신규 제품 버그·서사 모순 확정 후보는 **0건**이다. 자동 정책의 안전 판단 한계 1건만 `harness`로 구분해 [findings.json](findings.json)에 남겼다. 추가 시도는 하지 않았다.

## 성향과 실행

공개된 메인 목표의 장소와 다음 행동을 따라가며 첫 활성 선택을 기본으로 삼았다. 확인 질문·점검·안전 표현에 가중치를 주고 공격·강행은 피했다. 연료 꾸러미로 시작했으며 부족한 보급품은 거래, 가능한 현장 노동, 수리, 야영 순으로 마련하는 정책을 실행 전에 선언했다. 결과나 숨은 효과를 보고 고르지 않았다. [policy.cjs](policy.cjs)에 정책과 실행 방법이 있다.

- Seed `201001`, 이름 상혁, 연료 꾸러미. 실제 소스 엔진과 격리 메모리 저장소를 사용했다.
- 종료: `status=ended`, `ended=true`, `endKind=story_done`, `storyDone=true`, `method=core_transfer`.
- 54개 선택, trace 171행. 13회 출발, 28개 주행 구간 기록, 거래 3회, 야영 4회, 탐색 9회, 현장 노동 0회.
- 최종 시계 DAY 5 10:31, 누적 430km. 부산→양산→밀양→대구→구미→김천→상주→문경→충주→청주→천안→평택→수원→서울.
- 동료 0명. 최종 연료 약 11.51L, 물 10, 식량 0, 고철 2, 차체 약 90.44%. 연료 고갈 구제 사건을 2회 거쳤으며 사망·교착·예외는 없었다.
- 모든 선택은 관측의 `visible=true && enabled=true`였다. 선택 후 저장·재접속·지급 결과 재확인 54회 모두 `loaded=true`, `replayed=true`, `applied=false`; 기록된 전후 관측도 동일했다.
- 소스 해시 `6f9b628b020bcc8b22034294185f9b8dcf0ec4bdaa3f6efa4f5689b1196161b4`. 기존 분기 대비 새 선택 조합은 0개이며, 기존 trace 재사용 없이 새 seed로 실행했다.

## 전체 기록을 읽고 본 흐름

trace 1~171의 모든 행동과 선택 전후 상태, 54개의 선택 라벨·진입 원문·결과 원문·결과 칩을 검토했다. 도윤 가족의 버스 수리에서 이의 제기, 검증키 발견, 첫 발신 기록으로 이어지는 출발 동기가 분명했다. n4의 호스 우회 수리 후 n8의 다음 목표가 부두 민원 단말을 가리켜, 아직 읽지 않은 검증키 장면을 선행 행동처럼 요구하지 않았다.

중반에는 부모님이 서로 다른 곳으로 분류된 기록(n48), 인간 확인 절차 영상(n82), 분리 절차 회수(n90), 당사자가 고친 증언(n93), 명령 원본 대조(n104)가 이어졌다. 아빠의 죽음(n117)을 읽은 다음 엄마의 최근 표식(n131), 재회(n133), 돌아오지 못한 이유(n135)를 읽었다. 이 실행에서는 미확인 사실을 먼저 단정하거나 재회를 건너뛰는 흐름을 찾지 못했다.

능선 구조는 네 사람과 짐의 순서가 일관됐다. n55에서 아이를 먼저 올리고, n57에서 발판을 만든 뒤, n59에서 남은 사람과 수레를 분리해 당겼다. 구조 대상과 이미 올라온 인원이 결과에서 뒤바뀌지 않았다. 위수 구역의 경고사격은 실제 차체 감소(n73의 약 84.44→78.44%)와 연결됐다.

후반에는 엄마가 직접 타지 못하는 이유와 통신 지원을 설명했고(n135), 실제 이어진 이음망·유령·산지기 3곳의 응답을 받았다(n138). 최종 인계 결과도 같은 3곳을 사용했다(n162~164). 동료 없이 왔지만 여행 일지를 내미는 선택(n160)이 있어 진행할 수 있었다. n170은 부두 가족의 이송 취소 확인과 엄마에게 돌아가는 결과를 끝까지 보존했다. 최종 저장과 요약 모두 실제 종료와 본편 완료를 확인한다.

## 후보 판정과 제외한 항목

신규 `bug` 0건, `contradiction` 0건, `opinion` 제안 0건이다. `P01-H01`은 자동 정책의 한계다. n95와 n119의 출발 예측에 이미 `연료 3L 부족 / 위험`이 있었는데 정책이 `check.ok`만 보고 출발했다. 이후 n97과 n124에서 7시간·9시간의 실제 구제 비용을 치렀다. 위험 안내가 없었다고 보고하지 않는다.

같은 한계는 성향 해석에도 남는다. n45 본문에는 서쪽이 ‘보급, 안전’이라고 설명돼 있었지만, 짧은 선택 라벨 중심의 점수 정책이 동쪽 기본값을 골랐다. 수원에서는 현장 활동 라벨 ‘성문 평형추’를 노동 정규식이 인식하지 못해 식량 마련 노동을 하지 않았다. 따라서 이번 완주를 세심한 인간 초보의 최적 안전 행동으로 확대할 수 없다.

다음 항목은 새 버그로 세지 않았다.

- 문경 독행 n66은 예전의 소개되지 않은 대화 상대 대신 혼자 적고 읽는 결과였다. 수정된 문제를 다시 제보하지 않았다.
- 임시 행정소 n42는 태블릿을 지적해 무상 통과한 분기다. 예전 실패 분기의 비용 불일치를 이번 실행으로 재검증했다고 주장하지 않는다.
- n97은 식량 6→3인데 결과 칩은 식량 -2, 별도 메시지는 점심 식사 -1이다. 원문의 `G.applyFx`가 직접 비용을 처리한 다음 시간 경과의 식사를 별도 처리하는 것이어서, 이것만으로 지급량 오류로 확정하지 않았다.
- n166 이후 엔진 시계가 10:31이어도 서술은 밤과 다음 날 새벽을 다룬다. `src/03m-finale-reading.js`에 `epilogue`와 ‘그날 밤’, ‘다음 날 새벽’의 명시적 표지가 있다. 엔딩 후일담을 실시간 시계 오류로 제보하지 않았다. 실제 표지 렌더링은 미검증이다.
- 마지막 결정은 인계 1개가 활성이고 수면은 열쇠 상대 3/4, 보존은 감시 인원 0/3으로 막혔다(n164). `수원으로 내려가 준비한다 · 60분` 제어도 관측에 있었다. 조건이 없는 선택을 강제하지 않았으며, 준비 복귀 흐름은 이번에 밟지 않았다.
- 원시 `main` 객체나 저장 필드의 문구를 실제 공책 UI로 간주하지 않았다.

## 증거와 미검증 범위

[전체 trace](attempt01/player01-trace.json), [실행 요약](attempt01/player01-summary.json), [격리 최종 저장](attempt01/player01-save.json), [분기 비교](attempt01/coverage.json)를 보존했다. 최종 선택은 n170 `seoul_session_reset`의 ‘화면을 끄고 달구지로 돌아간다’이며 결과에 `〔 서울까지 400km · SESSION 1 END 〕`가 있다. n171의 지급 결과 재접속 후 엔진이 실제 종료됐다.

실제 엔진 자동 플레이이며 사람의 브라우저 플레이가 아니다. UI·오디오·실시간 타이머는 stub이다. 화면의 발견성, 잘림·겹침, 그림·인물 크롭, 페이지 입력, 키보드/터치, 듣기 경험, 실제 공책 투영과 저장 UI는 검증하지 못했다. 현재 사용자 저장·탭·서버는 건드리지 않았다. 생산 코드와 공용 harness도 수정하지 않았다.

서쪽 노선, 동료 모집·대화·부상, 업그레이드, 사이드 미션 수락·만료·완료, 선택 전 재접속, 결과에서 뒤로 가기/취소, 수원 준비 복귀, 수면·보존 결말은 이번에 밟지 않았다. 이전 여러 감사와 같은 분기를 새 실행한 결과여서 새 분기 커버리지나 모든 선택지의 완전 검증을 주장하지 않는다.
