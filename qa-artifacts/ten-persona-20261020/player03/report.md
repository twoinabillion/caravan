# player03 — 계산적인 장사꾼 / 실리주의자

마지막 새 실행 attempt03은 본편을 끝냈다. DAY 6, 430km, 66번 선택, `story_done=true`, `ending=story_done`, `method=core_transfer`다. 생산 코드·그림·HTML·실제 사용자 저장·공용 harness는 변경하지 않았다.

이 결과는 실제 소스 엔진을 Node VM과 격리 메모리 저장소에서 실행한 자동 플레이 감사다. 사람·브라우저·시각·음성 검수가 아니다.

## 먼저 정한 성향과 실행

선택 전에 `policy.cjs`에 공개 관측만 받는 기준을 선언했다. 돈과 이동 시간을 아끼고, 길목 배달과 이미 가진 물품의 조달을 검토한다. 거래·흥정을 선호하며 낯선 동승과 선택적 전투는 피한다. 부모님의 기록과 남산은 끝까지 확인한다. seed는 모두 201003, 시작 짐은 fuel, `reloadAfterChoice=true`다. 숨은 효과·결과를 미리 고르거나 자원·동료·플래그를 주입하지 않았다.

원본 세 실행과 세 정책을 모두 보존했다. attempt02/03의 66개 진입·선택·결과 본문은 동일하다. attempt03에 조달 수락/완료 2개 action만 더 들어갔고 이후 고철과 부품 잔량이 달라진다. 첫 실패와 두 정책 오류는 findings의 `harness`로 분리했다.

## 실제 경험과 수량 확인

- 밀양 게시판을 열어 `세 마을의 무전 1/3`을 수락하고 대구에서 명시적으로 전달했다(n36–44). 기한 없음인 장부 운송이며 기본 고철 16에 빠른 처리 보너스 4가 붙어 고철 31→51. 저장된 완료 장부도 “고철 20개를 받았다.”다.
- 대구 게시판에서 `세 마을의 무전 2/3 · 확인된 주파수표`를 확인했다(n45). 목적지가 현재 짧은 북상 경로의 인접 목적지가 아니라 수락하지 않았다. 후속 제안은 `questFollowup`으로 남고 기한 없음이다. 체인 전체를 완료했다고 주장하지 않는다.
- 수원 게시판의 `부품 2개 조달`을 수락하고 같은 장소에서 전달했다(attempt03 n180–182). 12일차 기한에 6일차 처리, 부품 10→8, 고철 128→151. 기본 19+보너스 4=23이며 저장된 완료 장부도 23이다. 다음 탐색과 서울 출발까지 이어졌다.
- 연료 거래 4회는 모두 공개 bundle/price와 실제 증감이 같다. 밀양 10L/고철7, 수원 10L/고철10을 3회. 각 거래는 25분을 썼다. 이 기록은 실제 화면의 비용 칸을 봤다는 증거가 아니다.
- 정비·일손은 밀양 공동 펌프에서 1회 실행했다. 25분, 물 +2, 고철 +14가 실제로 지급됐다. 파티는 전 과정 빈 배열이었다. camp_visitor의 불가 손님은 거절했지만 실제 동승/합류 요청은 만나지 않아 탑승 거절 UI를 검증했다고 하지 않는다.
- 3회 실행 전체의 지급 후 재접속 207회 모두 loaded/replayed=true, applied=false이며 관측 상태가 동일했다. 선택 효과 중복을 발견하지 않았다. 게시판 수락/완료 자체를 매번 직후 재접속한 것은 아니며, 다음 사건 선택에서 저장/로드를 거쳐 최종 저장의 완료 장부와 소모가 유지됐다.
- 최종 자원은 연료 29.516L, 물 9, 식량 8, 고철 161, 차체 94.44%, 부품 9다. 연료 부족 구제는 두 번 겪었고 각각 10/11시간 및 물·식량 비용을 실제 지불했다. 자원이 넉넉하다는 이유로 이 시간 손실을 무료 성공으로 세지 않는다.

수량 chip을 실제 변화와 대조했다. 성공한 두 실행의 비교 가능한 22개 연료/물/식량/고철/차체 chip은 일치했다. 실패 실행의 n172는 식량 chip -3, 실제 -4였으나 같은 action 중 점심 식사 알림 -1이 따로 있어 합계가 설명된다. 비용 UI 오표시로 확정하지 않았다. 완료 기록의 보너스 누락은 이미 수선되어 이번에도 20/23으로 맞았으므로 재제보하지 않았다.

## 모순 후보

`findings.json`에 제품 모순 후보 4건과 정책/감사 한계 2건을 나눠 기록했다. 후보는 생산 변경 승인이 아니며 root의 대조 판정 대상이다.

1. P03-C01 — 오미자 구매(attempt03 n95, attempt01 n90): 할머니와 혼자 만난 장면에서 여러 사람이 잔을 돌리며 서로 맛을 말한다. 특정 동료가 나타났다고 단정하지 않지만 현지 시음자라면 소개가 필요하다.
2. P03-C02 — 새벽 탐조등(attempt01 n160/229): 야영 완료 및 아침 배급 뒤 엔진 06:30에서 “새벽 3시” 사건이 열린다. 이미 지불한 지난밤 야영 중 사건과 현재 시각을 구분할 출처 마커가 없는 시간 맥락 후보다. 야영 시간·비용은 이미 처리됐으므로 무료로 밤을 다시 보냈다는 제보는 아니다. 실제 엔진도 기상 후 사건을 예약하므로 단순 타이머 축약 탓은 아니다.
3. P03-C03 — 연구단지의 실패 결과(attempt01 n212): 이미 시범 문서·수정표·회의록을 발견한 진입 뒤 “남은 건 텅 빈 서버랙과 정적뿐”이 이어진다. 삭제가 전자 자료만 가리킨다는 해석도 가능하므로 낮은 심각도의 문장 접속 후보다.
4. P03-C04 — 설명서 이전 공책(attempt03 n114→117→122): 영상 복원 때 지급되는 `parent_principle_found`만으로 `QuestJournal.entry`가 “설명서를 찾았으니”를 출력한다. 다음 실제 사건과 기록은 두 장이 없다고 명시하며, 두 장은 n122에서 받는다. 자연 관측한 본문과 UI 투영 소유자 소스를 연결한 후보이며 공책 실화면은 아직 보지 않았다.

마지막 밤/다음 날 새벽/수원 귀환이 같은 엔진 시각에 기록된 것은 후보에서 제외했다. `src/03m-finale-reading.js`와 `tests/test_persona_continuity.cjs`에 기존 `timeKind=epilogue` 및 구체적인 후일담 시간 마커가 있고, 이 어댑터의 텍스트 결합은 마커를 출력하지 않는다. 원시 main.act의 장 번호를 실제 공책 화면으로 단정하는 제보도 하지 않았다.

## 전체를 읽은 감상

수익을 챙기는 관점에서는 길목의 장부 배달과 이미 가진 부품 납품이 명확했다. 보너스와 실제 장부가 맞아 신뢰할 수 있었고, 무전 후속은 계속 맡을지 따로 판단할 수 있었다. 남산에서는 기록 창구를 닫는 대가와 합의의 느림을 읽은 뒤 집행권 인계를 골랐다. 동료 없이도 증언 사본과 거점 응답을 모아 종장까지 도달했다.

정책은 완벽히 합리적이지 않았다. 공개 hint에 위험 표시가 없는 “다른 입구를 찾는다”를 골라 70분과 찰과상을 지불했고, 긴 능선 구간에서는 고철이 있어도 시장이 없어 연료 부족 시간을 두 번 냈다. 이를 게임 오류로 세지 않는다. 첫 실행의 왕복 실패도 플레이어가 안내를 못 따라간 증거가 아니라 자동 정책의 상한 오류다. 이 한 성향의 엔딩 비율이나 남은 고철로 전체 밸런스를 판단할 수 없다.

## 범위와 증거 파일

모든 trace의 진입·선택·결과·자원/시간 변화·재접속 기록을 읽고 대조했다. attempt02와 attempt03은 조달 2개 action 외의 action 정렬, 본문, 선택이 동일함도 기계 비교했다. 최종 엔딩 증거는 attempt03 n216 결과의 `SESSION 1 END`, n217의 중복 지급 없는 재접속, `player03-summary.json`의 본편 완료/엔딩 플래그다.

미검증: 실제 브라우저 레이아웃/페이지 나눔/그림 crop/음성/키보드/터치, 실제 사용자 저장과 Studio, 메뉴 및 공책을 여는 실제 입력, 의뢰 포기·만료·늦은 전달, 무전 2/3·3/3 완료, 실제 동승 요청 거절, 다른 최종 집행안, 모든 선택 분기. 공용 harness에는 abandon-quest action이 없어 포기를 대체한 상태 조작은 하지 않았다.

정책: `policy.cjs` → `retry-policy.cjs` → `final-policy.cjs`. 실행별 `attemptNN/player03-trace.json`, `player03-summary.json`, `player03-save.json`, `coverage.json`은 원본이다. `inspect.cjs`는 기록을 읽기 위한 출력기다. 소스 hash는 세 실행 모두 `6f9b628b020bcc8b22034294185f9b8dcf0ec4bdaa3f6efa4f5689b1196161b4`로 같다.
