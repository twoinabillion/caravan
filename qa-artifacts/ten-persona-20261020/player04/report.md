# player04 — 성격 급한 직행형 독립 감사

본편 엔딩은 **attempt03에서 도달**했다. `storyDone=true`, `ending=story_done`, 최종 방식은 `core_transfer`다. 공개된 격리수면 선택은 열쇠 상대가 `3/4`로 부족해 비활성 상태였으므로 활성화된 집행권 인계를 골랐다. 선택 54회, trace 188개, 5일차 11:07, 누적 430km이며 동료와 수락한 사이드 의뢰는 없었다.

제품 후보는 기능 버그 1건(P04-01)과 서사 모순 1건(P04-02)이다. 정책 실패 2건은 `harness`로 분리했다. 수정은 하지 않았다.

## 성향과 방법

처음 실행하기 전에 `policy.cjs`에 공개 메인 목표를 빠르게 따르고, 선택적 대화·모집·의뢰를 사양하며, 필요한 보급만 마련하고, 가능하면 코어 격리수면을 고른다는 성향을 적었다. 모든 실행은 seed `201004`, 연료 팩, `reloadAfterChoice:true`다. `choose/decide`는 공개 관측만 받았다. 결과·fx·숨은 조건을 미리 읽거나 상태/자원/동료를 주입하지 않았다.

각 실행은 `require('../harness.cjs').run(config, attemptNN)`를 통해 실제 소스 엔진을 새로 시작했다. 생산 파일, 공용 harness, 다른 player, 기존 QA, 사용자 저장, 서버와 브라우저는 건드리지 않았다. 사후 검토에서만 관련 소스 정의를 확인했다.

## 전체 플레이에서 읽힌 흐름

완주 경로는 부산→양산→밀양→대구→구미→김천→상주→문경→충주→청주→천안→평택→수원→서울이다. 김천에서는 공개 설명에서 짧다고 안내한 동쪽 능선길을 골랐다. 구조 장면에서 '짧게 치고 오른다'를 골라 허리 부상도 겪었고, 이어진 선택에서 네 사람과 수레는 올라왔다. 성공 결과만 골라 본 실행은 아니다.

공개 메인 목표가 특정 장소의 주변 탐색을 지시할 때 같은 곳을 다시 탐색하면 다음 기록으로 이어졌다. 검증키·세 당사자의 정정 증언·명령 원본·아빠의 마지막 기록·엄마의 재회·거점 응답으로 이어지는 순서를 따라갈 수 있었다. 선택적 모집과 의뢰를 하지 않아도 필수 증언을 얻고 서울 진입 조건을 충족했다. 세 증언자는 달구지에 동승을 약속한 것이 아니라는 결과와 빈 동료 명단이 일치했다.

완주 실행에서 필요한 고철은 밀양 공동 펌프와 수원의 현장 활동으로 벌었다. 결과 원문과 구매·실제 자원 변화를 대조했다. 첫 두 실패에서는 장소 수색이 곧 연료 보급이라고 잘못 가정했고, 거래할 고철을 벌 수 있는 현장 활동도 좁은 이름 정규식으로 놓쳤다. 엔진의 이동 불가나 낮은 보급 여유 자체를 버그로 분류하지 않았다.

마지막 재시도의 60L 보급 목표는 과잉 보수적이었다. 특히 수원에서는 서울 한 구간에 필요한 양보다 많이 모으느라 탐색과 다음 날 현장 활동까지 했다. 직행 경로와 선택적 관계 회피라는 성향은 유지했지만, 이 실행을 인간의 최단 시간 플레이나 최소 보급 해법으로 주장하지 않는다. 첫 정책의 '지난다' 인식 누락으로 커피를 산 행동 역시 정책 품질 한계로 남긴다.

남산에서는 여행 일지를 내밀었고, 기록 창구가 잠기는 비용도 먼저 읽었다. #181의 공개 선택은 인계만 활성, 격리수면은 `열쇠를 나눠 맡을 상대 3/4`, 보존은 `감시 근무를 설 사람 0/3`이었다. 준비하러 돌아가는 컨트롤도 있었지만, 선택적 관계 확장을 피하며 가능한 결론을 빨리 내리는 성향으로 인계했다. 원하는 엔딩이 비활성이라는 사실을 버그나 밸런스 결론으로 삼지 않는다.

최종 #187 `seoul_session_reset`의 결과에는 부산에 이송 취소를 알리고 수원 외곽 중계소로 돌아가 엄마와 대화한 뒤 `〔 서울까지 400km · SESSION 1 END 〕`가 기록됐다. #188은 지급 결과 재접속이며 최종 summary/save 모두 본편 종료다.

## 후보와 근거

P04-01의 확정 부분은 **종료 후 상태 변경**이다. attempt02 #154 야영의 자정 처리에서 `thirst` 종료가 확정됐는데도 `G.advance`가 06:30까지 이어져 아침 물 1통 소비와 갈증 초기화를 실행하고, `G.camp`가 차체 회복·빗물 2통·정상 야영 완료를 적용했다. 그래서 저장은 종료 종류가 갈증인데 물 3, 갈증 0이다. root도 별도 격리 진단에서 물 2·갈증 3·차체 60으로 야영한 뒤, 갈증 종료 상태에 물 1·갈증 0·차체 64가 남는 동작을 확인했다. root 진단은 본 담당자의 자연 실행 선택 수와 coverage에 포함하지 않았다.

같은 후보의 별도 층은 **보급 후 구제 가능 시점**이다. 자연 실행 #149에서 빗물 2통을 얻어 하루 동안 보유했지만, `G.dawn`은 다음 아침 자동 섭취보다 먼저 지난 결식 counter를 검사한다. 물 획득 시점과 갈증 해소 시점의 의도된 규칙을 확인해야 하므로, 이 부분만으로 확정 버그를 주장하지 않는다. 초기 고립은 정책 오류이고, 더 확실한 제품 버그는 종료 뒤에도 식사·수리·빗물이 계속 적용되는 동작이다. 브라우저 엔딩 화면이 어떻게 보였다는 주장은 하지 않는다.

P04-02는 attempt02 #124와 #150이다. 식량 0에서 도둑을 보내면 실제 식량은 그대로 0이고 칩도 정확히 `식량 0`이다. 그런데 고정 결과는 '식량 약간이 사라졌다'고 말한다. 고철 3 손실은 실제로 적용됐다. 이미 수정된 실제 증감 칩을 재제보한 것이 아니라 남은 결과 문장과 실제 손실의 불일치다.

자세한 원문, 기대/실제, 전후 수치, 소스 소유자와 확신은 `findings.json`에 있다. P04-H01/H02는 제품 수선 대상이 아니라 정책 오류다.

## 확정하지 않은 해석과 범위

attempt01 제면소 #103은 10:23→12:23의 두 시간 작업 뒤 '그날 저녁은 잔치국수'라고 회고한다. 이후 저녁을 미리 압축한 서술로 읽을 여지가 있어 시간 버그로 확정하지 않았다. 수원 망루의 45분 행동에서 '한 시간이 필요했다'는 표현도 일상적 어림말과 구분할 근거가 부족해 확정 후보에서 뺐다.

서울 진입 #162의 '편지와 봉투와 수첩'은 실제 보유품에 남산행 편지·할아버지 봉투가 없고 이어지는 공개 선택도 해당 물품 부재로 막혀 있어 다소 어색했다. 다만 그 문장이 고유 아이템이 아니라 메인 기록의 종이/봉투를 통칭할 수 있어 미획득 물건 생성 버그로 단정하지 않았다.

캠프 장면이 야영 완료 시각인 06:30 상태와 함께 기록되는 것을 그 자체로 밤/새벽 묘사 오류라고 세지 않았다. 미표시 내부 목표 문구나 UI 레이아웃도 제품 문제로 주장하지 않았다. 현재 기준에서 실제 증감 칩, 한강 관문 선택 이름과 단독 탑승 대사가 바르게 적용된 사례를 과거 제보로 반복하지 않았다.

검수는 격리 Node 자동 실행이다. 사람/브라우저/시각/입력/음성 검수가 아니며, 컷 구성·이미지 크롭·애니메이션·클리핑·실제 화면의 비용 노출·취소/뒤로·모바일·실제 사용자 저장 복원은 미검증이다. 다른 최종 방식의 실행 결과, 서쪽 노선, 모집·동료 미션·사이드 의뢰·모든 무작위 결과를 검증하지 않았다. 이번 편향된 세 실행의 엔딩 빈도는 밸런스 자료가 아니다.
