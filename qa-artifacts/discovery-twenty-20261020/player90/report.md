## 경로와 자원

성공 경로는 부산 → 김해 → 진주 → 남원 → 담양 → 광주 → 목포 → 광주 → 전주 → 무주 → 영동 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울이다. 목포는 n117 DAY3 22:09, 영동은 n180 DAY5 19:48에 실제 도착했다. 상주430km에서 탐방을 접고 공개 메인 목표를 계속 따랐다. 종료 시 물26·식량24·연료63.91L·고철29·차체80.16%, 공식 동료는 없었다.

첫 시도에서는 목포 n96 DAY3 13:24, 영동 n146 DAY5 08:58, 강릉 n293 DAY11 08:14에 도착했다. 이후 강릉·대관령·원주·충주를 거쳐 청주·천안까지 갔다. 물·연료 비축을 낮게 둔 채 긴 탐방과 여러 번의 연료 회수를 이어 간 정책 실패를 보존했다. 예컨대 n299는 강릉 물5·식량11·고철28에서 공개된 물3·식량3 비용의10시간 도보 회수를 선택해 물2·식량7이 됐다. n397 뒤 천안 DAY16 20:28 물0·식량0·피로100에서 n399 야영을 선택했고 DAY17 00:00에 갈증으로 끝났다. 이를 제품의 회복불가 버그로 보고하지 않는다.

두 번째는 물30·식량24·연료70 목표와430km/9일 탐방 예산을 사용했다. 목표가 실제 용량을 넘는 경우 묶음 구매9회가 거부됐다(n86,102,133,138,147,150,153,276,291). 거부 때 자원·시간은 보존됐고 다른 행동으로 계속 진행했다. 이는 정책의 용량 계산 오류다. 다음 구간 `rationForecast/survivalWarning`를 직접 우선하지 않은 정책 한계도 남긴다.

## 제보 판정

확정 버그0건, 보류 후보0건이다. 발견 개수를 맞추지 않았다.

기각 후보 P90-C01: `attempt01` n203 원주 DAY7 06:30에서 “밤길이 생각보다 춥구먼”이라는 손님 대사가 나왔다. 물12·식량23·연료1.65L·고철62, 공식 동료0명이었고 거절 결과 뒤 n204 재로드 → n205 연료 구하기로 이어졌다. 같은 아침 문맥의 탐조등 장면도 n307·348 및 `attempt02` n255에서 읽었다. 원본 trace의 `observation.origin`에는 이미 `kind:'memory',label:'지난밤',timeLabel:'지난밤 · 야영지'`가 있었다. 본인이 작성한 축약 투영이 origin을 빠뜨려 생긴 오독이었다. 두 자연 시도 종료 뒤 source에서도 같은 표지를 확인했다. 현재 시계의 밤 사건이 아니므로 시간 모순 주장을 기각했다. 원시 harness의 결함은 없다. `compact-review.cjs`에 origin을 추가하고 모든 선택의 origin을 보충 검토했다. 실제 브라우저 출처 라벨 가시성은 확인하지 않았다.

사후 확인에서 인접한 `camp_dogs`와 미선택 `camp_visitor` 결과 일부도 노출됐다. 그 뒤 자연 플레이는 하지 않았다. 화자 오류 주장은 없어서 별도 화자 파서 fixture는 만들지 않았다.

취향 의견 P90-O01: 첫 시도에서 n225 이후 같은 “익숙해진 빈 탱크” 회수를12회 읽으니 탐방보다 회수 반복에 집중하게 됐다. 긴 경로와 비축 부족이라는 정책 영향이 커서 제품 결함으로 분류하지 않는다.

## 정책과 검증 근거

직접 쓴 mulberry32는 게임 RNG와 분리했다. 다중 선택마다25% 확률은 현재 가능 대안의 균등 추첨,75%는 호기심·보급·새 선택 가중 추첨이며 모든 대안 가중치는 양수다. 실현 비율을 맞추지 않았다. 첫 시도56회 중 균등14/가중42, 두 번째38회 중 균등10/가중28, 합계94회 중 균등24/가중70이다. 단일 선택55회를 더해149선택이다.

선택 전 재로드149회와 결과 재로드149회가 모두 성공했고 중복 효과는0회였다. 모든 travel은 v8의 실제 UI 출발조건 `forecast.ok && !forecast.shortage`를 통과했다. `walkfuel`은 노출된 `localControls`가 허용할 때만 호출했다. 두 시도의 게임 소스 hash는 동일하다.

`policy-attempt01.cjs`와 `policy-attempt02.cjs`에 각 실행 정책을 보존했다. `policy-evidence.json`에 분기 카운터·hash·정책 한계를, `attempt02/runtime-policy-evidence.json`에 전체 실행 카운터와 실제 가중치·선택·결정 사유를 남겼다. 첫 시도 전체 runtime 자료는 당시 stdout에만 출력됐으며 핵심 카운터를 근거 파일에 옮겼다.

격리 Node VM의 실제 소스 엔진 실행으로, 브라우저·인간·시각·입력·음성 QA는 아니다. 가드레일에 있는 과거 결함 설명을 미리 읽은 한계가 있다. 다른 참가자의 정책/보고와 완주 전 미래 소스는 읽지 않았다. 사용자 실제 저장·탭·배지·서버와 게임 파일은 건드리지 않았고 플레이어90 폴더에만 산출물을 작성했다.
