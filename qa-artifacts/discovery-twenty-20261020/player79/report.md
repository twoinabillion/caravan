# player79 산길 모험가 — 완료

seed `206079`로 실패 1회와 완료 1회를 보존했다. 두 번째 시도는 거창·무주·단양을 모두 방문한 뒤 집행권 인계(`core_transfer`)를 골랐고, DAY8·607km에서 `storyDone=true`, `ending=story_done`, 실제 결과의 `SESSION 1 END`까지 도달했다. 첫 시도는 DAY91 제한으로 끝났으며 완료로 세지 않는다.

두 번째 경로는 부산 → 양산 → 밀양 → 합천 → 거창 → 무주 → 김천 → 상주 → 문경 → 충주 → 청주 → 충주 → 단양 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울이다. 동료는 두 시도 모두 없었다. 여러 선택의 성향을 바꾸거나 게임 자원을 강제로 지급하지 않았다.

## 제보

1. **확정 서사 시간 충돌 — 단양의 오전 뱃놀이에서 노을을 본다.** `attempt02 n196`, DAY6 단양 08:51에 ‘배 타고 직접 세러 간다’를 골랐다. 3시간 뒤 시계는 11:51인데 결과는 “세다가 절벽에 걸린 노을을 만났다”, “팔경에 노을 하나를 보태”라고 완료한다. 기억이나 과거 기록 표시는 없다. 동료0명, 연료7.960L·물15·식량1·고철87에서 선택했고 자원은 그대로였다. 다음 n197 유료 결과 reload에서 효과 재적용 없이 보존됐으며, n198 주변 탐색으로 이어졌다. 자연 시도 종료 뒤 `src/03-data.js:5447`을 확인하니 해당 결과의 노을 문구와 `time:180`이 고정이었다. 시간대에 맞는 결과 또는 진입 조건이 필요하다. 화면 아트나 화자 표시 결함을 주장하는 제보는 아니다.

2. **후보 — 연료5L 이상이지만 모든 출발에 부족한 무주 정차에서 회복 길이 드러나지 않는다.** `attempt01 n112`, DAY3 18:20 무주에서 연료5.650335666666439L·물16·식량13·고철55, 동료0명이었다. 서쪽 노선을 골라 거창/영동은 잠겼고 김천9L·전주12L 모두 실제 UI 출발 기준으로 비활성이었다. 거래에 연료는 없고 `연료 구하기`도 없었다. 사후 실제 UI 소스 `src/07-ui.js:2942`에서 이 컨트롤이 `fuel<5`일 때만 나오는 것을 확인했다. n112 탐색 → n114 검문소 선택 → n116 야영 → n117 탐색 → n118~120 현장일 이후에도 연료는 같았다. 다만 영입·게시판·모든 대안을 소진한 검증은 아니므로 영구 회복불가/확정 softlock으로 세지 않는다. 아래 정책 오류가 머무는 기간을 크게 늘렸다.

## 실패와 정책 한계

첫 시도는 공개 시장에서 연료를43.684L까지만 채웠고, 산길과 김천 왕복 후 위 정차 상태에 들어갔다. 이후 유료 촛불 순찰과 야영을 계속 반복해 고철까지 소진했다(n118~176). 물↔식량 거래도 이용하지 않았다. 일일 작업 한도는 지켰지만 하루가 바뀌는 반복을 멈추지 못한 정책 오류다. DAY91까지 머물렀다는 사실만으로 제품이 회복 불가능하다고 주장하지 않는다.

두 번째 시도는 공개 시장 비축 목표를 연료52L·물13·식량10으로 높이고 유료 반복을 제한했다. `연료 구하기`가 실제 노출될 때만 총5회 사용해 기존 비용을 지불했다. 최종 수원에서도 고정 연료 목표가 적용되어 고철을 모두 쓴 것은 정책의 과도한 비축이다(n266~273). 본편은 완료했고 재시도하지 않았다.

## 전편 검토와 확률 증거

`compact-review.cjs`로 첫 시도238행·28선택, 두 번째337행·78선택을 각 시도 시간순으로 모두 읽었다. 합계 **575행·106선택**이다. entry와 결과, 노출/비활성 선택 및 비용, 전후 위치·시각·동료·재고, 메시지와 다음 행동을 매 발생마다 확인했고 반복 본문만 최초 참조로 줄였다. 읽은 범위는 `findings.json.review`에 남겼다.

독립 xorshift32를 새로 작성했다. 다중 선택마다 별도 난수로 25% 균등 분기를 뽑고 나머지75%에는 모든 대안을 양수로 두는 성향 가중을 적용했다. 첫 시도는 다중24회 중 균등5·가중19, 두 번째는 다중54회 중 균등10·가중44였다. 유한 표본의 실현 비율을 quota로 맞추지 않았다. runtime 카운터는 `policy-evidence.json`에 보존했다. `verify.cjs`로 전체106선택을 같은 PRNG에서 재구성했으며 불일치0, 관측 최소 가중0.58이다.

실제 UI 기준 출발25/25회가 유효했고, unpaid-entry/paid-result reload212회 모두 상태 변화·중복 효과가 없었다. 두 번째 마지막 n336 결과에 `〔 서울까지 400km · SESSION 1 END 〕`가 있고 n337 reload도 `applied:false`였다.

## 구분과 한계

능선 구조의 사람·수레·약을 나눠 올리는 세 단계(n110/113/116)는 산길 성향에 잘 맞았다. 이는 취향 평가다. 본편 회의에서 새로 응답하는 유령은 회의 자체에서 도입·수락하므로 부재 동료 오류로 세지 않았다. 구제 도보의 부족분 소모, raw 피로 소수와 후일담 시계는 확정 결함으로 세지 않았다.

이 감사는 실제 소스 엔진과 격리 저장의 유한 자원 실행이며 브라우저·시각·음성·사람 플레이 검증은 아니다. 자연 시도 전부 종료 전에는 게임 소스·미래 outcome·과거 참가자 정책/보고서를 읽지 않았다. 사후 확인 중 인접 source에 미관찰 대안도 노출됐으나 이후 자연 시도는 없었다. 실제 게임과 사용자 저장은 수정하지 않았다.
