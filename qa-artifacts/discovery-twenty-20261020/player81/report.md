# player81 · 무전 애호가

첫 시도에서 `SESSION 1 END`까지 마쳤다. DAY 7, 579km, 선택 66회이며 마지막 결정은 집행권 인계(`core_transfer`)였다. 청주(n125, DAY 4 12:21), 원주(n143, DAY 5 09:42), 수원(n169, DAY 5 22:20)을 모두 방문했다.

확정 제품 제보와 보류 후보는 0건이다. 버그 수를 채우기 위한 재시도는 하지 않았다.

경로는 부산 → 양산 → 밀양 → 합천 → 거창 → 무주 → 영동 → 대전 → 청주 → 충주 → 원주 → 이천 → 수원 → 평택 → 천안 → 평택 → 수원 → 서울이었다. 물은 최소10, 식량은 최소10, 연료는 최소6.88L였고, 이동17회 모두 실제 UI의 출발 조건을 만족했다. 시장에서 보유 고철로 연료를 샀으며 연료 강제 지급이나 동료 강제 합류는 없었다.

무전 흐름에서는 n242의 응답 확인이 가장 잘 맞았다. DAY 7 11:11 수원 중계소에서 이음망·유령·산지기의 역할을 되읽고, 각 거점의 수락만 송신표에 남겼다. 인계 후 도로와 물차의 우선순위까지 이미 합의됐다고 쓰지 않았다. n238의 엄마는 함께 걷지 못하는 이유를 밝히고 “끊기면 내가 다시 부를게”라고 답했다. n292 후일담에서는 하진에게 귀환을 강요하지 않고 연락 주파수를 적었으며, 엄마의 중계소로 돌아가 비워 둔 의자에 앉았다. 연락의 다음 행동이 끝까지 보였다. 이 평가는 텍스트 취향이며, 음성이나 실제 화자 표시를 검증한 결과는 아니다.

플레이 정책에는 두 한계가 남았다.

- n89에서 재이에게 “김천까지 같이 가요”라고 했지만 경로 정책은 김천을 따라가지 않았다. DAY 3 06:30 무주에서 연료20.35L·물19·식량14·고철35였고, 다음에는 탐색 후 영동으로 갔다. 마지막 save에도 김천행 임시 동행이 `task`로 남았다. 정식 동료는 끝까지0명이지만, 이 임시 동행 때문에 모든 장면을 완전 독행이라고 부를 수는 없다.
- n188에서는 수원의 명령 대조 탐색이 열려 있었는데 일반 탐색과 같은 하루3회 제한에 걸려 평택으로 출발했다. 당시 DAY 6 08:50, 연료38.23L·물20·식량14·고철79였다. 이동 후 공개 메인 목표가 천안을 안내했고 n204 탐색, n206 대조로 이어졌다. 현재 위치의 메인 행동을 정책이 놓친 사례다.

자연 시도가 끝난 뒤 trace n1~293을 시간순으로 읽었다. 선택66회의 진입문·선택지·요구량·고지·결과, 모든 행의 전후 시간·위치·재고·동료·메시지·다음 행동을 확인했다. 읽기용 투영에서 같은 상태는 직전 AFTER를, 같은 목표는 최초 행을 참조했다. 첫 출력에서 잘린 n15~27은 다시 읽었다. 선택 전 로드66회와 지불 결과 재생66회는 모두 성공했고, 결과 효과를 다시 적용한 경우는 없었다.

다중 선택42회 가운데 균등 추첨9회, 성향 가중 추첨33회였다. 단일 선택은24회다. 게임과 분리한 xorshift32 난수를 썼고 다중 선택 때마다25% 분기로 균등 추첨했다. 실현 비율21.4%를 맞추려고 재실행하거나 선택을 바꾸지 않았다. runtime의 전체 선택 index·weight·mode는 `attempt01/policy-runtime.json`, 집계와 검증은 `policy-evidence.json`에 남겼다.

이번 감사는 격리 Node VM의 실제 소스 엔진 플레이다. 브라우저 화면·이미지 크롭·키보드/터치·애니메이션·오디오·실제 Continue 화면 복구는 확인하지 않았다. raw main은 공책 UI로 보지 않았고, 후일담의 귀환을 서울에 남은 state 좌표나 엔딩 시계와 비교해 오류로 세지 않았다. AGENTS·guardrails·BRIEF의 기존 문제 설명을 읽었으므로 완전 블라인드도 아니다. 다른 담당자의 정책·보고서·발견, 완주 전 미래 이벤트/결과 source는 읽지 않았다. 사후 제품 source나 별도 fixture 진단은 필요하지 않았다.
