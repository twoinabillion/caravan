## 확인한 문제 1건

**P85-01 / P2 — 지하상가의 ‘글씨를 존중한다’가 고지 없이 물을 기부한다.**

자연 발생 n104 탐색 뒤 n106에서 `exp_underground`의 index1을 골랐다. DAY3 15:29, 상주 자전거길, 동료0명, 물10·식량6·고철57·차체90%였다. 진입은 ‘문 두드리지 말 것’이라는 글씨를 소개하고 선택은 ‘글씨를 존중한다’였으며, 물 기부나 비용은 설명하지 않았다. 결과는 “대신 입구에 물 한 통을 두고 왔다”이고 물이10→9로 줄었다. 시간·나머지 재고는 그대로였다. n107 새로 읽기도 재차감 없이 복원됐고, n108 문경 이동이 가능했다. 진행을 막는 문제는 아니다.

모든 자연 플레이가 끝난 뒤 실제 선택의 비용 소유자와 엔진을 확인했다. 해당 선택은 `req=null`, 비용 빈 값, 예측 고지 없음이었다. 실제 UI의 `eventChoiceData`도 이 요구량·예측을 사용한다. 별도 격리 fixture에서는 물10→9를 재현했고, 물0에서도 선택이 허용되어 물0을 유지하면서 똑같이 “물 한 통을 두고 왔다”고 출력했다. 물0 사례는 사후 진단이며 자연 발생으로 세지 않았다. 기부 의사·물1 소모를 미리 설명하고 소지량에 맞게 처리해야 한다.

근거: [trace](attempt01/player85-trace.json) n104–108, [격리 진단](diagnostic-underground.json), [진단 스크립트](diagnose-underground.cjs). 실제 브라우저 화면의 시각적 확인은 하지 않았다. 게임 코드는 수정하지 않았다.

## 정책과 검토 범위

공개 선택·비용·지도·재고만 보고 선택했다. 게임과 분리한 xorshift32에서 다중 선택의25%는 균등 추첨,75%는 모두 양수인 성향 가중 추첨으로 분기했다. 다중 선택44회 중 균등11회·가중33회, 단일25회였다. 유한 비율을 맞추지 않았고 성공을 반복하지 않았다. 실행 프로세스의 카운터는 harness 출력에 남지 않아, 완료 후 같은 sampler에69개 frozen observation을 넣어 모든 실제 index 일치를 확인했다. 이 차이는 [policy-evidence.json](policy-evidence.json)에 명시했다.

게시판은5번 열었지만 수락은0번이었다. 본인 정책이 공개 `kind=deliver` 대신 ‘배달·전달·소포’ 문자열을 찾아 ‘건네고’, ‘편지’, ‘부품 궤짝’을 놓쳤다. 따라서 게시판 배달의 기한·인계·보상은 이번 플레이의 검증 범위에 넣지 않았다. 이는 게임 문제가 아닌 정책 한계다. 반면 n158의 정정·서명 뒤 사본만 맡고 원본은 당사자가 가져가는 처리, n317의 하진에게 귀환 선택권을 돌려주는 결말은 배달부 관점에서 분명했다.

`compact-review.cjs`로 n1–318을 순서대로 읽었다. 69개 선택의 진입 본문·전체 선택지·고지·결과·전후 시간/위치/동료/재고·메시지와 다음 행동을 검토했고, 미지급 진입69회·지급 결과69회의 reload도 각 발생을 확인했다. 전편 범위는 `findings.json.review.ranges`에 남겼다. 모든 지급 결과 reload는 `applied=false`였으며 추가 자원 지급이나 차감은 없었다.

Node VM 격리 엔진 감사이므로 시각·입력·음성 QA는 아니다. 동료 대화와 연료5 미만 복구 컨트롤은 자연 발생하지 않았다. 문서의 기존 단서 외에 다른 참가자의 정책·보고서나 완주 전 미래 source/outcome은 읽지 않았다. source 문맥의 인접 미관찰 대안은 완주 뒤에만 노출됐으며 이후 자연 플레이에 이용하지 않았다. 사용자 저장·탭·Studio·배지·서버는 건드리지 않았다.
