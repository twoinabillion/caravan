## 방식과 계측에서 발견한 문제

각 정책은 게임 RNG와 분리한 seeded PRNG를 썼다. 여러 대안이 가능할 때 선언 확률25%는 균등 추첨, 나머지75%는 모든 대안이 양수인 성향 가중 추첨이다. 실제 균등 비율이나 결말 종류를 quota로 맞추지 않았다. 단어 기반 성향이 실제 사람의 동기/판단을 완전히 재현하지는 못한다.

모든 에이전트가 저장/대사 가드레일을 읽어 과거 결함 단서를 이미 접했다. 완전 블라인드는 아니다. 다른 사람의 정책/보고·미래 결과 소스는 자기 자연 시도가 끝나기 전 읽지 않도록 했고, 사후 인접 소스 노출은 각 보고서에 남겼다. 최대3시도 중 실제로는 각1~2시도를 사용했다.

### T01 — 최초3명의 UI 불가 출발

구 v6 관측은 `G.canTravelTo`만 봤지만 실제 UI의 출발 조건은 `forecast.ok&&!forecast.shortage`다. 최초71/72/73의 원본에서 연료 부족 출발5건이 있었다. 그 뒤 발생을 실제 UI 경로로 일반화하지 않는다.

게임은 건드리지 않고 이번 QA wrapper의 관측/dispatch만 보정했다. 원본 정책/trace/보고 사본을 보존한 채 **같은3명의 task/ID/seed**로 검증했다. 이미 소스를 본 뒤라 이3회는 비블라인드 계측 재검증이고 새 참가자나 블라인드 자연 발견으로 세지 않는다. 나머지17명은 최초부터 보정된 출발 조건을 썼다.

[v7 계측 전후 hash](./instrumentation-v7.json) · [당시 검사2/2](./observer-tests.log).

### T02 — 저연료 정차 복구 버튼 누락

74/75 원 실패에서 연료3L 안팎인데 출발이 잠겨 야영만 반복했다. 실제 UI에는5L 미만의 ‘연료 구하기’가 있는데 v7 감사에는 그 버튼이 빠져 있었다. 두 실패에는 정책 실수와 도구 누락이 함께 있다.

이번 QA helper에 실제 버튼과 같은 조건/`G.openRescue` 호출만 추가했다. 강제 공급·새 구제·비용/확률 변경은 아니다.77–90은 v8을 사용했고 기존 성공률을 꾸미려고71–76을 다시 돌리지 않았다. 실제 조건도 안 맞는79의5.65L 사례는 별도 C04다.

[v8 계측 기록](./instrumentation-v8.json) · [검사3/3](./observer-tests-v8.log). 마지막에도 같은3검사를 다시 실행해 통과했다. 이는 생산 전체927검사를 새로 실행했다는 뜻이 아니다.

용량 필드, 모든 시장/게시판/제작/수리 UI, 실제 퍼크·합류·종결 클릭은 완전한 UI 복제가 아니다. 가득 찬 탱크 거래가 실제 엔진에서 거절되고 시간/돈을 보존한 관측은 남겼지만 raw 소수점/숨은 enabled 차이를 실화면 결함으로 만들지는 않았다.20명 모두 출발 조건 보정 상태로 본편을 끝냈다고 모든 입력이 실제 UI와 동등하다는 뜻은 아니다.

## 완료 검증·소스와 실제 Studio

[verification.json](./verification.json)의 완료/seed/실제 종결 저장/검토 행·선택 수/원제보 전부 판정/서로 다른 제출 정책 파일 검사를 통과했다. 다른 hash는 파일이 다르다는 증거이지 성격의 의미적 독립성을 수학적으로 증명한 것은 아니다. [collected.json](./collected.json)은 전체/출발 보정 범위·지리·재개·원제보를 함께 담는다. 전편 읽기는 각 에이전트의 검토 진술이며 기계 검사는 그 행위를 대신 증명하지 않는다.

11:05:50→12:12:52 UTC의 [소스 지문](./freeze-before.json) / [종료 지문](./freeze-after.json):

- 생산 engine SHA `ad02e459f7a9ae99ba869f0d30e8a6508f9f459473244d838fed0ea9443e2d6a` 동일.
- 기존 `src/assets/tools` diff SHA `6ff496301b49a177677059694de2ef1592d1eb065994c083c307f651fa824220` 동일.
- 생성 HTML106,317,594bytes / SHA `bb8666c76a38abf435515d9d51dac9f75e4343d8448a085f5caace18e50a9c9a` 동일. 손편집/새 빌드 없음.
- 이전 감사 관측기4개는 동일하고 이번 wrapper/helper만 위 T01/T02에 따라 의도적으로 바뀌었다. ‘관측기 전부 무변경’이라고 하지 않는다.
- 시도별 runner source SHA `0b900e2fd1875f5ccdaa09c9448d57f5d913a4577bb3e10b12696afe11199e5c`는 파일 묶음이 달라 engine SHA와 다른 값이다.31시도 모두 같은 source다.

실제 지정 Studio/미리보기의 [최초 GET](./live-before.json)11:05:53.813 UTC와 [종료 GET](./live-after.json)12:13:03.558 UTC는 모두200이었다. 두 응답 모두 타이틀/game:null·360×728/DPR2, loaded/style1792485720870·pending1792486398018·applyingfalse다. 즉 **이전 수정 코드도 현재 화면에는 적용 대기 중**이고, 이번 감사는 그 수선을 포함한 최신 소스를 검사했다. 사용자 저장·배지·새로고침·탭/서버는 조작하지 않았다.

GET의 텍스트 상태는 스크린샷이나 시각 검수 증거가 아니다. 실제 브라우저 완주·모바일 터치/글자 크기/크롭·음성/애니메이션/성능·설치·보존감시 결말은 이번에 검증하지 않았다. 모든 버그를 찾았다는 보장도 아니다.
