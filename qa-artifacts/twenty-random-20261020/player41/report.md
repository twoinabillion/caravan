같은 이름·준비물·시드(상혁 / 연료 / 204041)로 두 번 플레이했다. 첫 시도는 DAY21 갈증 사망으로 끝났고 그대로 보존했다. 공개 보급·이동·현장 활동 관찰을 바탕으로 정책을 고친 두 번째 시도는 DAY8, 누적842km에 `core_transfer`로 완료했다. `storyDone=true`, `seoul_session_reset`의 실제 결과에 `〔 서울까지 400km · SESSION 1 END 〕`가 남았다(attempt02 n285).

두 시도 합계726행, 선택187회를 처음부터 끝까지 읽었다. 각 발생의 본문, 선택지와 비활성 조건, 선택, 결과, 자원·시간·위치·동료의 전후 상태를 확인했다. 같은 문장은 최초 행을 참조하되 각 발생의 문맥은 따로 읽었고, 잘린 출력 구간은 다시 열었다. 검토기는 `review-reader.cjs`, 상세 행 범위는 `findings.json`에 있다.

## 루트 확인이 필요한 후보

- P41-C01 (P2), attempt01 n350: **“가까운 마을로 견인을 부탁한다”**를 골랐지만 고철20과5시간을 내고 연료6만 받았다. 천안→평택의 같은19.24/28km 지점, `at=null`에 그대로 남았고 n351 리로드 뒤에도 같았다. 말 그대로 마을로 옮겨 주는 행동으로 이해하기 쉽다. 작은 수정 경계는 기존 비용·효과를 보존하고 비상 연료 구매에 맞게 선택과 결과를 고치는 것이다. 실제 견인 구현은 도착·경로 전환까지 별도로 검토해야 한다.
- P41-C02 (P3), attempt01 n84: 현재 장면의 **“사람들이 비를 피한다”**가 맑은 날 DAY3 08:32에 나왔다. 논산→대전26.45/40km, 동료 없음, 연료2.94·식량7·물10·고철2였고 앞뒤 날씨는 모두 `clear`, `origin=null`이다. 같은 고정 본문은 두 번째 시도의 폭풍 날씨에서는 맞았다(n85). 단서와 효과는 유지하고 날씨를 전제하지 않는 문장이나 현재 날씨 분기로 좁혀 확인하면 된다.

소스 확인은 모든 자연 시도가 끝난 뒤에만 했다. 두 후보의 관찰된 정의와 치명적 시간 경계의 결과 처리만 확인했다. 생산 코드는 수정하지 않았다.

## 제외한 항목과 정책 한계

첫 시도 마지막 탈진은19:11부터 자정까지289분만 흐르고 사망했지만 하네스 반환 텍스트에는 “여섯 시간이 지나”가 기록됐다. 실제 UI는 `S.ended`일 때 결과를 그리기 전에 종료하므로 표시 결함 후보에서 제외했다. 원시 기록과 UI 노출을 구분한 사례다.

첫 정책은 긴 귀환 배달을 연속 수락하고 현장 활동 이름을 좁게 매칭해 보급을 놓쳤다. 사망 자체는 정책 실패다. 완료 정책도 조달 의뢰의 `need:{name,qty}`를 물품별 수량 맵처럼 비교하는 필터 문제가 있어 조달 수락 검증은 주장하지 않는다. 실제 배달 수락·인계는 두 시도에서 확인했다.

이 검토는 격리된 Node 엔진 플레이이며 표시·타이머·오디오는 대체됐다. 화면, 입력, 이미지 자르기, 음성, 실제 목표 노트북, 사용자의 저장·Studio 상태는 검증하지 않았다. 결과 뒤 리로드186회는 모두 재적용 없이 복원됐다. 두 후보는 아직 루트 확인 대상이다.
