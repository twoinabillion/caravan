# player38 · 원칙 있는 비폭력 변호인

새 정책과 seed `204038`, 식량 준비로 한 번 플레이해 본편을 끝냈다. `storyDone=true`, 종료 종류 `story_done`, 결론은 `core_transfer`다. 11일차, 누적 841km에서 297행의 「새 세션」 결과에 `SESSION 1 END`가 나왔고 이후 종료 처리까지 이어졌다. 실패·재시도·상태 주입은 없다.

전체 298행을 시간순으로 읽었다. 선택 84회의 진입 본문, 제시된 선택과 비활성 조건, 실제 선택, 결과 전문, 비용 칩, 전후 시간·위치·자원·동료와 다음 행동을 대조했다. 반복되는 상태와 안내는 축약했지만 각 발생 시점은 확인했다. 선택 직후 재로드 84회 모두 `loaded=true`, `replayed=true`, `applied=false`이며 관측 가능한 전후 상태가 정확히 같았다.

다중 선택 58회 중 균등 추첨 18회(31.0%), 성향 가중 추첨 40회였다. 정책은 매 다중 선택에 28% 확률로 활성 선택 전체를 균등 추첨하고, 나머지에서는 설명·기록·증거·도움에 가중치를 두되 모든 대안에 양의 확률을 남겼다. 실제 결과를 미리 보거나 선택 ID로 성공 분기를 고르지 않았다. 원본 정책과 `random-qa.json`에 시드·해시·추첨 행을 남겼다.

검토 후보는 한 건이다. 8일차 05:31, 영동에서 대전으로 가던 659.5km 지점의 `patrol_toll`에서 「논길로 멀리 우회한다」를 골랐다. 연료는 `2.0059372499999943→0L`로 정상 소진됐지만 결과 칩이 `연료 -2.005937L`로 반환됐다(185행). 상태 계산은 그대로 두고 새 결과의 표시 정밀도만 줄일 사안인지, 부모 에이전트가 실제 표시 소비자를 확인하면 된다. 브라우저에서 보인다고 확정하거나 글자 잘림을 주장하지 않는다. 186행 재로드에서는 중복 지불이 없었다.

이 플레이의 심한 연료·식량 부족은 별도로 기록했다. 정책은 시장이나 감당 가능한 일거리가 없으면 출발을 막지 않아, 62·116·172·183·211·236·261행에서 부족 예보를 보고도 이동했다. 미완료 강우 부탁을 계속 우선해 청주 이후 남쪽으로 되짚은 구간도 있었다. 이 때문에 생긴 연료 구조·허기·피로 사건을 엔진 결함으로 세지 않았다. 기아를 만들기 위해 일부러 자원을 버린 실험은 아니다.

후반부에서는 검증키·원본 명령·아빠 기록·엄마 재회 순서가 유지됐고, 실제 연결된 세 거점의 응답이 최종 인계에 이어졌다. 보존 선택은 실제 근무 가능 동료가 0/3이라 비활성화됐지만, 인계와 격리 수면은 선택할 수 있었다. 마지막 기록은 맡긴 작업장 열쇠, 함께 만든 퓨즈 자리, 민지 합류 방식으로 이번 선택을 다시 받았다. 추가로 확정할 서사 결함은 찾지 못했다.

필수 지침과 허용된 하네스·관측 API 외에는 종료 전 원문 소스, 미래 결과, 다른 플레이어 정책·보고서를 읽지 않았다. 종료 후에도 제작 소스는 열지 않아 후보 확인을 부모에게 넘긴다. 실제 소스 엔진을 별도 메모리 저장소에서 실행했으며 자원은 유한했다. 화면·오디오·타이머는 대체했으므로 브라우저, 모바일, 실제 노트 UI, 취소·뒤로·Continue, 시각·음향 품질의 증거는 아니다. 프로덕션과 Studio, 사용자의 저장 데이터는 바꾸지 않았다.

원시 결과는 `attempt01/player38-trace.json`, `player38-summary.json`, `player38-save.json`에 있다. 구조화된 후보·정책 한계는 `findings.json`, 추첨 검증은 `random-qa.json`, 구간별 재검토 출력은 `review.cjs`로 확인할 수 있다.
