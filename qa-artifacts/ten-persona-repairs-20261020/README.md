## 검증

- 신규 [실제 엔진·reader·공책 회귀](../../tests/test_ten_persona_repairs.cjs). 처음22개 중19개 실패로 원 결함을 재현한 뒤, 인접 화자와 종료 UI/옛 피로 칩을 더해 최종25개를 검사한다.
- `before.json`은 생산 수정 전에 캡처한 사건 계약/파일hash다. 선택 조건·확률·비용·효과는 원 계약과 대조한다. 새 기억 출처는 명시적으로 검사한 뒤 기존 corpus baseline으로 투영한다. 전체 해시를 새 값으로 덮지 않았다.
- 최종 전체 source 검사, 대사/콘텐츠 참조 검사·HTML 빌드·diff 결과와 파일hash는 [verification.json](verification.json)에 기록한다. 기존 용량 권장 경고와 대사 반복 어두 후보는 별도다.
- 기존 성공 정책 10개를 현재 엔진에서 다시 실행했다. 최종 `attempt02`는 10/10 본편 완료, 755선택·3종결 방식, 지급 후755/선택 전89/일반34 재로드 총878회 관측 동일·재지급0이다. 이전 각 성공 실행과 사건 ID/선택 index 순서 차이0. 새 에이전트나 사람/브라우저 완주가 아니다.
- 첫 회귀 실행 `attempt01`은 07의 **원래 실패했던 초기 정책을 잘못 가져온 실행기 선택 실수**로 중단했다. 실제 탈수와 앞선6완료를 원본 `replay-results.json`에 남겼다. 원 감사의 성공 정책 `policy-attempt02.cjs`로 선택 경로를 바로잡고, 최종10정책 전체를 새 `attempt02`에서 돌렸다. 원래 실패를 코드 퇴행이나 수정으로 인한 난이도 변화로 세지 않는다. 두 실행 사이 인접 화자 명시도 추가했으므로 엔진hash가 다르며, 최종10개끼리는 같은 hash다.

## 적용 상태와 남은 범위

실제 Studio 주소4327·미리보기4319를 사용했다. 수정 전은 title·저장없음·360×728/DPR2·loaded/style1792421030997·pendingnull이다. 중간16:25:18Z GET도 같은 화면·loaded를 유지하고 새 pending1792427103006을 확인했다. 최종 GET·빌드 상태는 [live-after.json](live-after.json)에 따로 기록한다. 사용자 저장·배지·새로고침·새 서버·탭을 조작하지 않았다.

구현된 새 코드는 의도적인 **새 코드 준비됨** 적용 대상이다. 새 코드가 적용되지 않은 타이틀은 수정한 사건의 시각 검수 증거가 아니다. 실제 해당 사건의 모바일 그림/출처/선택/결과/공책·음성·입력/취소·브라우저 refresh/Continue는 미검수다. 자동 재로드는 기록된 snapshot의 동등성만 보며 숨은 RNG 후속 흐름까지 보장하지 않는다. 현재 사용자의 화면으로 새 테스트 저장을 대신 열지 않았다.

Claude 대사 교차검토는 실제 도구를 호출했으나 사용 한도로 실패했다. 초안/리뷰를 받았다고 주장하지 않으며, 이번 문구는 Codex가 원문·인물 말투와 상태를 대조해 수선했다. 게임 디렉터/대사·저장 지침으로 수선 경계를 정했고 PARA 기록으로 실행과 미검증 범위를 분리했다.
