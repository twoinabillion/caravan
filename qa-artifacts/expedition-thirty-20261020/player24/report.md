# player24 — 직진·생존 원정

seed 207024, fuel 준비, 독립 정책으로 한 번 실행했다. 4일 17:40·430km에 본편 엔딩 `story_done` / `core_transfer`에 도달했다. fatal ending이 아니다. 양산·구미·청주·수원 네 목표를 모두 방문했다. 확정 결함은 **0건**이다. production과 사용자 Studio·저장·서버는 건드리지 않았다.

원문 trace는 [attempt01/player24-trace.json](attempt01/player24-trace.json), 종료 상태는 [summary](attempt01/player24-summary.json), 실제 실행의 분기 기록은 [adapter-policy-evidence.json](attempt01/adapter-policy-evidence.json)에 있다. 게임 결과를 보고 정책을 바꾸거나 다시 실행하지 않았다.

## 전수 검토

227행 전부와 선택 52회 전부를 순서대로 읽었다. `review.cjs`가 선택 전 텍스트·전체 선택지와 조건·선택 결과·origin·chip, 전후 장소·시간·자원·로스터, 바로 앞뒤 상태와 행동을 출력했다. 검토 범위는 1–25, 26–50, 51–75, 76–100, 101–125, 126–150, 151–175, 176–200, 201–215, 216–227이다. 첫 출력의 과도한 반복으로 생긴 잘림은 압축 출력을 만든 뒤 1–25부터 다시 읽어 해소했다. 표시는 소수 셋째 자리로 줄였으며 원본 trace의 정밀도는 보존했다.

구성은 새 게임1, 선택52, 선택 전 reload52, 결과 reload52, travel13, drive26, 거래9, 현장 작업4, 야영3, 탐색9, 연료 회복1, 서울 단계 진입5행이다. n1–227의 연속성을 검사했다. reload104행에서 불러오기 실패·효과 재적용·핵심 자원과 로스터 변화는 없었다.

선택용 PRNG는 엔진과 분리한 LCG다. 모든 보이는 enabled 선택의 가중치가 양수이고 25% 확률로 균등 선택했다. 실제로 uniform17회·weighted35회였고 선택 index0·1·2·3·4가 나왔다. 결정 호출은39회, 동료 영입 제안은0회다. 첫 실행 전에는 지침과 공개 observation 생성부만 읽었고 미래 결과나 이전 참가자 정책·보고·결과는 읽지 않았다.

## 실제로 확인한 흐름

첫 발신 기록(n28–32) → 김천 운행표(n60–67) → 부모님의 분리된 작업(n91–96) → 청주 영상·검증키·상자·분리 절차·세 증언(n106–126) → 천안 명령 원본(n131–136) → 평택 실패 진입과 아빠의 기록(n141–149) → 수원 엄마의 신호·재회·설명·세 거점 응답(n170–184) → 서울 진입·코어 인계·세션 종료(n189–227)가 연결됐다.

청주에서는 새 `mainEvidence` 안내를 따라 n107·111·115·122에 네 번 탐색했다. 앞선 검색이 있었다고 장소를 영구 제외하지 않아 진행됐다. 분리 절차 두 장 뒤에 실제 검증키가 생겼고(n119–122), 세 증언 뒤에 명령 원본이 열렸으며(n123–136), 아빠 기록 뒤에 엄마의 현재 신호와 재회가 열렸다(n146–178). 최종 인계에는 실제로 응답한 이음망·유령·산지기 세 채널이 쓰였다(n180–183, n213–218).

최소한의 안내 탐색을 계속 수행했기 때문에 놓친 증거를 북쪽에서 회수하는 사본 분기는 자연 발생하지 않았다. 북쪽 사본의 출처·화자·순서를 검증한 run으로 집계하면 안 된다. 같은 seed에서 그 분기를 만들려고 다시 뛰지도 않았다.

## 결함과 구분한 것

평택의 연료 회복은 내 장거리 보급 계획이 부족해서 필요했다. n141 도착 연료3.56L에 다음 수원 forecast는5L였다. 제공된 `walkfuel`만 사용했고(n148–151), 기다리기 실패가10시간·물3·식량3을 소모하고 연료8L를 주는 결과와 전후 수치가 맞았다. 야영 후 수원 출발도 forecast를 통과했다(n152–155). softlock이나 자원 오류가 아니다.

수원에서는 마지막 서울34km에도 고정36L 연료 버퍼를 채우려 거래·작업을 반복했다(n159–170). 느려진 원인은 정책의 고정 목표다. 실제 현장 작업은 완료되고 보상·할인이 반영됐다. 게임이 불필요한 노동을 강제했다고 보지 않는다.

에필로그의 밤·새벽 문장은 종료 후 서술이며 엔진17:40과 불일치한다고 신고하지 않았다(n219–226). 마지막 선택 행에서 `ended=false`였지만 결과를 보존하는 deferred finalization이 끝난 summary는 `storyDone=true`와 완료 main entry를 기록한다. fatal을 본편 엔딩으로 세지 않았다.

감상으로는 청주의 반복 탐색이 한 장소에서 긴 기록 묶음을 읽는 인상을 줬다. 인과는 이해됐다. 엄마의 원격 역할과 세 거점의 응답, 혼자 온 상태에서 동료 선택을 제한한 점은 좋았다. 이는 이 어댑터에서 읽은 이야기의 감상이며 실제 UI 조작성 평가는 아니다.

한 시도·한 seed만 검토했다. 동료·업그레이드·사이드 미션·제작·다른 최종 방법·준비 후 복귀는 미실행이다. API 성공은 버튼 발견·클릭·스크린샷·음향·네이티브 폰 QA가 아니다. 상세 의견, 반증, 정책/adapter 한계와 인접 n 증거는 [findings.json](findings.json)에 분리했다.
