## 종합 디렉터 판단 — 개별 문장보다 먼저 지킬 계약

1. **현재 자원·신체 상태:** 실제로 허기를 해소했으면 미발행 기아 위기는 무효여야 하고, 실제로 잤다면 깨어 있던8시간으로 처리하지 않아야 한다. 이 두 수선은 서술을 추가하는 일이 아니라 상태 계약을 맞추는 일이다. 저장 전후·지급 전후·다음 행동 회귀가 우선이다.
2. **현재 장면의 자격:** 광역 지역/밤 태그만으로 바닷가·수면·서울 잔여 거리까지 가정하면 우회 원정에서 무너진다. 위치·진입 모드·현재 잔여 거리 계약을 기존 사건 가용성 소유자로 맞추고, 빠진 별도 이동/수면을 서술로 발명하지 않는다.
3. **실제로 쌓은 관계의 기억:** 이름을 열거하는 회상은 실제 만남으로, 완성 알림은 실제 완성 시점으로 맞춘다. 비용·확률·동료 반대 성격·유효한 송출 가능성은 이 정리에 섞어 바꾸지 않는다.
4. **화면과 도구를 구분:** 예보 API/공책 내부 데이터와 실제 UI가 보여 주는 필드를 구분한다. engine-only 제보를 화면 버그로 승격하지 않는다. 실제 모바일 초반 플레이, 보존감시 결말과 숨은 장소의 화면·음성 검수는 이 감사로 대체되지 않는다.

반복 의견도 우선순위가 다르다. 여러 정책에서 단위 거래·연료 구제·같은 검문소/야영 문장이 반복됐지만, 과잉 비축과 길 찾기 실패가 반복을 크게 만들었다. 이를 근거로 즉시 거래 시간·보급량·발생 확률을 바꾸지 않는다. 사람 플레이에서 실제 조작 부담을 확인한 뒤 필요하면 묶음 수량/총시간 안내의 **별도 디자인 초안**을 검토한다. 청주·수원 연속 기록의 밀도도 실제 읽기 호흡을 먼저 본다. 반대로 선택한 작업·유대·거절·미완료 약속이 야영/결말에 남는 체험은 여러 실행에서 장점으로 보고됐으므로 보존한다.

아래 판정은 raw findings에만 고정 ID를 부여한다. 긍정·취향·약한 명료성 의견과 정책 실패는 개인 보고의 opinions/rejected/policyLimitations에도 남아 있으며 모두를 ‘고칠 버그 수’로 합산하지 않는다.

중요한 보정: 현재 시장 보드는 `G.canStoreSupply`로 이 묶음을 비활성화하므로, 어댑터가 요청한 n220을 실제 사용자가 누를 수 있는 버튼/실제로 뜬 toast로 주장하지 않는다. 단순히 옛 buy 함수만 따라가면 UI 가용성 차이를 놓친다. 다만 현재 공급 행 자체의 sub도 `S[key]/G.supplyMax(key)`를 그대로 보간하고, 행 렌더러는 esc만 하므로 **실제 소비 소유자의 수치 문자열 정리 누락**은 별도로 확인된다. API 거절 why도 원값이다.

표시용 formatter만 공유해 현재량/최대량을 짧게 맞추면 되는 낮은 강도 수선이다. 내부 연료 정밀도·구매 gate·돈/시간 미차감은 정상이며 반올림한 재고로 계산하면 안 된다. 실제 줄바꿈·잘림·모바일 가독성은 미검수다. 다른 raw 결과 칩의 긴 소수는 이미 `storyFeedbackChip`에서 정리되므로 같은 버그로 합치지 않는다.
