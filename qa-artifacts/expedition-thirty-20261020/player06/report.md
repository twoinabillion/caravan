`review.rowsReviewed=722`, `review.choiceOccurrencesReviewed=150`. `review.cjs`로 모든 행을 순서대로 읽었고, 모든 선택의 전체 진입문·선택 라벨·힌트·결과·origin과 전후 자원/위치/시간/명단, 직전·직후 행을 검토했다. 같은 상태는 `=`로 명시한다. 처음 잘린 출력은 압축 출력으로 다시 읽었다. 범위별 내역은 `findings.json`에 있다.

확정할 새 게임 버그는 0건이다. 아래에는 실제 확인한 경로와 관측 한계를 남긴다.

첫 시도에서는 밀양에서 ‘한 박사에게 편지’를 수락했다(n44–45). 이후 김천의 동쪽 회랑 선택은 청주까지 다른 의뢰 목적지로 나갈 수 없다고 분명히 알렸다(n105–107). 적은 비축, 연료 지원 반복과 탐색 지연으로 DAY 7에 due6 편지가 실패했다(n183–186). 이후 부족한 연료로 짧은 경로를 못 타면 다른 가능한 길로 돌아가는 정책까지 겹쳤다. 이는 내 계획 실패로 분류했다.

원래 정책은 `policy-attempt01.cjs`에 보존했다. 두 번째에는 공개 시장에서 긴 구간을 위한 유한 비축을 하고, 의뢰 중 선택 탐색·새 모집을 줄였으며, 현재 메인 목표가 요구하는 탐색을 우선했다. 같은 seed, 같은 양수가중 무작위 선택을 유지했다. 이벤트 정답표나 숨은 결과를 사용하지 않았다.

두 번째 시도의 실제 납품은 모두 성공했다.

증거는 `attempt02/player06-trace.json` n59–60/94–96, n100–101/117–119, n119–120/186–188이다. 도착 직후 `ready=true`가 되었지만 수령은 별도의 `turnin-quest`에서만 일어났다. 계약 삭제와 실제 고철 증가, 알림이 일치했다. 수락·기한·보너스 지급을 하나의 결과로 뭉뚱그리지 않았다.

배달부 관점에서는 수령인의 한 줄 답이 있으면 더 기억에 남을 것 같다. 관측한 두 편지는 별도 장면 없이 완료 알림으로 마무리됐다. 이건 취향 의견이며, 존재할 수 있는 다른 편지 후속을 없다고 판정한 것은 아니다.

혼자 도착한 종장도 이어졌다. 보존 근무표를 물으면 ‘첫 근무에 필요한 세 사람 중 0명’이라고 답했고(n312–314), 이어 실제 가능한 인계를 골라 마지막 세션까지 닫았다(n315–326). 야영의 지난밤 회상과 종장/후일담의 서술 시간을 현재 시계의 오류로 세지 않았다.

원시 칩의 긴 소수점과 사망 시 반환된 완주형 탈진 문장은 후보에서 제외했다. 전편 검토 후 해당 소비자만 확인하니 실제 UI는 숫자를 반올림하고, `S.ended`이면 결과문을 그리지 않고 바로 종료했다. API 반환값만으로 화면 버그를 만들지 않았다.

25% 균등 탐색과 나머지 양수가중 성향 선택의 실제 같은 프로세스 기록은 각 `adapter-policy-evidence.json`에 있다. 첫 시도 균등29/성향60, 두 번째 균등12/성향49이며 선택 인덱스도 각각 0–3, 0–4로 달라졌다.

조달 계약은 관측된 제안에 없어서 수락·조달·납품하지 않았다. 게시판의 장기 배달 연속 계약은 제안만 읽고 선택하지 않았다. 기존 authored 편지 후속도 자연 관측되지 않았다. 동료 정식 모집·획득 퍽·개조·제작·야영 대화는 미실행이다. `perkChoice:1`은 설정만 있으며 실제로 퍽을 지급하지 않았다. 첫 시도의 민지는 울산까지 동행하기로 한 임시 승객이므로 `party=[]`만으로 차량이 비었다고 판단하지 않았다.
