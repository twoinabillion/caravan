이번에 관측한 제작·수리·소유 요건에서 확정할 게임 오류는 없었다. 보고서의 긍정·취향 의견과 정책 실수는 아래에 따로 적었다. 다른 경로나 UI에 오류가 없다는 뜻은 아니다.

## 검토 범위

`review: { rowsReviewed: 422, choiceOccurrencesReviewed: 75 }`

검토한 시도는 `attempt01` 하나다. [trace](attempt01/player07-trace.json)의 1–422행을 순서대로 모두 읽었다. 각 선택은 전체 진입문, 전체 선택지와 요건, 선택 결과, origin, 전후 위치·시각·자원·동료와 바로 앞뒤 행을 확인했다. 도로·일손·캠프·저장 행도 포함했다. [review.cjs](review.cjs)가 범위를 빠짐없이 출력하며, 처음 출력이 잘린 18–50·128–130·182행은 다시 읽었다. 중복 읽기를 합계에 더하지 않았다. 읽기 출력만 소수 셋째 자리로 줄였고 원 trace는 원래 정밀도를 보존한다.

미지급 진입 재개 75회는 모두 로드 성공과 동일 상태를 확인했다. 지급 결과 재개 75회도 `loaded=true, replayed=true, applied=false`이고 전후 상태가 같았다. 마지막 결과의 유예 종료 후 summary가 본편 완료로 닫혔다. 이는 엔진과 격리 저장의 확인이며 실제 브라우저 Continue/새로고침 검증은 아니다.

## 발견 사항과 의견

확정 findings는 0건이다. 재현 가능한 관측, 반증한 의심, 의견, 정책·도구 한계는 [findings.json](findings.json)에 분리했다.

정비 일손으로 얻은 부품을 직접 장착과 제작에 쓴 뒤 가드의 효과를 확인하는 흐름은 잘 이어졌다. 동료 영입도 바로 보유 동료를 만드는 대신 임시 승객·일 처리·하룻밤·정식 합류로 이어졌고, 그 사이의 차량 개조는 보존됐다.

처음 만난 김 선장과 하 여사가 이음망을 이미 알려진 배경처럼 언급해 조직 이름을 따라가기 조금 어렵다(70·145행). 처음 듣는 이름이라는 상혁의 짧은 반응이 있으면 읽기 편하겠다. 그러나 그들이 화면 밖 연락으로 달구지 소문을 들었을 수 있고, 흰 X는 차량의 원래 표식이므로 서사 모순으로 올리지 않았다.

보급을 큰 목표량까지 사는 정책에서는 식량 1묶음마다 25분이 쌓여 밤을 넘겼다(106–122행). 여러 묶음의 총 소요시간을 미리 알면 계획하기 쉽겠다는 의견이다. 실제 UI의 반복 부담이나 인간 플레이 속도를 측정한 것은 아니다.

## 정책 실수와 한계

첫 플레이 전 이전 참가자 정책·보고·사건 결과 소스를 읽지 않았다. 새 독립 xorshift PRNG를 썼고, 매 선택에서 25%는 균등 분기, 나머지는 현재 선택지의 정비·부품·제작·기록 표현에 가중치를 줬다. 가능한 모든 선택의 가중치는 양수다. 실행 중 실제 호출은 75회, 균등18회(24%)·편향57회였다. 선택 index는 0/1/2/3에 각각52/19/3/1회 분포했고, 다중 선택 진입은51회였다. 단일 선택도 합계에 포함된다.

초기 포항·경주 재방문과 눈앞의 위험한 연료 기회 사양 때문에 도보 구조를 두 번 썼다(85–99행). 식량0까지 내려갔다가 대구에서 구매했다. 이것은 경로·자원 계획의 미숙함이며 게임 softlock이 아니다. 공개 예보가 부족하다고 막은 출발을 우회하지 않았다.

연료 목표65L는 탱크70L와 10L 묶음을 고려하지 못했다. 이 때문에 용량 초과 구매15회가 거절됐고, 다른 행동으로 상태가 바뀌면 다시 시도했다. 거절 때 자원과 시간이 변하지 않았고 다음 일손·이동이 가능했다. 정책의 반복 시도와 어댑터의 시장 enabled 투영 누락을 게임 오류로 세지 않았다.

개조6·제작3 제한 때문에 고급 선행 개조 사슬이나 좌석 확장·텃밭은 끝내지 않았다. 일반 현장 수리 대신 야영 수리1회만 했고, 동료 대화·게시판·라디오 수리는 거의 다루지 않았다. 단일 성공 seed가 모든 분기·균형을 대표하지 않는다.

## 도구 범위와 사후 확인

공식 감사 어댑터로 실제 소스 엔진을 Node VM에서 실행했다. 격리 메모리 저장과 유한 자원만 썼다. 화면·오디오·입력 타이밍은 stub이므로 UI 클릭, 시각·음성·네이티브 기기 QA로 주장하지 않는다. 사용자 Studio·미리보기 서버·사용자 저장은 조작하지 않았다.

첫 실행 종료 뒤에만 의심을 좁혀 소스를 읽었다. `src/03-data.js`의 차량 표식·두 거점 소개를 확인해 흰 X 의심을 철회했다. 127행의 `64.44140333333338/70` 용량 오류문은 엔진에서 반환되고 UI toast로 전달되는 코드가 있지만, 현 시장에는 disabled-row 제출 방지도 있다. 어댑터로 호출한 결과만으로 사람이 그 문구를 실제 화면에서 봤다고 말할 수 없어 UI 결함으로 올리지 않았다. 이 사후 소스 확인은 정책 수정이나 재시도에 사용하지 않았다.

생산 코드·기존 QA·다른 참가자 파일에는 쓰지 않았다. 본인 폴더의 정책·검토 스크립트·보고와 격리 `attempt01`만 만들었으며 재시도는 없다.
