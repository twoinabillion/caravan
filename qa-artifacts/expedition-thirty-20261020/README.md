## 무엇을 고칠지 판단하는 기록

[디렉터 판정과 최소 방향](director-rulings.md)을 우선 읽는다. [adjudications.json](adjudications.json)은 모든 원 후보의 개별 판정/중복 연결이다. 원 보고의 ‘버그’ 표현이 그대로 최종 확정 판정인 것은 아니다. 확정 오류, 문장 명료성 후보, 설계 검토와 미검증을 구분했다. 이번 요청에서는 생산 코드를 수정하지 않았다.

먼저 현재 상태 계약(E02 기아 해소 후 대기 위기, E07 수면의 각성 피로)을 고친다. 그다음 사건 자격(E03 내륙 염전, E04 서울 잔여 거리, E06 수면 중 도난의 주행 진입)과 선택 이력(E05 미만남 회상, E08 군번줄 반납 오판)을 맞춘다. 그 후 완료 알림/시각/출처/손상 인과 등의 낮은 강도 문구를 다듬는다. E01의 준비도 문제는 실제 UI가 아닌 API 라벨이므로 화면의 ‘준비됨’ 오표시로 소개하지 않는다. 우물의 강제 파괴는 별도 설계 판단이며, 무료 철수/가격·확률·난도 변경을 자동 적용하지 않는다.

단위 거래·연료 구제·같은 검문소/야영 문장 반복과 청주/수원의 기록 밀도는 여러 정책의 의견에 남았다. 과잉 비축·경로 실패라는 교란을 구분하고 실제 사람 플레이의 호흡/조작 부담을 확인하기 전에는 경제·발생 확률을 바꾸지 않는다. 선택한 작업과 거절·미완료 약속이 야영/결말까지 남는 체험은 보존할 장점이다.
