# player12 — 산길과 숨은 장소 탐방가

seed **207012**, 연료 준비, 새로 작성한 공개 관측 정책으로 **첫 시도에서 메인 엔딩 `story_done / core_sleep`에 도달했다.** 14일, 누적 713km다. 거창·단양·원주·대관령을 모두 방문했다. 확정할 게임 오류는 **0건**이다. 의견 3건과 기각한 의심 5건을 `findings.json`에 분리했다.

실제 사람이 화면을 보며 플레이한 결과가 아니다. 실제 소스 엔진을 격리 Node VM과 별도 저장소에서 실행했다. Studio, 사용자 브라우저·저장·서버, 생산 파일은 건드리지 않았다.

## 실행과 전수 검토

`attempt01`만 실행했다. 정책 수정·재시도·자원 지급·무한 모드·텔레포트·비가용 선택·출발 예보 우회는 없다. 첫 실행 전에 다른 플레이어의 정책·보고서·과거 QA 및 사건 결과 소스를 읽지 않았다. 첫 실행 후 의심을 판별할 때만 현재 본편 연결·능선 조건·화자 소스를 제한적으로 대조했다.

모든 **409행 / 94회 선택**을 `review.cjs`로 순서대로 출력해 읽었다. 범위는 1–45, 46–90, 91–135, 136–180, 181–225, 226–270, 271–315, 316–360, 361–409다. 각 범위 선택 수는 11·9·10·10·11·10·10·10·13이며 합계 94다. 진입 본문·모든 선택 라벨/비용/가용성·실제 결과·칩, 전후 장소/시간/자원/파티/아이템, 인접 이동/작업/야영/재로드를 포함했다. 콘솔에만 자원 소수점을 두 자리로 줄였고 원본 trace는 보존했다.

94회 미지급 진입 재로드와 94회 지급 결과 재로드가 모두 성공했다. 전체 관측 상태의 전후 차이와 중복 지급은 0건이다. 21회 출발은 모두 공개 `check.ok && forecast.ok && !forecast.shortage`를 통과했고, 숨김·비활성 선택을 고른 사례도 없다. 이 검사는 실제 화면이나 읽기 커서의 복원을 입증하지 않는다.

## 실제로 지나간 길

부산 → 양산 → 밀양 → 합천 → 거창 → 무주 → 영동 → 상주 → 문경 → 충주 → 단양 → 원주 → 대관령 → 원주 → 충주 → 단양 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울.

| 목표 | 첫 도착 | 근거 행 |
|---|---|---|
| 거창 | 2일 14:25, 127km | n66 |
| 단양 | 5일 12:39, 329km | n142 |
| 원주 | 6일 09:49, 359km | n163 |
| 대관령 | 7일 15:52, 403km | n191 |

거창 산지기 조우(n69)는 송전 통신탑 발견을 실제로 지급했다. 이후 n71 공개 관측에는 통신탑이 **11km·이동 가능·보급 부족 없음**으로 나타났다. 그러나 내 정책은 지정 정류장까지의 거리만 우선해 무주로 갔다. 숨은 경로가 안 열린 것이 아니라 열린 길을 놓친 것이다. 구조줄 획득·사용, 통신탑 내부, 남산 능선길은 검증하지 못했다. 첫 성공 뒤 추가 시도를 만들어 커버리지를 채우지 않았다.

원주의 낮은 목소리 장면(n165), 대관령 위령비(n193)는 실제 도착한 장소와 맞았다. 이름을 이어 읽는 위령비 결과는 이송표의 숫자와 좋은 대비를 이뤘다. 이는 이 정책 실행을 읽으며 남긴 의견이며 사람 대상 감상 조사 결과는 아니다.

## 오류로 세지 않은 부분

유령을 만나지 않았는데 최종 회의에 나타난 것처럼 처음에는 읽혔다. 하지만 n358이 유령 통신원에게 직접 역할을 요청하고 수락을 받는 실제 연결 장면이다. 결과에도 세 조직의 이름이 나왔다. 사후 소스의 무전 화자와 `D.coreLinkedCells`도 이를 뒷받침한다. 관측이 턴의 텍스트만 합치면서 무전 화자 이름을 생략하는 한계가 있었다.

산지기 첫 조우는 능선길 작업 완료가 아니다. 남산에서 `능선 길로 오른다`가 숨겨졌지만, 나는 통신탑 방문·별도 길 습득을 하지 않았다. 아침에 열린 들개와 탐조등 사건도 `origin:memory / 지난밤`이 명시돼 시간 모순으로 세지 않았다. 솔로 격리 수면 결과의 “제가 설명할게요” 역시 부재 동료가 아닌 플레이어 발화였다.

연료 구조는 총 **13회**였다. n224는 물/식량 1/1에서, n245는 0/0에서 ‘물 3·식량 3’ 도보 구조가 가능했다. 실제 칩은 잔여량만 차감해 상태와 맞았다. 생존 탈출구의 하한 처리를 일반 구매 게이트와 같게 취급하지 않았다. 다만 힌트가 `최대 3` 또는 `남은 보급 소진`으로 읽히면 더 명확하겠다는 의견을 남겼다.

## 정책과 도구의 한계

엔진과 별개 LCG를 사용했다. 선택마다 25% 확률은 활성·표시 선택지를 균등 추출하고 나머지는 현재 라벨·힌트의 산길·지도·단서·조사·구조 표현에 가중치를 주었다. 모든 후보 가중치는 양수다. 같은 프로세스에서 남긴 실행 증거는 PRNG 214회, 선택 94회(균등 분기 20회, 성향 분기 74회), 길 위 결정 72회다. 선택 인덱스도 0/1/2/3/4에서 각각 52/30/6/5/1회 나왔다.

공개된 단일 이동 예보를 통과하는 것만으로 후속 사건과 긴 왕복의 보급이 확보되지는 않는다. 내 정책은 장기 공급망보다 목표 정류장과 탐색을 앞세웠다. 식량이 떨어진 뒤에도 도보 구조를 고르고, 휴식 대안을 충분히 찾지 못해 굶주림·탈진이 이어졌다. 수원에서는 음식 목표를 먼저 채우다 연료 구매용 고철까지 소진했다. 반복 구조가 느리게 느껴진다는 의견은 남겼지만 이를 게임 소프트록이나 밸런스 오류로 판정하지 않았다.

끝까지 `party=[]`였고 영입·제작·개조는 실행하지 않았다. 동료 인과, 구조줄 소모, 제작 재료, 실제 개조 가격에 관한 결론은 없다. 표시·입력·화면 배치·모바일 접근성·이미지 크롭·애니메이션·음성·오디오는 검사 범위 밖이다. 후일담의 미래 시각을 고정된 엔진 시계와 단순 비교하지 않았다.
