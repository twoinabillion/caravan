# player04 — 손익 계산형 상인

seed 207004, 연료 준비. 첫 실행 `attempt01`에서 무주·전주·군산을 모두 방문하고 6일차 21:17, 583km에 본편 `story_done / core_transfer` 엔딩에 도달했다. 실패·재시도는 없었다. 이번 범위에서 확정한 게임 오류는 0건이다.

276개 trace행과 60개 선택의 본문·전체 선택지·결과, 전후 시간/자원/인원, 인접 이동·현장 일·야영·리로드를 전부 읽었다. `review.cjs`의 연속 구간과 재열람 기록은 [evidence.json](evidence.json)에 있다. 읽기용 숫자만 소수 셋째 자리로 표시했으며 원본은 수정하지 않았다.

연료 10L 구매 11회는 총 110L/고철78이었다. 매번 공개 가격·묶음과 실제 증감이 맞았다. 전주 비빔밥은 고철4/식량1(n109), 군산 빵은 고철3/식량2(n119)로 맞았다. 밀양 부품 분류·펌프 도움의 추가 고철14도 결과 칩과 일치했다(n49–50). 선택 전 reload60회와 기지급 결과 reload60회는 관측 snapshot을 바꾸지 않았고, 기지급 효과를 재적용하지 않았다. 출발 16회는 모두 공개 예보에서 부족 없음이었다. [verify.cjs](verify.cjs)의 읽기 전용 검증을 통과했다.

영동에서 와인 한 병을 얻는 이야기의 결과는 고철+3만 남아, 이야기 속 물건과 보너스 사이가 조금 떨어져 느껴졌다(n149–151). 물건을 일반 자원으로 추상화한 의도일 수 있어 취향·명료성 의견으로만 남겼다. 남산행 편지는 마지막 결과에서 미배달 약속으로 명시돼 완료 오류로 보지 않았다(n275).

무주의 물물교환은 어댑터에 `qty:0 / price:1`로 나왔다(n86). label은 실제 교환 내용을 설명한다. 이를 게임의 고철 청구 오류로 단정하지 않았으며, 어댑터에 교환 투입/산출을 따로 담는 방향을 제안했다. 공개 관측에는 저장 상한/묶음 수용 여부가 없어 용량 경계 계획도 제한된다.

독립 PRNG의 선택 확률은 25% 균등 탐색과 75% 손익 가중치였다. 실제 60회는 균등20/가중40이고 선택 index는 0/1/2/3/4에 각각 41/11/6/1/1회 분포했다. 가능한 모든 선택지에 양수 확률을 줬다. 같은 프로세스 실행 후 카운터는 [adapter-policy-evidence.json](attempt01/adapter-policy-evidence.json)에 보존됐다. 기존 player 정책·결과와 미관측 event outcome을 읽지 않고 정책을 작성했다. 다만 관측 스키마 확인을 위해 읽은 runner 구간에 내장 generic `defaultDecision` 코드도 함께 노출됐다. 새 `choose/decide`를 직접 작성·사용했으며 기본 정책을 호출하지 않았다.

이번에는 끝까지 동료 없는 여정이었고 자원이 넉넉했다. 시장 구매가 연료에 집중돼 물/식량 묶음, 용량 상한, 무료 구매, 지불·기부 부족 경계와 퀘스트 보너스는 실행하지 못했다. 엔딩 도달을 위해 결과별 quota, 강제 지급, 순간이동, 비가용 선택이나 공개 부족 예보 우회는 사용하지 않았다.

실행은 격리된 실제 엔진 API 감사다. Studio·사용자 저장·브라우저를 조작하지 않았고 화면·음성·터치·실제 인간 플레이 QA를 뜻하지 않는다. 최종 상태는 지연 종료가 반영된 summary/save로 확인했다.

상세 분류와 기각한 의심은 [findings.json](findings.json), 원본은 [trace](attempt01/player04-trace.json)와 [summary](attempt01/player04-summary.json)에 있다.
