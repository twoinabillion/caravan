## 실제 Studio 상태와 남은 검수

지정된 4327/4319의 read-only GET만 사용했다. 새 서버·탭·저장·배지 클릭·강제 새로고침은 하지 않았다.

- [최초](live-before.json) 07:39:25Z: title/game:null·360×728/DPR2·loaded/style1792464616916·pendingnull.
- 사용자 ‘계속 수정’ 후 [재확인](live-resume.json) 08:43:22Z: 같은 title/game:null·viewport, loaded/style1792485720870·pendingnull. 이때 집중 검사는 아직 red였으므로 revision 증가를 이번 수선 완료로 해석하지 않았다.
- [수정 후](live-after.json) 08:55:42Z: title/game:null·viewport·loaded/style1792485720870 동일, **pending1792486398018**, applyingfalse. 이번 JS/데이터는 **‘새 코드 준비됨’ 배지 적용 대기**다. CSS live 적용과 혼동하지 않는다.
- 접근 가능한 CUA 목록에서 현재 Studio 창을 확인하지 못했다. 과거 문맥만으로 Safari 전체를 읽는 요청은 다른 개인 탭 노출 위험 때문에 auto-review가 차단했다. 우회하지 않았으며, 현재 Studio의 정확한 앱/창 이름과 그 창 한정 접근을 사용자에게 비동기로 요청했다. 따라서 이번 영향 장면의 실제 시각·입력·음성·브라우저 refresh 검수는 미완료다. 텍스트 상태 GET/소스 projection을 시각 증거로 대체하지 않았다.
