자연실행 5곳은 선택 전 load와 지급 후 load/replay를 모두 통과했다. 결과가 두 번 지급되지 않았으며 다음 출발이 가능했다. 추가 격리 fixture 14개는 5곳의 모든 선택 10개, 야간 대조 3개, 매화 교환 고철0 경계 1개다. 14개 모두 결과 재지급 없이 재개하고 다음 공개 도로로 출발했다.

확인한 수정 후보는 다음과 같다.

- P2: 매화마을 항아리 교환은 고철0에서도 허용된다. 식량20→21, 고철0→0인데 결과는 고철을 냈다고 말한다. 고철10 대조는 정상적으로3을 차감했다.
- P2: 온천은 자연실행07:54→11:54인데 밤하늘을, 등대는11:09→19:09인데 다음 아침의 미역국을 서술한다. 호수 낚시도09:00→17:00 fixture에서 달빛·밤새·다음 아침을 말한다.
- P3 명료성: 혼자 온천에 간 상태인데 소개되지 않은 상대와 긴 수다를 나눈다. 익명의 목욕객으로 해석할 여지는 있어 확정 동료 버그로 분류하지 않았다.

온천 목욕으로 피로가 증가하는 것도 확인했지만 root의 기존 A01 회복 계열과 중복 판단 대상으로 넘겼다. 호수 낚시와 등대 당번을 수면이라고 단정해 피로 자체를 오류로 세지는 않았다.

기존 harness에는 NPC 소문 동작이 없었다. 이번에는 생산 코드 `src/07-ui.js`의 `talk(nid)` 함수를 그대로 추출해 격리 VM에서 실제 공개 소문/감사 버튼 callback을 호출했다. 원함수 SHA256은 `12bd14fc9af6c254870c2f9be19f08b1ab902dd1524efd2982238ff796093de1`이다. 미발견 장소를 직접 주입하지 않고 각 소문 뒤 known 변화도 남겼다. 이전의 미방문을 게임의 접근 불가능으로 판단할 수 없다.

첫 시도는 감사 정책의 동수 ID 오타 때문에 등대만 놓쳤다. 당시 로그와 정책을 보존했고 두 번째 시도에서 수정했다. 이는 게임 오류가 아니다. `targeted-complete`는 감사 정책의 한정 종료 상태이며 엔딩이나 모든 기능 검증을 뜻하지 않는다.

자세한 분류·재현·한계는 [report.json](report.json), 간추린 원시 증거는 [evidence.json](evidence.json), 전체 자연실행은 [attempt02/agent02-trace.json](attempt02/agent02-trace.json), 격리 검사는 [fixture-results.json](fixture-results.json)에 있다. 자연실행은 소스/과거 정책을 읽고 목표를 정한 플레이이며 블라인드 검사는 아니다.

실제 사용자 Studio, 생산 소스, 기존 QA, 생성 HTML, 저장과 서버는 변경하지 않았다. 화면/모바일/음성/실제 버튼 입력은 검수하지 않았다. NPC 감사 후 돌아가기와 엔진 결과 종료는 실행했지만 브라우저의 취소·Escape·backdrop 입력은 미검증이다.
