# agent08 · 사이드 미션 경계 감사

확정 게임 오류는 **0건**이다. 명료성 후보 1건과 legacy/malformed 저장 방어 후보 1건을 분리했다. 생산 수정은 하지 않았다.

[최종 실행](raw-attempt02.json)은 실제 엔진과 추출한 현행 게시판 callback으로 46개 관측·21개 검사를 통과했다. [보고서](report.json)에 재현, 비용, 출처, 미검증 범위를 기록했다.

- 정상 미종료 저장을 재개한 대구 조달: 게시판 수락→기존 부품17→15 인계→고철0→24(기본20+빠른처리4)→공책/저장 재개→중복 인계 false→식량 구매까지 확인했다. 식량은 고철1/25분으로 실제1묶음 늘었다. 같은 장소에서 기존 물품을 건넸으므로 먼 지역을 다녀온 조달 완주로 세지 않았다.
- 획득 fixture: 부품0/2는 인계 불가, 구매2회에 고철20/50분, 이후 정확히2개 소모·20 지급·완료 재개. 순이익0은 가격/보상과 맞아 오류로 보지 않았다.
- 마감 fixture: 마지막 날 즉시 인계는 성공하고, 실제 `advance(2)`로 자정을 넘기면 실패·보상0·재개 후 실패 유지. 다만 dawn을 건너뛴 **인위적인 만료 활성 저장**은 공책 실패 안내와 달리 게시판에서 인계·지급된다. 정상 생성 경로가 입증되지 않았으므로 확정 오류가 아닌 방어 정책 후보로 남겼다.
- 지역 후속 fixture: 기한 없음은 오래된 due값을 넘겨도 유지됐다. 다음 요청을 맡기 전 닫기/재개, 다른 지역, 원래 지역 재방문, 같은 후속 수락과 경로 안내까지 확인했다. 장소 이동은 주입했으므로 실제 여행은 검증하지 않았다.

진행 중 공책 카드에는 보상이 없지만 활성 게시판 row에는 `D-6 · 고철20`이 남는다. 이미 알려진 약속 금액을 보여주는 예외인지 정할 명료성 후보이며, 지급액은 정확하다. 포기 API/버튼은 찾지 못해 포기·재수락 기능을 임의로 만들지 않았다.

첫 실행은 보존 저장의 허기 사건에서 탐색을 골라180분이 지났고 이후 조달 게시가 없었다. 감사 코드가 없는 제안을 JSON으로 읽어 중단한 [실패 원본](raw-attempt01.json)을 남겼다. 두 번째 독립 재개는 허기 사건의 다른 공개 선택을 사용했다. 무한 시도하지 않았다.

이전 `ten-persona-repairs` T06과 회귀 검사는 보너스 영수증/기본 중복 지급을 이미 다뤘고, `expedition` player02는 지역3단계 완료, player23은 조달·만료 미실행이었다. 새 검사는 이 범위를 읽은 뒤 조달 획득/만료/후속 보류로 한정했다. `setup.cjs`의 오프닝 완료 설정과 UI 대역을 사용하되 정상 저장 재개와 인위적 fixture를 구분했다.

브라우저 클릭, 실제 Studio 저장/화면, 모바일, 시각·음성 검수는 아니다. 모든 결과는 자기 폴더에만 썼다. 재실행은 기존 기록을 덮어쓰지 않도록 새 파일명을 전달한다.
