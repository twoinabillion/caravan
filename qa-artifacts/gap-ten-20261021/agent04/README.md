# agent04 — 민규의 능선·재이의 창고

확정 게임 오류는 0건이다. 민규의 능선은 이전 정상 저장에서 이어 실제 발견·이동·대화·완료·복귀했다. 재이의 창고는 정상 실행에서 해제하지 못했고, 조건을 명시한 fixture로 성공·동료 부재·저장 재개·완료 기억을 확인했다. 생산 소스와 실제 Studio는 건드리지 않았다.

## 정상 저장 재개

출처는 `../agent01/attempt04/decision-64-save.json`이다. 계보는 [agent01 README](../agent01/README.md)에 남아 있다. agent01 새게임→정상 재개에서 민지·강우·재이 3명 영입→DAY16 서울 결정을 앞둔 저장이며 자원/동료 주입은 없다. 이번 `attempt01`은 그 저장의 재개이며 새게임으로 세지 않는다. 읽은 이전 정책과 agent01의 출력 경로 격리 harness를 사용했다.

[원시 trace](attempt01/agent04-trace.json)의 n7에서 `talk_mj_21` 결과로 `mj_radio`를 자동 획득했다. n133 실제 능선 도착, n134 미정산 재로드, n135 `…기다린다` 선택, n136 정산 재로드에서 `applied:false`, n137–138 영동 복귀를 확인했다. 최종 저장의 `mingyu_reunion`과 「남매, 능선에서」 기록도 남았다.

재이는 bond28이지만 개인 이야기 stage2로 `jy_story`를 얻지 못했다. 정책은 식량을 회복하지 못하고 DAY21 영동에서 정체했다. 이 실패와 불필요한 왕복도 원시에 남겼다. 미도달을 불가능이나 게임 오류로 해석하지 않는다.

## 분리한 fixture

[fixtures01.json](fixtures01.json)은 18개 명시 fixture, [fixtures02.json](fixtures02.json)은 김천 분기 과거를 추가한 18개 재실행이다. setup부터 opening 완료·인접 위치·유한 자원·로스터·레벨/유대/대화 이력을 주입했다. 부재 검사는 동료 제거/복원도 주입했다. 자연 영입·발견으로 세지 않는다.

- 각 시그니처는 lvl2에서 bond14와 개인 이야기 stage3가 함께 있어야 해제됐다. bond13 또는 stage0/2에서는 미해제였다. 두 장소는 일반 숨은 장소 추첨에서 제외된다.
- 동료 없이 먼저 도착하면 해당 사건을 소비하지 않았다. 동료 복원 후 재방문하면 두 사건 모두 정상 열렸다.
- 미정산 저장은 같은 사건/본문과 게임 상태를 복원했다. 결과 재생은 효과를 다시 주지 않았다. 완료 후 인접지로 돌아가 재방문해도 같은 사건을 반복하지 않았다.
- 재이 완료 기억은 전용 `jaeyi_cache_opened` 또는 정확한 옛 완료 기록만 인정했다. `used`, 넓은 `jy_law`, 같은 제목의 다른 기록은 충분하지 않았다.

첫 fixture의 창고 재방문 실패 2건은 김천 첫 분기에서 선택한 노선 잠금이었다. 청주까지 선택 노선을 완료해야 한다는 정상 안내와 일치했다. 원본은 보존하고, 두 번째 fixture에만 `route_mid_fork` used 이력을 주입해 나머지 경계를 격리했다. 미정산 전체 문자열의 차이는 로더의 `view/reading:null` 정규화이며 실제 게임 상태는 같았다.

두 현장 사건은 진행 선택이 1개이며 별도 거절/취소는 없다. 엔진 결과 계속읽기·복귀를 확인했으나 브라우저 Back/Escape·실제 화면·감속 연출·모바일·음성은 확인하지 않았다.

전체 조건/한계와 출처는 [report.json](report.json), 주요 원시는 [target-excerpt.json](target-excerpt.json), 검증 및 원본 저장 SHA-256은 [verification.json](verification.json)에 있다. `verify.cjs`는 남긴 원시 로그를 확인한다. 산출물은 덮어쓰기를 거부하므로 재실행에는 새 출력 이름을 사용해야 한다.
