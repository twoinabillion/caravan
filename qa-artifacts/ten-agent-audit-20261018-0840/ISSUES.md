## 취향·설명력 의견 — 자동 수정하지 말 것

- 02·07: 구조의 ‘교전/전세/전술’ 용어. 구조 성공·비용은 맞지만 전투 어휘가 튄다는 의견.
- 02: 구조한 여성이 남쪽 정착지까지 태워 달라고 한 뒤 하차가 생략됨. 승객 상태 소실로 확정하지 않음.
- 04·06: 마지막에 알게 되는 인원/거점 조건, 상세 질문 하나 뒤 결정으로 넘어가는 호흡. 준비 복귀와 기본 설명은 실제 존재.
- 05: 강우가 있는데 ‘동료들을 돌아본다’는 민지가 필요하고 ‘혼자라도 오른다’만 열리는 명칭.
- 05: 자물쇠를 부술 쇠파이프 출처가 없는데 다른 장면은 가방 도구를 요구함. 현장 도구 생략 가능성은 남음.
- 08: 한강 접근→관문→도하가 여러 번 건너는 듯 읽힘. 도하 시작/끝으로 읽을 수도 있음.
- 09: 말없이 반창고를 붙이는 돌봄 외 동의 중심 반응 부족. 둘 사이 농담으로 읽을 여지도 있음.
- 10: 발표 연습 영상 복원을 공책은 ‘발표 원고’라 부르는 출처 표현.
- 03: 우회 비용을 더 비교하고 싶다는 의견. 일부 비용 관찰 누락 때문에 실제 UI 결함으로 확정하지 않음.

## 오탐·한계로 분리

1. 후일담에는 실제 epilogue 시간/장소 표식이 있다. VM의 합본 글에서 생략된 것을 순간이동/시계 고장으로 세지 않는다.
2. raw 목표 why의 선행 정답은 실제 공책이 지우고 질문형으로 바꾼다. root 투영에서도 확인, 실제 공책 스포일러에서 제외했다.
3. 빈 hint는 실제 UI의 reqCostText가 관찰 API에 전부 전달되지 않은 경우가 있다. 실제 비용 미표시로 단정하지 않는다.
4. 03의 준비 복귀 반복,05·06의 탐색 제한 왕복은 자동 정책 오류다. 원 실패와 최소 정책 보정 재시도를 보존했다.
5. 마지막 trace의 ended=false만으로 미완주라 하면 오탐이다. 결과 기록 뒤 Continue가 종결하므로 최종 저장의 ended/endKind/story_done으로 확인했다. 집계기의 최초 가정 오류를 고쳤고 게임 결함으로 세지 않았다.

다음 구현을 한다면 A01 도착/위치 처리부터, 이어 선택·인물·소유·시간·목표 연결을
작게 재현하는 순서를 제안한다. 대사를 대량 추가하거나 엔딩/자원 규칙을 일괄
변경할 근거는 아니다. 이번 세션에서는 어느 항목도 게임에 적용하지 않았다.
