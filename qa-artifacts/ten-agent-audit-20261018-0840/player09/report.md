# player09 — 비폭력·동의 중시형

첫 시도에서 본편을 끝냈다. `story_done`, 집행권 저항 연대망 인계(`core_transfer`)다. seed `181309`, 준비물 `provisions`. 6일째 21:47, 누적 530km, 동료는 민지와 강우였다. 실패·막힘·예외·재시도는 없었다. 원래 시도를 보존했으며 게임 코드나 사용자 저장은 바꾸지 않았다.

이 결과는 공유 실행기로 실제 게임 소스를 구동한 격리 Node VM 플레이다. 각자 다른 실제 엔진 구현이나 브라우저/사람 플레이가 아니다. 정책은 실행 전에 작성했고 관측된 본문·label·hint·공개 조건·자원·목표·예보만 받았다. 미래 결과·확률·효과를 선택 전에 조회하지 않았고, 자원·인물·플래그·난수를 주입하지 않았다.

## 여정과 선택

부산 → 양산 → 밀양 → 양산 → 울산 → 경주 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울. 밀양의 민지를 울산까지 태워 진단기를 구하고 경주에서 정식 합류했다. 대구에서 강우의 후임과 감시 표식 문제를 해결하고 구미에서 정식 합류했다. 김천에서는 동쪽 능선길을 택했다. 상주에서는 역할 분담 → 발판 조성 → 사람 줄과 수레 줄을 나누는 구조로 네 사람과 해열제를 모두 올렸다. 회수조 앞에서는 여자 옆에 섰고, 강제 귀환 대신 함께 떠났다.

실제 행동은 거래 9회, 노동 2회, 탐색 16회, 야영 5회, 이동 16회, 동료 대화 7회였다. 밀양의 공동 펌프 일을 하고 실제 얻은 고철로 연료를 샀다. 별도 야전 수리는 필요하지 않았으며 야영과 민지의 획득한 정비 능력으로 차체를 회복했다. 마지막 자원은 연료 42.77, 물 17, 식량 12, 고철 12, 차체 100%, 피로 55.61이었다. 보급 부족이나 이동 불가 상태는 겪지 않았다.

최종부에서는 강우의 보존 반대, 인계의 합의 갈등, 수면의 기록 조회 중단, 보존의 매일 세 사람 감시 부담을 읽었다. 기록 조회 창구를 확인하고 연대망 인계를 골랐다. 보존은 근무 인원 2/3으로 막혀 있었다. 결과는 실제 거점들의 수락, 설비 유지, 도로/물차 우선순위를 둘러싼 합의 갈등이었다. 마지막에는 하진이 귀환 여부를 스스로 결정하도록 답하고 엄마의 중계소로 돌아가는 후일담까지 읽었다.

성향 구현에는 한계가 있다. 정책은 label 어휘 점수와 첫 선택 동률 규칙이다. 최종 인계와 수면은 둘 다 0점이어서 인계가 선택됐다. 이를 실시간으로 깊은 윤리 판단을 내린 사람의 선택으로 포장하지 않는다. 허락을 구하는 표현을 놓치거나 호스 수리의 ‘우회’를 충돌 회피로 잘못 가중한 경우도 있었다. 자세한 실제 이유는 `attempt01/choice-reasons.json`에 남았다. 성공 뒤 정책을 고쳐 더 마음에 드는 여정을 만들지는 않았다.

## 확인한 문제

1. `gp_note2`, trace 98: 대구에서 야영을 마친 정차 상태인데 결과는 긴 내리막을 달려 평지에 닿았다고 한다. 위치·시간·거리·driving은 전부 그대로다. 해당 사건에 기억/후일담 표식도 없다. 현재 장면과 완료한 행동이 어긋난다. 중간 심각도, 높은 확신.

2. `talk_kw_01`, trace 114 / `talkr_mj_3`, trace 178: 각각 20분 침묵과 5분 휴식을 마쳤다고 쓰지만 호출과 결과 모두 시계는 0분 경과다. 분 단위 시계와 서술의 차이는 확정된다. 무료 동료 대화의 의도적인 시간 추상화일 수 있어 낮은 심각도로 기록했으며 시간 게이트나 악용 문제로 확대하지 않았다.

3. `perimeter_first`, trace 166: 경고탄은 차 옆 아스팔트를 때리고 보행기는 길을 비키지만 결과에서 차체가 6% 줄어든다. 맞거나 부딪힌 대목이 없다. 감소량 칩 자체는 정확하다. 수치 오류가 아니라 손상 원인이 본문에 연결되지 않은 문제다. 중간 심각도, 높은 확신.

4. `talk_mj_03`, trace 145: 상처를 발견한 뒤 선택은 말없이 반창고를 붙이거나 “아프지도 않냐”뿐이다. 첫 선택의 주인공은 “말하면 손 뺐을 거잖아”라고 답한다. 동의를 먼저 묻는 돌봄을 표현하기 어려웠다. 두 사람 사이의 농담으로도 읽히므로 주관적 성향 마찰로만 기록했다.

문제별 원문, 실제 상태, 기대/관측, 영향, 확신도와 분류는 `findings.json`에 있다. 진행 차단이나 엔딩 도달 실패는 관측하지 않았다.

## 검토 범위와 재접속

76개 choice 전부의 진입 본문, 모든 공개 선택(비활성 조건 포함), 고른 결과, 결과 칩, 전후 시간·장소·이동·동료·보유물·자원·목표를 순서대로 읽었다. 범위는 trace 2–256이다. 그 사이 105개 비선택 동작도 전부 읽어 노동·거래·야영·임시 동행/정식 합류·이동의 연결을 확인했다. `review.cjs 1 76`으로 같은 전편을 다시 출력할 수 있다.

선택마다 격리 저장/로드 후 지급 결과를 재조회했다. 총 76회 모두 `loaded:true`, `replayed:true`, `applied:false`였고 snapshot 전후가 정확히 같았다. 이는 효과 재지급 방지의 엔진 증거다. 실제 브라우저 새로고침, 읽기 커서, 포커스, 열려 있던 도구 복원은 검사하지 않았다.

후일담의 `timeKind:'epilogue'` 표식과 ‘다음 날 새벽’/‘그 뒤, 수원 외곽 중계소’를 확인했다. 그래서 끝난 저장이 서울 6일째 21:47에 남아 있는데 후일담은 새벽과 수원 귀환을 말하는 점을 버그로 세지 않았다. 원시 `main.why`는 공책 표시에서 변환될 수 있어 원시 목표 문구만으로 선행 스포일러라고 단정하지 않았다. 실행기는 실제 UI의 `reqCostText` 전체를 관측에 싣지 않으므로 빈 hint를 비용 미표시의 증거로 쓰지 않았다.

화면·그림 crop·입력·애니메이션·음성은 보지 않았다. 실제 Studio, 탭, 서버, 사용자 저장에 접근하지 않았고 다른 감사 보고를 읽지 않았다. 전편 검토 뒤에는 해당 관측의 시간 표식을 좁게 확인했으며 소스 전체 감사로 넓히지 않았다.
