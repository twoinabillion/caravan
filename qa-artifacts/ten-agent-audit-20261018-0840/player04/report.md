# Player 04 — 성급한 직행형

첫 시도에서 본편을 완료했다. `story_done`, 최종 방식은 집행권을 저항 연대망에 넘기는 `core_transfer`다. DAY 4 07:13, 430km, 동료 0명으로 종결했다. 실패 시도나 재시도는 없다.

## 실행 범위

`policy.cjs`를 먼저 작성한 뒤 공유 `../harness.cjs`의 `run(config, 'attempt01')`로 실제 소스 엔진을 격리 실행했다. seed는 `181304`, 준비 꾸러미는 `fuel`이다. 기존 정책은 불러오지 않았고, 다른 플레이어 및 과거 보고서는 읽지 않았다.

정책은 공개 본문·선택 문구·조건·자원·메인 목표·경로 예보만 받는다. 짧은 직접 확인, 진행, 주목적지 최단 경로를 우선하고 대기·왕복·추가 의뢰·전투를 낮게 평가했다. 선택 전 점수와 이유 57건, 일상 행동 이유 26건을 `attempt01/decision-reasons.json`에 남겼다. 결과와 효과는 정책 입력으로 전달받지 않았다.

src/assets/tools/docs와 기존 QA, 실제 Studio 저장은 수정하지 않았다. 생성한 파일은 이 `player04/` 아래뿐이다. 브라우저/인간 플레이가 아닌 Node VM 실행이다.

## 여정

부산 → 양산 → 밀양 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울.

김천에서는 짧은 동쪽 능선길을 골랐다. 지나가는 사람들의 추가 일은 피했고, 메인 목표가 현재 장소를 가리키면 주변을 탐색했다. 결과적으로 역주행 없이 13구간을 이동했다.

178개 trace 중 공개 선택 57회, 실제 이동 시작 13회, 주행 묶음 32회, 탐색 9회, 거래 3회, 서울 진입 단계 5회가 있다. 거래로 대구에서 연료 10L, 수원에서 연료 10L와 물 5통을 샀다. 현지 노동·직접 야영·현장 수리·동료 영입은 실행하지 않았다. 졸음 장면의 실제 2시간 수면 3회와 피로 한계의 4시간 휴식 1회를 거쳤다.

연료는 두 번 바닥났다. 첫 구간에서는 7시간 걸어 연료를 구했고, 두 번째는 9시간 걸었다. 천안 출발 전 예보는 이미 `연료 4L 부족 · 피로 누적`, 평택 출발 전에도 같은 경고였다. 이 결과는 경고를 무시하고 직행한 정책의 선택으로 분류했다. 게임의 무경고 연료 소실이나 진행 불능으로 보고하지 않는다.

종결 상태는 연료 약 9.58L, 물 6, 식량 0, 고철 0, 차체 약 74.44, 피로 약 80.68이다. 이 수치는 엔진이 보관하는 현재 시각/장소이며 에필로그의 서사 시각을 뜻하지 않는다.

## 관측한 문제

1. **P04-01, 확정된 설명 누락 / 중간** — `perimeter_first`, trace 79. 경고탄은 차 옆 아스팔트에 맞았고 유일한 선택은 통과인데 차체가 80.44에서 74.44로 감소했다. 영수증도 `차체 -6%`다. 명중·충돌·작업 손상이 서술되지 않아 왜 차가 상했는지 알기 어렵다. 손실 계산 자체의 오류로 단정하지 않았다.
2. **P04-02, 확정된 안내·본문 불일치 / 낮음** — `seoul_ruins`, trace 155·158·161. 메인 안내는 막힌 길을 열라고 하지만 장면은 신호가 속도에 맞춰 전부 초록으로 바뀌고 한 번도 멈추지 않고 통과했다고 한다. 실제 선택은 질문 하나다. 원시 목표를 화면으로 오인하지 않도록 `QuestJournal.entry`의 해당 분기만 확인했고, 변환 뒤 문구도 `여긴 길이 막혔네`였다. 실제 화면은 보지 않았다.
3. **P04-03, 확정된 장 번호 불일치 / 낮음** — `parents_mother_truth`, trace 122·142·145. 목표는 앞으로 전진하는데 장 번호와 저장된 갱신 제목은 `5장 엄마 → 4장 거점 응답 → 5장 서울`로 움직인다. 실제 진행 퇴행은 없다. 현재 목표 카드의 화면 표시가 아니라 저장된 장/갱신 데이터 문제로 범위를 한정했다.
4. **P04-04, 직행 성향의 주관적 불편 / 낮음** — `seoul_decision`, trace 169·171. 54번째 선택에 와서 격리 수면은 열쇠 상대 3/4, 보존은 근무 인원 0/3임을 확인했다. 동료 없는 직행에서는 인계만 가능했다. 수원 준비 복귀가 있고 인계로 완주했으므로 막힘은 아니다. 준비 거점을 떠나기 전에 결말별 인원 조건을 알면 왕복 부담을 예상하기 쉽겠다. 다른 UI의 사전 정보는 보지 않아 보편적 누락으로 단정하지 않는다.

각 항목의 원문, 실제 전후 상태, 기대, 영향, 확신도는 `findings.json`에 있다. 게임 수정은 하지 않았다.

## 전편 검토와 재접속

종결 뒤 trace 1–178을 순서대로 읽었다. 57개 선택의 진입 원문, 전체 공개 선택지/비활성 조건, 실제 선택, 결과 원문, 전후 시간·장소·이동 상태·명단·자원·아이템·목표를 끝까지 대조했다. 목표의 전체 변화도 별도로 읽어, 현재 목표와 이미 마친 사건을 구분했다. 첫 진입부터 `seoul_session_reset`의 SESSION 1 END까지 검토했다. 정규식으로 후보만 추린 뒤 결론내린 보고가 아니다.

57개 유료/확정 결과 모두 저장 후 `G.load`로 불러온 뒤 같은 결과를 재요청했다. 57/57에서 loaded/replayed=true, applied=false였고 전후 snapshot이 같았다. 추가로 밀양 trace 28에서 일반 저장/재접속을 1회 실행했으며 상태가 같고 다음 이동이 이어졌다. 이는 격리된 엔진 저장 검수이며 Studio 새로고침·읽기 위치·포커스 검수는 아니다.

## 한계와 제외한 가설

- 공유 실행기는 하나이며 이 정책만 독립적이다. UI·그림·음성·실시간 연출·브라우저 입력·모바일 크롭은 미검수다.
- 실행기는 서울의 다음 진입 단계를 자동 호출하고, 실시간 대기와 결과 읽기/닫기를 추상화한다. 실제 화면에서 다음 버튼을 찾기 쉬운지는 판단할 수 없다.
- `main.why` 원문만으로 내용 노출이나 UI 버그를 판정하지 않았다. `QuestJournal.entry`가 목표 문구를 바꾸므로 P04-02만 해당 변환 분기와 대조했다. 장 번호는 저장된 갱신 데이터에 한정했다.
- `seoul_night`의 밤·새벽과 종결 뒤 수원 복귀를 현재 엔진 시각/장소와 대조해 시간·순간이동 버그로 세지 않았다. 실행기에는 에필로그의 `timeKind` 표시가 빠진다.
- 동료가 없다는 이유만으로 일반적인 ‘우리’ 표현을 동료 출현 버그로 세지 않았다. 실제 동료 행동이 없는 대목은 모순으로 확정하지 않았다.
- 막힘, 선택 효과 중복 적용, 실제 저장 손실, 게임 오류 예외는 이 여정에서 관측하지 않았다. 안 본 분기와 다른 준비 성향에 대해서는 결론내리지 않는다.

## 파일

- `policy.cjs`: 실행 전 확정한 독립 성향과 공개 정보 정책.
- `attempt01/player04-trace.json`: 전체 진입·선택·결과·전후 상태.
- `attempt01/decision-reasons.json`: 모든 정책 선택 및 일상 행동의 이유.
- `attempt01/player04-summary.json`, `attempt01/player04-save.json`: 종결 요약과 격리 저장.
- `read-trace.cjs`: 원문을 줄이지 않고 상태 중복을 줄여 순서대로 읽는 보조 도구.
- `findings.json`: 확정 3건과 주관적 불편 1건의 개별 근거.
