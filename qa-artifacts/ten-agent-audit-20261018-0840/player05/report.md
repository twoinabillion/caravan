# 플레이어 05 — 탐험형 독립 감사

두 번째 시도에서 본편을 완료했다. 최종 선택은 코어 격리 수면(`core_sleep`), 종결은 `story_done`이다. 첫 시도의 탈수 실패도 그대로 보존했다. 게임 소스나 문구는 고치지 않았다.

## 실행과 재시도

seed는 `181305`, 준비물은 `repair`다. 실행 전에 [policy.cjs](policy.cjs)에 탐험·기록·새로운 사람을 우선하되 보급·수리·야영을 먼저 처리하는 성향과 판단 규칙을 썼다. 공개 원문, 선택 label/hint, 조건 충족 표시, 현재 자원·명단·목표·지도만 선택에 사용했다. 미래 out/fx/확률, 숨은 플래그를 조회해서 선택하지 않았고 자원이나 동료를 주입하지 않았다. 선택과 행동 이유는 각 attempt의 `decision-reasons.json`에 남겼다.

| --- | --- | --- | --- | --- | --- |
| attempt01 | 탈수 `thirst` | 미완료 | 19일차 00:54 · 1,240.1km | 100 / 399 | 99회 |
| attempt02 | `story_done` · `core_sleep` | 완료 | 엔진 요약 6일차 16:54 · 519km | 70 / 238 | 70회 |

첫 시도는 내 정책에 있던 장소별 탐색 3회 상한 때문에 청주의 새 메인 기록을 열지 않고 세종과 왕복하다 실패했다. 당시 공개 목표와 탐색 가능 표시에는 청주의 새 기록이 계속 나와 있었다. 게임 진행 불능으로 세지 않는다. [retry-policy.cjs](retry-policy.cjs)는 그 공개 메인 기록 열람만 일반 탐색 상한에서 제외한다. 다른 성향·seed·준비물은 유지했다. 자세한 근거는 [retry-rationale.md](retry-rationale.md)에 있다.

완료 경로는 부산 → 양산 → 밀양 → 대구 → 구미 → 김천 → 무주 → 전주 → 논산 → 대전 → 청주 → 천안 → 평택 → 수원 → 서울이다. 서쪽 장터길을 골랐다. 민지의 울산 부탁은 거절했고 강우의 후임 인계를 도운 뒤 구미에서 정식 영입했다. 최종 인원은 주인공과 강우, 2명이다. 최종 자원은 연료 45.59L, 물 20, 식량 9, 고철 51, 차체 82.42%, 피로 34.78이다.

실제 거래 14회, 지역 노동 1회(밀양 공동 펌프), 탐색 18회, 야영 5회, 노선 출발 14회와 실제 엔진 주행을 거쳤다. 버스 난방은 호스 우회로 수리했고, 야영에서 차체가 회복됐다. 별도 `field-repair`나 업그레이드 구매는 실행할 필요가 생기지 않았다. 영입·퍼크도 획득 조건을 거쳐 처리했다.

두 시도의 sourceHash는 모두 `680680f7e67c7d414f19b18666409127b3ca27043e8c6eea4c9bbb44ff22628b`다. 실제 Studio 4319의 저장·탭·서버에는 접근하지 않았다.

## 전편 검토

총 170개 선택, 637개 기록을 검토했다. 각 선택의 입장 원문, 공개 선택지 전체, 고른 문구, 결과, 칩, 전후 시각·장소·주행 상태·명단·자원·목표를 읽었다. 두 시도에서 첫 163개 기록(선택 46개)이 JSON 단위로 정확히 같음을 확인하고 공통 본문으로 함께 검토했다. 그 뒤 갈라지는 모든 기록은 따로 읽었다. 반복 사건도 결과·공개 선택지·자원이 달라진 경우 별도로 확인했다.

목표 모델은 두 시도 합쳐 서로 다른 28종을 읽었다. 전체 거래·노동·야영·주행·영입·재접속 기록도 읽었다. 읽기용 [attempt01/review-log.json](attempt01/review-log.json), [attempt02/review-log.json](attempt02/review-log.json)은 원본 전체 내용을 보존하고 목표에 참조 번호를 붙인 투영본이다. 원본 trace와 저장은 각 attempt 폴더에 남겼다.

169번의 지불 결과 재접속 모두 `loaded=true`, `replayed=true`, `applied=false`였고 관측 스냅샷이 동일했다. 이 범위에서 자원 중복 지급·차감이나 목표/명단 변동은 없었다. 실제 브라우저 복원까지 검증했다는 뜻은 아니다.

## 확정 관측 4건

1. **출발 때 고르지 않은 정비 방식을 뒤에서 회상한다.** 공통 trace10에서 `회로도에 지금 배선 경로를 덧그린다`를 선택했다. 번호표 선택은 고르지 않았다. 그런데 trace157 `story_family_key` 입장은 “출발 전에 번호를 붙여 둔 선들”이라고 말한다. 실제 선택과 후속 기억이 어긋난다. `P05-C01`, P2.

2. **만나지 않은 한별에게 암호를 배웠다고 한다.** attempt01 trace191 `cell_ghost_meet`에서 “한별이 알려준 문구”로 유령의 출입 확인을 통과한다. 앞선 전체 입장·결과에는 한별이나 해당 문구 전달 장면이 없었다. 플레이어에게 장면 하나가 빠진 것처럼 느껴진다. `P05-C02`, P2.

3. **결식 중인 아침에 앞으로 먹을 저녁을 완료한 사실로 쓴다.** attempt01 trace301 `talk_kw_19`는 12일차 06:30, 식량 0에서 시작해 같은 상태로 끝난다. 결과는 “그날 저녁은 강우가 제일 많이 먹었다.”고 쓴다. 이후 종료까지 식량은 줄곧 0이고 같은 날 점심 결식과 쇠약 경고도 나온다. `P05-C03`, P2.

4. **반복 위기의 서수가 실제 횟수를 따라가지 않는다.** attempt01 연료 위기 237·255·271 다음, 네 번째인 trace280부터 열세 번째인 trace396까지 “세 번째다.”라고 반복한다. 세 번째 탈진 trace399도 `두 번째 한계`로 나온다. 같은 과거 장면을 다시 보는 인상이 강하다. `P05-C04`, P3.

각 원문, event ID, trace n, 실제 상태, 기대·관측·영향·확신도는 [findings.json](findings.json)에 있다.

## 주관적 불편 2건

- attempt02 trace224 `seoul_base`: 강우가 동행하는데 `동료들을 돌아본다`는 민지가 필요해서 막히고, 가능한 유일한 선택은 `혼자라도 오른다`다. 민지 전용 대사라면 선택 이름도 민지를 가리키는 편이 이해하기 쉽다. 강우가 실제로 사라졌다고 단정하지 않았다. `P05-S01`.
- attempt01 trace313 `water_toll`: 입장문과 가방에 없던 쇠파이프를 결과에서 바로 사용한다. 같은 날 trace317 도둑 사건은 쇠파이프 1개가 없어 그 선택을 막는다. 현장 물건을 빌린 가능성이 있어 확정 자원 조건 오류로 세지는 않았지만 출처 연결은 부족했다. `P05-S02`.

## 검수 한계와 제외

공유 실행기와 실제 엔진을 사용한 Node VM 진단이다. 독립 저장과 선택 정책을 썼지만 엔진 구현 자체가 독립인 것은 아니다. 프레젠테이션·오디오·실시간 대기·UI 입력은 생략됐다. 화면, 그림 크롭, 터치, 음성, 읽기 페이지, 브라우저 새로고침·열린 도구 복원은 검수하지 않았다. 브라우저나 인간이 직접 전편을 플레이했다고 주장하지 않는다.

실행기의 `eventObservation`은 실제 UI의 `eventChoiceData`가 만드는 `G.reqCostText(req)`를 모두 전달하지 않는다. 따라서 hint가 빈 값이라는 사실로 실제 화면의 비용 미표시를 확정하지 않았다.

원시 목표의 `why`/`expected`는 실제 공책에서 변환되므로 원문 모델만으로 노출 문구나 스포일러 문제를 확정하지 않았다. 에필로그의 밤·새벽·수원 귀환도 별도 `timeKind`/`scene` 서술 표식을 고려해, 엔진 요약의 고정 시계·노드만으로 오류로 세지 않았다. `camp_scan`의 새벽 3시는 직전 실제 야영 구간(02:27~06:30)에 포함되므로 시간 오류로 잡지 않았다.

첫 시도의 탈수와 길 왕복은 정책 실패다. 본편 완료 후에는 소스 전반 감사나 다른 경로의 추가 실험으로 확대하지 않았다.
