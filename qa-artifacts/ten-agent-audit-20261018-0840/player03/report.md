# Player 03 · 실리·생존형 독립 감사

본편을 완료했다. 첫 시도는 내 정책 오류로 실패했고, 공개된 마지막 선택을 인식하는 조건 한 곳만 고친 두 번째 시도에서 집행권을 저항 연대망에 넘겨 `story_done / core_transfer`로 끝냈다. 게임 코드는 수정하지 않았다.

독립 에이전트가 직접 작성한 정책과 실제 게임 소스의 Node VM 엔진 실행, 완결된 자기 로그의 문맥 검수다. 브라우저·사람 플레이나 UI·음성 검수가 아니다. 공통 harness와 runner를 사용했으며 독립 엔진 구현을 만든 것은 아니다. 다른 에이전트의 결과는 읽지 않았다.

## 성향과 실행

수리 준비물(`repair`), seed `181303`, 플레이어 이름 상혁. 물자를 합법 거래하고 노동으로 고철을 벌며 주 목표를 따라간다. 확인·복구·안전·보급에 가치를 두고, 무보상 위험과 폭력·영구 희생을 낮게 평가했다. 플레이 정책은 공개 본문·선택 label/hint·요구 조건·목표·자원·경로 예보만 사용했다. 미래 결과, 효과, 확률, 저장 파일로 선택을 최적화하거나 상태를 주입하지 않았다. 결과 검수용 스크립트는 플레이가 끝난 뒤 별도로 작성했다.

두 시도 모두 사망 장면·사망형 종결은 관측하지 않았다. 1차는 공동체의 외면에 따른 실패다. 2차는 본편과 새 세션 후일담까지 읽은 종료다. 최종 2차 저장은 연료 1.56L, 물 13, 식량 5, 고철 1, 차체 85.66%, 피로 13.30, 부품 2, 의약품 1, 부모님의 검증키 1이다. 최종 본문은 수원에서 엄마와 재회하지만 종료 저장 좌표는 서울에 남는다. 이를 종결 뒤 실제 이동 불능으로 판정하지 않았다.

경로는 부산 → 양산 → 밀양 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울이다. 능선길을 택했다. 밀양 공동 펌프 노동 1회로 물 2와 고철 14를 얻었고, 정상 2차 시도에서는 거래 5회·야영 3회·목표 탐색 9회를 했다. 수리를 강제로 성공시키거나 동료·깃발을 넣지 않았고 영입도 없었다.

## 전편 검수 범위

선택 125개 기록(1차 73, 2차 52)의 진입 원문·모든 공개 선택과 조건·선택 결과·전후 시간/장소/자원/동료/목표를 검수했다. 두 실행의 선두 160 trace, 선택 48개는 전체 JSON이 정확히 같다. 이 공유 본문은 한 문맥으로 읽고 동일성을 대조했으며 서로 다른 선택 문맥 77개를 읽었다. 이 수치를 125개의 서로 다른 사건으로 세지 않는다.

선택 외 이동·주행·거래·노동·탐색·야영·서울 진입·준비 복귀도 전후 자원과 메시지를 읽었다. 유료 결과 재접속 125회 모두 `loaded=true`, `replayed=true`, `applied=false`, 전후 스냅샷 동일이었다. 이는 엔진의 저장/불러오기·중복 효과 검수이며 브라우저 새로고침 품질 증거가 아니다.

각 선택의 예상 대가·판단, 실제 수치 변화, 성공/진행 평가와 불분명한 비용은 [review-ledger.md](review-ledger.md)에 남겼다. [review-ledger.json](review-ledger.json)은 125개 선택의 원문, 모든 선택, 전후 전체 상태와 목표, 결과, 칩, 정책 이유를 포함한다. 정책 이유 로그는 각 attempt의 `policy-decisions.json`이다.

## 확정된 문구·상태 불일치

1. **목표 장 번호가 전진 중 되돌아간다.** 두 실행의 `parents_mother_truth`, trace 132에서 메인 스토리 5장(엄마 재회)이 4장(거점 응답 준비)으로 바뀌고 trace 135 뒤 다시 5장이 된다. 목표 진행은 11/13→12/13으로 늘고 새 수원 작전을 준비하는 장면이어서 회상 전환도 아니다. 다음 행동·장소 안내는 맞으므로 진행 차단이 아니라 낮은 심각도의 안내 일관성 문제다.
2. **네 번째 이후 고갈도 “세 번째다”라고 한다.** 1차 `crisis_nofuel3`의 trace 196은 이미 네 번째 연료고갈인데 제목이 “세 번째 빈 탱크”, 진입문이 “엔진이 잠들었다. 세 번째다.”다. 214·234·250·264에서도 반복된다. 반복 위기의 생존 회복은 작동했다. 이 경로는 내 불필요한 왕복 때문에 생겼고 정상 본편 첫 통과에 필수로 노출되는 문제는 아니다.

## 실리 입장에서 불편한 부분 — 확정 결함과 구분

- `patrol_toll` trace 193의 “논길로 멀리 우회한다”에는 공개 관찰 API 기준 시간·연료·차체 힌트가 없다. 실행 뒤 45분, 차체 -3%, 남은 연료 0.494448L 전부를 잃었다. 먼 우회의 소모는 짐작되지만 손상까지 비교하기 어렵다. `crisis_nofuel`의 도보 연료 조달도 7시간·물 -2·식량 -2를 실행 뒤 알게 됐다. 모든 결과를 미리 알려야 한다는 요구가 아니라 생존 예산 판단의 불편이다. 실제 UI의 별도 설명까지 없다고 단정하지 않는다.
- `perimeter_first` trace 76은 경고사격이 차 옆 아스팔트를 때린 뒤 보행기가 길을 열어 주지만 차체가 83.66→77.66%다. 결과는 작업대 설치를 말하고 손상 원인은 설명하지 않는다. 피탄·파편 같은 생략된 사유는 가능하므로 물리적 모순보다는 강제 손실의 인과 설명이 약하다는 의견이다.

## 내 정책의 실패와 실행기 한계

1차는 `seoul_decision`의 “집행권을 저항 연대망에 넘긴다”가 이미 활성화돼 있는데도, 내 코드가 “넘긴다”를 실행 동사로 인식하지 못해 “수원으로 내려가 준비한다”를 10번 골랐다. 수원에서는 실질적 준비를 늘리지 않고 즉시 서울로 되돌아갔다. 연료고갈 8회, 굶주림과 공동체 외면이 누적돼 실패했다. 게임 softlock이나 동료 영입 강제의 증거로 쓰지 않는다.

2차 변경은 이 공개된 활성 선택을 인식하는 정규식에 `넘긴`을 추가한 한 곳뿐이다. seed·보급·경로·노동·선택 평가를 바꾸지 않았고, 첫 160 trace가 동일하다. 4일차에 동일한 보급 상태로 정상 인계와 본편 종료가 가능했다. 첫 정책 원본은 `policy-attempt01.cjs`로 보존했다.

동점이면 첫 선택을 고르는 규칙 때문에 “서쪽 장터길=보급·안전”이라는 본문 정보를 충분히 반영하지 못했고, 일자리도 이름의 일부 동사로만 찾았다. 그래서 실제 게임에 보급 수단이 없었다거나 경제가 필연적으로 파탄 난다는 결론을 내릴 수 없다. 공공 노동의 고철 14는 실제로 얻었지만 미리 결과를 읽고 계획한 보상은 아니다.

UI, 그림, 잘림, 버튼 도달성, 입력 속도, 움직임, 음성, 실제 탭 복귀는 평가하지 않았다. `camp_scan`은 야영 뒤 06:30 상태에서 “새벽 3시”를 서술하지만 야영 내부 사건의 재구성일 수 있어 시간 결함으로 세지 않았다. 에필로그의 밤·새벽·수원 귀환도 종료 서술과 플레이 좌표가 분리돼 있어 추가 확인 없이 실제 재개 버그로 세지 않았다. Studio 4319·사용자 저장·탭·서버는 건드리지 않았다.
