# 06 · AI와 권력을 불신하는 여행자

최종 여정은 7일째 서울, 누적 530km에서 `story_done`으로 끝났다. 본편을 완료했고,
최종 방법은 `core_sleep`(코어 격리 수면)이었다. 민지·강우 두 동료와 함께했다.
신뢰할 수 없는 자동 명령을 제한하되 의료·급수·병원 전력을 살리고, 재가동 열쇠를
여러 사람에게 나누는 선택이었다. 원본 검색창이 닫히고 내일 예약한 세 건의 조회가
늦어진다는 비용도 먼저 확인했다. 보존 선택은 감시 가능 동료 2/3으로 잠겨 있었다.

## 방법과 재시도

실제 소스 엔진을 공통 `harness.cjs`/`runner.cjs`의 Node VM에서 실행했다.
독립 Map 저장소, seed `181306`, `provisions` 팩의 새 게임이다. 정책은 실행 전에
`policy.cjs`로 작성했다. 공개 원문·라벨·힌트·현재 목표·경로·보급만 보고 골랐으며
미래 결과·효과·확률을 정책에 넘기거나 자원·동료·플래그·난수를 주입하지 않았다.
다른 사람 보고나 옛 정책을 가져오지 않았다.

첫 `attempt01`은 14일째 청주에서 갈증 엔딩(`thirst`)으로 끝났다. 106회 선택,
377개 trace, 832km였다. 새 목표가 같은 장소에서 다시 주변 탐색을 요구했는데도
정책이 '장소당 1회 탐색' 제한을 유지해 청주↔세종을 왕복했다. 실제 공개 목표가
현지 미완료 기록을 가리킬 때 다시 탐색하는 보정 하나만 `attempt02`에 넣었다.
첫 기록은 보존했으며 실패를 게임의 진행 불가로 세지 않았다.

재시도는 79회 선택, 273개 trace였다. 밀양에서 실제 공동 펌프 일을 해서 물 2와
고철 14를 받았고, 거래 15회·탐색 16회·야영 6회·실제 주행 16구간을 수행했다.
민지와 강우의 부탁을 끝내고 각각 정식 영입했다. 수리는 무료 상태 주입 없이
야영과 실제 획득한 민지 정비 퍼크로 이뤄졌다. 임의 현장 수리나 업그레이드는 없었다.

완료 경로는 부산→양산→밀양→양산→울산→경주→대구→구미→김천→상주→문경→충주→
청주→천안→평택→수원→서울이다. 마지막 저장의 자원은 연료 약 33.8L,
물 15, 식량 9, 고철 2, 차체 100이었다. 종료 시 저장 좌표 서울과 시계 7일 10:59는
후일담을 서술하는 시간·장면 표지와 구분했다.

## 전체 검토

두 attempt의 선택 185건을 검토했다. 각 선택의 진입 원문, 모든 공개 선택과 잠금,
선택 결과, 칩, 시간·장소·이동 구간·동료·자원·물품·목표 전후를 읽었다.
처음 53건은 두 attempt의 전체 choice 객체가 완전히 같음을 대조했고, 같은 본문을
공유 증거로 읽었다. 고유 choice 객체는 132건이다. 정규식 후보만으로 확정하지 않았다.
각 선택 이유는 각 attempt의 `decision-reasons.json`에 남아 있다.

완료된 결과 뒤 저장·불러오기·유료 결과 재열람을 총 185회, 별도 정차 재접속을 2회
실행했다. 187회 모두 관측 상태 전후가 같았고 결과 효과를 다시 적용하지 않았다.
이 검사는 엔진의 메모리 저장 검사이며 브라우저 새로고침이나 Studio 도구 복원
검수는 아니다.

## 발견

확정 내용은 세 가지다. 자세한 상태와 원문은 `findings.json`에 들어 있다.

- P06-01, P2: 강우와 현재 20분을 함께 보냈다고 쓰지만 시계는 06:30→06:30이다.
  엔진을 5분 듣는 수첩 장면, 민지와 조수석에서 5분 쉬는 장면, 라디오를 10분 듣는
  장면도 0분이다. 후일담의 장면 표지 문제가 아니라 현재 행동의 명시적인 시간과
  실제 시간 효과가 어긋난다.
- P06-02, P2: 수원에서 '식량 1일치'를 사면 식량 1이 늘고 고철 4가 든다.
  이 3인 일행은 다음 아침 한 끼에 식량 3을 쓴다. 판매 단위를 하루분으로 읽으면
  필요한 양을 잘못 계산한다. 실제 렌더러도 이 라벨을 전달한다.
- P06-03, P3: 연료 위기가 네 번째·다섯 번째 이후에도 계속 '세 번째 빈 탱크',
  '엔진이 잠들었다. 세 번째다.'로 나온다. 원래 첫 두 번을 구분한 연작의 기억이
  세 번째 이후 실제 횟수와 맞지 않는다.

주관적인 불편은 하나다. `seoul_costs`의 세 버튼은 모두 무엇을 '먼저' 확인할지
묻는데, 기록 창구 하나를 자세히 본 뒤 다음은 최종 결정이었다. 출처·반론을 대조하는
성향에서는 세 방식의 상세 대답을 모두 듣고 싶었다. 큰 비용 세 가지는 이미 본문에
공개됐으므로 진행 불가나 확정 정보 누락으로 세지 않았다.

반대로, 부모님의 말만으로 가족 명령의 책임을 확정하지 않고 당사자 정정·동의가
담긴 증언과 명령 원본을 따로 대조하게 한 과정은 이 성향을 잘 받았다. 코어가 스스로
고백해도 검증키가 우선한다는 설명, 격리 수면 후 생활 설비가 살아 있다는 설명,
하진이 귀환 여부를 직접 정하는 마지막 대화는 선택의 의미와 일치했다. 상위망의
반론도 서울의 이미 이룬 중단·인간 확인층을 취소하지 않았다.

## 실행기와 정책 한계

공유 실행기가 충족된 `req`의 `G.reqCostText`를 정책에 넘기지 않는 차이를 찾았다.
도르래 고철 4, 견인 고철 20은 실행기의 선택 hint에 없지만 실제 게임 렌더러는
표시한다. 따라서 이것을 게임의 '비용 미표시'로 보고하지 않았다. 정책에 실제 화면보다
적은 정보가 일부 들어온 한계다. 정책의 첫 탐색 오류 역시 별도 항목으로 분리했다.

화면·텍스트 넘침·인물 크롭·음성·터치·키보드·실시간 접근과 감속·실제 브라우저 저장은
검수하지 않았다. 이것은 사람이 브라우저에서 새 게임을 끝낸 테스트가 아니라, 실제
엔진을 사용한 공개 정보 기반 Node 실행과 전체 텍스트·상태 검토다. 사용자 Studio
4319, 탭, 서버, 실제 저장은 건드리지 않았다. 게임 수정도 없다.
