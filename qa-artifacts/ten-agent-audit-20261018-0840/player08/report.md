# player08 — 동료와 이동식집을 우선한 한 여정

첫 시도에서 본편을 마쳤다. `attempt01`, seed `181308`, 보급 꾸러미 `provisions`로 시작했고, 종결은 `story_done`, 집행 방식은 `core_transfer`였다. 재시도와 정책 수정은 없었다. 마지막 엔진 상태는 7일차 13:54, 서울 남산, 누적 530km다. 민지와 강우가 정식 동료로 함께 남았다.

독립 정책은 첫 실행 전에 작성했다. 공개 본문, 선택과 조건, 현재 자원, 공책의 목표, 업그레이드 현황만 보고 사람의 부탁과 대화를 우선했다. 미래 결과·확률·효과를 읽어 선택하지 않았다. 공용 `../harness.cjs`와 실제 소스 엔진 실행기를 사용했고 저장은 별도 Map에 격리했다. 사용자 Studio, 브라우저 탭, 서버, 실제 저장, 게임 소스와 기존 감사 결과는 건드리지 않았다.

## 실제로 한 일

부산 → 양산 → 밀양 → 양산 → 울산 → 경주 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울을 갔다. 밀양에서 민지의 부탁을 받아 울산 폐차장에 갔고, 실제 고철 4와 차체 3을 소모한 도르래 선택으로 진단기를 회수했다. 한 구간 임시 동행 뒤 경주에서 민지의 합류를 수락했다. 대구에서는 강우가 감시 표식을 뜯고 후임에게 초소를 넘기는 일을 함께 마친 뒤, 구미에서 정식 합류를 수락했다.

좌석은 미리 유료로 마련했다. 밀양 trace 40에서 `bench`를 사며 고철 12, 부품 1, 5시간을 실제로 지불했다. 정식 영입 전에 좌석 부족을 억지로 무시하거나 명단을 주입하지 않았다. 공동 펌프 일손 1회로 물 2와 고철 14를 얻었고, 탐색 16회, 거래 12회, 야영 6회, 동료 대화 9회를 했다. 별도 야전 수리는 하지 않았고 버스 수리, 민지의 엔진 정비, 야영 회복을 실제 진행했다. 다른 생활 설비는 여유 자원과 구입 가능 조건이 맞지 않아 추가 구매하지 않았다.

끝까지 넉넉하지는 않았다. 평택을 떠난 직후 연료가 바닥나 trace 205에서 직접 걸어 연료를 구했다. 7시간, 물 2, 식량 2를 소모하고 연료 9L를 얻었다. 수원에 도착한 다음 아침에는 식량 부족도 겪었고, 남은 고철로 연료와 식량을 샀다. 마지막 자원은 연료 약 40.8L, 식량 3, 물 13, 고철 2, 차체 100, 부품 7, 의약품 2였다.

마지막에는 연대망 인계와 격리 수면이 열렸다. 코어 보존은 근무 가능한 동료가 2/3이라 막혀 있었다. 두 사람의 부탁을 끝내고 계속 대화를 나눴어도 이 경로에서 세 번째 동료를 만나지는 못했다. 정책은 가능한 인계를 택했으며, 다른 엔딩을 얻기 위한 재시도나 추가 동료 주입은 하지 않았다.

## 발견한 문제

확정 관측 5건, 주관적 연결감 1건, 실행기 한계 1건을 `findings.json`에 분리했다. 진행을 막는 오류는 없었다.

| 구분 | 사건 / trace | 관측 |
| --- | --- | --- |
| 중간 | `up_bench_first` / 40, 212 | 밀양에서 유료 설치를 끝낸 좌석을 5일 7시간 3분, 442km 뒤 수원에서 처음 설치하는 현재 사건으로 다시 묘사했다. 그 좌석을 마련한 뒤 민지·강우가 이미 합류해 다녔다. |
| 중간 | `perimeter_first` / 162 | 경고사격은 차 옆 아스팔트에 맞았고 그냥 지나갔는데 차체가 6 감소했다. 본문과 결과에 차가 손상되는 원인이 없다. |
| 중간 | `seoul_decision` / 263–269 | 집행권을 넘긴 뒤 공개 목표 데이터가 ‘코어 앞을 지나 남산 코어로 오른다’와 4/5로 돌아갔다. 후일담 동안 유지되다 마지막 결과에서 완료된다. |
| 낮음 | `parents_mother_truth` / 234, 237 | 엄마 재회 완료 다음 목표 표제가 5장 → 4장 → 5장으로 바뀐다. 진행률은 계속 늘어나므로 실제 뒤로 돌아간 것은 아니다. |
| 낮음 | `talkr_mj_3` / 141 | 정확히 5분 쉬었다는 결과와 달리 시계는 06:30에서 전혀 움직이지 않는다. |

한강의 첫 다리 사건 → 남쪽 진입 관문 → 한강 관문을 잇는 순서는 위치가 반복되는 느낌이었다. 다만 첫 결과는 ‘다리에 올라섰다’까지만 써서, 도하 시작 장면으로 해석할 여지가 있다. 이를 확정 지리 모순으로 세지 않았다.

## 검수 범위와 제외한 판단

79개 choice 전부의 진입 본문, 공개 선택과 사용 가능 조건, 선택 이유, 결과, 칩, 시간·장소·동료·자원·목표 전후를 처음부터 끝까지 읽었다. 나머지 이동·거래·노동·탐색·야영·영입 기록과 결과 재접속 기록도 대조했다. `read-trace.cjs`는 반복되는 목표 필드만 차이로 줄여 보여 주며 원 trace는 그대로 보존한다. 문제 후보를 확인할 때만 해당 사건과 목표 계산·시간 표식 소스를 좁게 읽었고 전역 소스 감사로 확대하지 않았다.

선택 후 격리 저장을 재로드해 지급 결과를 다시 읽는 검사가 79회 있었고 모두 `loaded:true`, `replayed:true`, `applied:false`였다. 이는 효과 중복 적용이 없다는 엔진 검증이며 실제 브라우저 새로고침, 결과의 계속 버튼, 입력·뒤로·취소 UI 검수는 아니다.

후일담 `seoul_night`, `seoul_uplink_reveal`, `seoul_session_reset`에는 실제 `timeKind:'epilogue'`와 ‘그날 밤’, ‘다음 날 새벽’, ‘그 뒤 수원’ 표식이 있다. 그래서 저장 시계 13:54가 유지되거나 마지막 상태 위치가 서울에 남는다는 이유만으로 후일담을 시간·귀환 오류로 판정하지 않았다. 공책은 원시 목표 `why`를 별도로 변환하므로 raw `why`의 설명체를 플레이어 문장 결함으로 세지 않았다. 모닥불 손님이 06:30에 나타난 일도, 밤길을 걸어온 사람이 아침 불을 쬘 수 있어 확정 밤/낮 모순으로 세지 않았다.

실행기는 실제 UI의 `reqCostText(req)`를 모두 관찰값으로 넘기지 않는다. 따라서 빈 hint를 근거로 비용 표시 누락을 확정하지 않았다. 화면·그림 크롭·애니메이션·음성·접근성은 검수하지 않았으며 브라우저나 사람의 직접 플레이로 주장하지 않는다. 취소/뒤로 선택은 이 경로에서 실행하지 않았고 결과 강제도 하지 않았다.
