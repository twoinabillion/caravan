# player07 — 위험 감수형 독립 플레이 감사

첫 시도에서 본편을 완료했다. 종결은 `story_done`, 마지막 방식은 `core_transfer`(집행권을 저항 연대망에 인계)다. 6일차 12:14에 종결 엔진 상태가 남았고 누적 이동은 634km였다. 정식 동료는 민지 1명. 재시도는 없었다.

정책은 실행 전에 `policy.cjs`로 고정했다. seed는181307, 준비 묶음은fuel. 공개 본문·선택 이름·hint·활성 요구조건·현재 자원·목표·예보만 사용해 야간 이동, 구출과 직접 행동, 불확실한 거래를 선호했다. 선택 뒤 미래 결과나 확률을 보며 정책을 바꾸지 않았고 결과를 되돌리지 않았다. 구출의 부분 성공과 졸음운전 사고2회를 그대로 수용했다. 모든71선택의 당시 이유는 `attempt01/decision-reasons.json`에 있다.

진행 경로는 부산→양산→밀양→양산→울산→경주→대구→경주→대구→구미→김천→상주→문경→충주→청주→천안→평택→수원→서울이었다. 김천에서는 동쪽 능선길을 골랐다. 실제 거래10회, 밀양 펌프 노동1회(고철13→27), 탐색15회, 야영3회, 영입 만남1회와 정식 합류1회를 거쳤다. 초반 버스 수리는 보유 부품1개로 실행했다. 별도 현장 수리와 업그레이드 구매는 하지 않았다. 총241trace이며 선택71회, 주행40구간 기록, 출발18회가 포함된다.

## 확인한 문제

- P07-001 · 중간 · `crisis_nofuel` · trace192: 수원 정착지에 도착해 주행이 끝났는데 인적 없는 길 위에서 고립됐다는 연료 고갈 장면이 열렸다. 도보 조달로7시간과 물·식량을 써야 했고, 바로 뒤 같은 수원에서 연료10L/고철10의 정상 거래가 가능했다. 도착 경로 예보는연료4L, shortage=false, 연료 여유0L였다. 여유 없는 경로를 고른 판단과 별개로, 도착 후의 위치와 구제 장면이 맞지 않는다.
- P07-002 · 중간 · `loc_gyeongju` · trace62: 현재 시각은2일차05:15인데 “천년 왕릉 사이로 해가 진다”로 장면을 시작했다. 선택한5시간 휴식 뒤10:15가 됐고 아침 식사도 적용됐다. 후일담이나 회상이 아닌 현재 도착 장면의 모순이다.
- P07-003 · 중간 · `perimeter_first` · trace150: 경고사격이 차 옆 아스팔트에 맞고 보행기가 길을 열었다고 서술했다. “지나간다” 결과에도 손상 행동은 없는데 차체84.44→78.44, 즉6%가 감소했다. 손상량은 칩에 나타났지만 손상 원인이 문장에 없다.
- P07-004 · 낮음, 주관적 마찰 · `route_ridge_anchor` · trace127: 사람을 업고 비탈을 오르는 구조에서 선택 위험은 “비탈 압박”인데 결과는 “교전 압박 상승”이었다. 앞뒤의 “전세 우세”, “전술 연계”도 구조 현장을 전투 수치로 읽게 했다. 구조 결과 자체의 오류로 보지는 않는다.

각 항목의 원문, 상태 전후, 기대와 관측, 영향, 확신도는 `findings.json`에 기록했다. 위 네 후보를 확인하는 데 필요한 해당 사건/분기만 읽었고 이후 소스 전반 감사로 범위를 넓히지 않았다.

## 전편 검수와 재접속

선택1–71을 순서대로 모두 읽었다. 각 선택의 진입 본문, 보이는 활성/비활성 선택과 요구조건, 고른 선택, 전체 결과, 결과 칩, 시간·위치·주행·명단·소지품·연료·물·식량·고철·차체·피로·목표 전후를 대조했다. `review.cjs`는 원시trace에서 이 정보를 읽기 쉽게 출력하는 보조 도구다. 검토한 choice trace는2,4,6,8,10,12,14,17,21,24,27,31,37,39,43,48,52,56,59,62,66,70,73,80,83,87,94,100,104,108,112,115,118,122,125,127,129,133,137,140,143,147,150,153,157,161,164,168,172,176,179,183,185,189,192,201,203,205,208,212,215,218,221,224,227,230,232,234,236,238,240이다.

71개의 paid-result-reload 기록 모두 loaded=true, replayed=true, applied=false였고 기록된 before/after가 동일했다. 이는 별도 메모리 저장소에서 실제 엔진의 save/load와 같은 유료 결과 재해석을 확인한 것이다. 브라우저 새로고침, 계속하기 화면, 읽기 커서나 실제 화면 복원 검수는 아니다.

## 실행기와 정책의 한계

공유 `harness.cjs`가 기존 실제 엔진 실행기를 불러왔다. 개별 Map 저장소를 사용했고 사용자 Studio4319, 브라우저 탭, 서버, 실제 저장, src/assets/tools/docs 및 이전 QA 자료는 수정하지 않았다. 이 폴더의 정책·신규attempt·보고서만 썼다. 화면·오디오·실시간 대기와 프레젠테이션은 스텁이므로 사람/브라우저/시각/음성 플레이 검수로 세지 않는다.

실행기의 eventObservation은 실제 UI의 `eventChoiceData`가 붙이는 `G.reqCostText(req)`를 모두 전달하지 않는다. 따라서 원시hint가 비어 있다는 것만으로 실제 화면의 비용 미표시를 주장하지 않았다. 후일담은timeKind 표식과 별도 서사 시점을 갖기 때문에 종결 뒤 수원으로 돌아가는 문장과 마지막 엔진 좌표·시계의 차이를 UI/시간 오류로 확정하지 않았다. 원시 main.why도 공책 표시 단계에서 변환되므로 선행 스포일러로 판정하지 않았다.

민지 영입 중 첫 경주 방문에서는 “하룻밤을 보낸 뒤 다시 이야기해 보자”는 공개 알림이 있었지만, 정책은 당장 야영하지 않고 북쪽으로 갔다가 영입 목적지로 되돌아왔다. 이104km 왕복은 정책의 우선순위와 제한된 행동 모델이 만든 우회로, 게임의 강제 왕복 결함으로 세지 않았다. 획득한 첫 퍼크는 실행기 기본값으로 선택됐으므로 플레이어가 능력을 비교해 고른 경로를 검수한 것도 아니다.
