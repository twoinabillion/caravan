# 열 명의 독립 에이전트 플레이 감사

요청: 서로 다른 성향의 서브에이전트 10명이 새 게임부터 엔딩까지 진행하며
무엇이 문제인지 기록한다. 이번 세션에는 게임을 고치지 않는다.

각 에이전트는 자신의 공개 선택 기반 정책을 만들고 실제 소스 엔진을 실행한다.
독립 Map 저장소·새 난수를 사용하며 사용자 Studio와 기존 감사 자료를 바꾸지 않는다.
`harness.cjs`는 기존 실제 엔진 실행기를 출력 경로만 분리해 로드한다.
원 실행기와 이 어댑터는 공유 기반이며, 독립 엔진 구현 열 개는 아니다.
프레젠테이션·오디오·실시간 대기는 생략하므로 브라우저/인간 플레이로 세지 않는다.

진행 중 관측 한계도 확인했다. 실행기의 eventObservation은 실제 UI
eventChoiceData가 붙이는 G.reqCostText(req)를 모두 전달하지 않는다.
따라서 빈 hint는 실제 비용 미표시의 증거가 아니다. 이번 열 명의 관찰 조건을
중간에 바꾸지 않고, 이 차이를 별도 도구 한계로 보존한다.

- 게임 소스·문구·그림·효과·조건·난수 결과·실제 저장은 수정 금지.
- 각자 `playerNN/`만 작성. 이전 attempt는 보존하고 재시도는 새 attempt에 남긴다.
- 성격·선택 이유는 실행 전에 정책에 쓴다. 미래 결과/효과를 보고 선택하지 않는다.
- 실제 얻은 자원으로 거래/일/탐색/수리/영입/이동한다. 자원/동료/플래그 주입 금지.
- 실패 엔딩·막힘도 그대로 기록한다. 필요한 재시도는 공개 정보에 근거한 정책 조정만 허용한다.
- 엔딩 후 자기 여정의 진입 문장, 선택, 결과, 자원, 시간, 장소, 동료 명단과
  목표 변화를 전부 읽는다. 정규식 후보만으로 문제를 확정하지 않는다.
- 문제마다 원문·event ID·trace n·실제 상태·기대·실제·영향·확신도를 남긴다.
- 확정 모순, 주관적인 어색함, 실행기 한계는 구분한다. 못 본 화면/음성은 평가하지 않는다.
- 최종 보고에는 종결 종류·본편 완료 여부·경로·인원·재접속·검수 한계도 포함한다.

10명은 동시 3명씩 실행한다. 각자의 보고가 끝나면 다음 에이전트를 생성한다.
최종 집계는 중복 지적을 합치되 어느 에이전트/어떤 여정에서 관측했는지 유지한다.
