잠정 문제는 2건이다. 정확한 전후 값·다른 해석·인접 n·최소 수선 방향은 [findings.json](findings.json)에 있다.

- P12-01 — `attempt01` n507–511, `ev_fog_pass` 선택 2. 식량 0→0인데 결과는 먹을 것을 꺼내 마지막 봉지를 접었다고 한다. `attempt02` n258에서는 같은 문장과 식량 5→4가 관측됐다. 무자원 대기는 유지하고 실제 음식 보유에 맞게 문장을 나누면 된다. 진행 차단은 없었다.
- P12-02 — `attempt01` n344–348, `crisis_drowsy` 선택 0. 06:32→08:32 수면 중 일반 awake 피로 4.104가 더해져 피로가 92.76787999999998→51.871879999999976으로 변했다. 끼니 경계도 없었다. 자연 반복 4회와 수면 옵션이 빠진 시간 경로를 확인했다. 현재 `fx.sleep`은 피로를 먼저 0으로 만들므로 단순 옵션 추가로 기존 부분 회복 45를 전면 회복으로 바꾸면 안 된다.

카메라·초록 신호·탐조등과 강원 지역의 짧은 만남은 밤길 취향에 잘 맞았다. 속초 노인의 실제 질문을 결말에서 다시 전하고 직접 연결한 세 거점만 인계에 응답하는 점도 좋았다. 반면 첫 시도는 왕복과 구조 연료에 의존해 같은 위기 문장이 반복됐다. 이는 완만한 경로 추첨, 보급·야간 탐색 계획 실패가 주원인이므로 제품 오류로 계산하지 않았다. 두 번째 시도에도 강릉↔대관령 왕복과 물0·결식 관리 실패가 남았다.

처음 실행 전 원시 runner·과거 정책/보고·미래 결과를 읽지 않았다. 실행 후에는 자기 원기록과 두 의심의 좁은 소스만 진단했다. 동료는 0명이었고, 케이블카는 발견했지만 방문하지 않았다. 실제 UI·공책 접근·레이아웃·사람·음성 검수가 아닌 격리 엔진 감사다. 생산 코드, 실제 저장, Studio와 서버는 건드리지 않았다.
