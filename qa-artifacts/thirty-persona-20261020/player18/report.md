# player18 · 약속을 먼저 지키는 배달부

두 실행 모두 실제 `storyDone=true`, `core_transfer`, `SESSION 1 END`까지 도달했다. 두 번째 실행에서는 밀양 게시판의 **부품 궤짝 → 대전**을 DAY1에 수락하고 DAY3 아침에 직접 넘겼다. 기한은 DAY5였으며 고철은 12→26으로 늘었다. 안내도 빠른 처리 +4와 실제 합계 +14를 구분했다.

| 실행 | 결과 | 범위 |
| --- | --- | --- |
| attempt01 | DAY7 · 430km · 본편 완료 | 191행, 선택 62회. 게시판 필터 오류로 배달 수락을 놓침 |
| attempt02 | DAY8 · 582km · 배달 및 본편 완료 | 231행, 선택 72회. 배달 수락 #29, 완료 #62, 마지막 후일담 #230 |

첫 정책은 배달이라는 단어만 찾다가 공개된 `kind=deliver` 두 건을 놓쳤다. 원본을 `policy-attempt01.cjs`에 보존하고, 공개된 종류와 기한으로 고르는 부분만 고쳐 재시작했다. 두 번째 실행에서는 배달을 우선해 합천→거창→무주→영동→대전으로 갔고, 완료 후 김천으로 돌아와 본편을 이었다.

발견한 문제는 결과 수치의 과도한 소수점 표시 1건이다. attempt02 #117 `combat_toll_breach` 선택 3의 연료가 0.314425L→0으로 줄면서 결과에 **“연료 -0.314425L”**가 남았다. #120 연료 회복 사건에도 **“피로 +1.85719”**가 나왔다. 실제 차감과 상한 처리는 맞지만 읽는 결과 문구에는 과한 정밀도다. 실제 값을 유지하고 표시 단계에서 약 −0.3L처럼 정리할 수 있다. 두 실행을 마친 뒤 확인한 소스에서도 결과 칩을 소수 여섯 자리까지 만들고, UI가 해당 숫자 또는 문구를 그대로 출력한다. 저장된 문자열 문제는 확인했으며 실제 화면의 줄바꿈·크롭은 검사하지 않았다. 자세한 사실과 수정 경계는 `findings.json`의 P18-01에 적었다.

서사·진행 단절은 이번에 선택한 분기에서 확인하지 못했다. 인계 뒤 목표는 남은 결과 읽기로 전진했고, 엄마를 중계소에 남긴 선택은 마지막 재회까지 유지됐다. 동료 없이 온 실행에서 동료 증언·감시 근무 선택은 잠겼고, 가능한 집행권 인계로 끝낼 수 있었다.

플레이 의견으로는 두 번째 실행의 검문소가 세 번 같은 세 단계와 철수 문구로 반복됐다(#72–76, #113–117, #155–159). 매번 쇠파이프·은수·화염병이 없어 최종 선택은 철수 하나였다. 다만 도구 경고가 앞에 나왔고 이전 경험 후에도 내가 접근을 반복했다. 진행을 막은 결함으로 보지는 않는다.

연료 부족 예보를 보고도 출발했고, 첫 실행에서는 커피와 회수료에 고철을 썼다. 부족한 보급으로 동쪽 능선을 택한 판단도 위기에 기여했다. 배고픔·연료 회복·탈진은 모두 실제 경험했지만 다음 행동으로 이어졌다. 이들을 강제 소프트록으로 세지 않았다. 수락한 배달의 기한을 놓친 적은 없다.

검토는 두 실행의 전체 422행을 순서대로 나눠 읽었다. 선택 134회의 진입문·모든 선택지와 잠금 조건·고른 문장·결과·칩·상태 변화를 확인했다. 같은 문단은 첫 출현을 참조하되 각 출현의 시간·위치·혼자라는 인원·물자·선택을 다시 대조했다. 저장 후 재실행 134회는 모두 `loaded=true`, `replayed=true`, `applied=false`였고 전체 공개 스냅샷도 같았다. `review-view.cjs`로 같은 범위를 다시 읽을 수 있다.

이 검토는 화면·소리·타이머를 대체한 격리 Node 엔진 실행이다. 실제 브라우저·모바일·화면 배치·음성·독서 커서 검사가 아니다. 게시판 한 건의 성공과 한 결말만 다뤘으며 늦은 배달·배달 취소·동료 모집·다른 결말은 검증하지 않았다. 실제 사용자 화면과 저장, 프로덕션 파일은 건드리지 않았다.
