# player03 — 구두쇠 현실주의자

올바른 `repair` 준비물로 **7일 차·430km·동료 없이 인계 결말과 실제 SESSION 1 END까지 완주**했다. 선택 60회와 trace 188행을 전부 검토했다. 중대 진행 차단은 겪지 않았다.

| 실행 | 준비물 / 성격 | 결과 | 검토 |
|---|---|---|---|
| attempt01 | tool — 공통 안내 오류에 따른 진단 실행 | DAY5, core_transfer, storyDone=true | 176행 / 선택57회 |
| attempt02 | repair — 비맹검 통제 재생 | DAY7, core_transfer, storyDone=true | 188행 / 선택60회 |

공통 BRIEF가 처음에 존재하지 않는 준비물 ID를 안내했다. root 요청에 따라 첫 정책을 [보존](policy-attempt01.cjs)하고 **pack 필드만 repair로 변경**했다. choose/decide/perk/reload 코드는 동일하다. 두 실행 모두 같은 seed203003·현재 소스 해시를 사용했다. 실패한 실행은 없다.

## 발견

- **P03-F01 · P3 · 확인된 서사 오류.** attempt02 행177, `seoul_core` 선택4 「여행 일지를 내민다」: “만난 사람, 나눈 물, 돌아간 길, 못 지킨 약속까지 적혀 있다.” 두 여정 모두 물을 나눠 주지 않았다. 우편부에게도 명단 대조만 했고, 물 손실은 식사·구출·채집 비용이다. attempt01 행165에도 같다. 결과의 회고 사례만 실제 완료 행동에 맞추거나 중립화할 범위다.
- **P03-F02 · P3 · 연속성 후보.** 두 실행 행18, 첫 부산→양산 주행13.6km에서 “우리가 스친 정착지” 세 곳의 이야기를 전한다. 아직 방문 노드는 부산뿐이다. 이전 삶의 지식일 가능성을 배제할 수 없어 확정 버그로 세지 않았다.

## 비용과 정책 오류

「지나가는 차를 기다린다」가 가격 재수락 없이 구매로 끝난 점은 의견으로만 남겼다. 진단 실행 행85는 고철11→0·연료+9·6시간, 재생 행54는 고철11→1·연료+10·5시간이다. 실제 차감 칩은 맞았다. 의도된 무작위 위기 결과일 수 있어 비용 게이트 버그로 단정하지 않았다.

구출 위기 다섯 번·허기 두 번은 정책의 자원 계획 실패가 컸다. 부족 예측을 보고도 출발했고, 「회수료」를 회수 행동으로 잘못 채점해 고철10을 냈으며, 수원의 무료 현장 일을 이름으로 알아보지 못했다. 강제 교착으로 보고하지 않는다. 재생에서 실제 거래는 행146 물5통 구매 한 번뿐이다.

## 검증과 한계

합계 **364행·선택117회·사건59종**을 읽었다. 재생의 동일 문장50회는 앞 실행을 참조하되 이번 시간·위치·자원·동료·게이트·후속 행동을 다시 확인했다. 새롭거나 달라진10회는 전체 문장을 읽었다. 비선택 행도 모두 읽었다. 저장 재열람117회 전부 성공, 효과 재적용0회, 전후 snapshot 차이0회였다. [선택별 검토](choice-review.md)와 [구조화된 근거](findings.json)에 행 번호를 남겼다.

실제 소스 엔진의 격리 Node VM 실행이다. 화면·음성·모바일·화자 파서는 검사하지 않았고, 사용자 화면·저장·Studio·생산 코드는 건드리지 않았다. 모집·사이드 미션·업그레이드·다른 결말은 미검증이다. 종결의 밤/새벽/복귀 서술과 정지된 엔진 시계는 종결 추상화일 수 있어 버그로 세지 않았다.

첫 완주·전수 검토 뒤 경험한 사건의 정의를 확인하다가, 넓은 sed 범위로 인접한 미경험 meet_seedlady 문장과 meet_photographer 식별자를 노출했다. 같은 경험 사건의 미선택 결과도 읽었다. 원래 공개문은 findings.json에 그대로 보존했다. **그 뒤 root가 준비물 정정 재생을 요청했으므로 attempt02를 독립 맹검으로 주장하지 않는다.** 재생 전·중 추가 소스 열람은 없었고, 행동 정책은 바꾸지 않았다.
