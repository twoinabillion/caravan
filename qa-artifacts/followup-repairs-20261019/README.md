# 후속 감사8항목 수선 — 구현·검사 완료, 실제 적용/화면 검수 미확인

Sang의 ‘고고’ 승인으로 [이전 감사](../followup-playtest-20261019-1401/README.md)의6곳과 후속 진단2곳을 수선했다. 게임 디렉터·대사 지침에 따라 비용·보상·기한 규칙과 인물 성격은 유지하고, 실제 상태와 표시·회고를 일치시켰다. 새 서브에이전트/디자인 변경은 없고 CSS·구조·시각/음성 자산·저장 스키마도 바꾸지 않았다.

## 변경

1. **의뢰 기한:** 실제 공책 phase를 ‘기한 N일차까지 · 넘기면 실패’로 고쳤다. 낡은 overdue 활성 기록은 게시판 처리 상태를 확인하게 하고, 전달이 보장된다는 말과 상충하는 인도 안내를 없앴다. DAY due에는 인도 가능, 다음 날 dawn에는 기존 실패·삭제·태도 손해 그대로다. 무기한 연속 의뢰는 그대로 무기한이다.
2. **완료 영수증:** `G.checkQuest`의 기존 장부 wrapper에서 실제 고철 전후 차이를 기록한다. 기본6+빠른 처리4이면 새 완료 기록도10이다. 보너스 계산·지급·조달품 소비는 바꾸지 않았다. 옛 영수증은 당시 총액을 추측해 고치거나 보상하지 않는다.
3. **회수조 동선:** 성공의 회수조는 승합차를 타지 않고 걸어서 물러난다. 한 대의 승합차는 여자 곁에 남아 문을 잠그는 다음 행동과 연결된다. 부분성공 note도 현장 하차·들길 퇴장으로 맞췄다. 새 차/갈림길/여행을 추가하지 않았다.
4. **야영 회상:** ‘자동 검문소’ threat만으로 수레를 만들지 않는다. ‘다섯 수레’ objective일 때만 행렬을 회상하고, 일반 검문소는 검문소만 기억한다. 결과 코드와 옛 저장된 현대형 context는 그대로다. 기존 구형 목표 문장 변환도 자기 frozen 문장만 읽는다.
5. **박 선생 종:**06:30의 무료 결과가 ‘그날 하루’를 완료하지 않고, 지금 문을 한 번 더 여닫는 반응으로 닫힌다. 고철1·시간0 그대로다.
6. **종장 조사:** 실제 동료 이름의 종성에 따라 과/와를 붙인다. 박 선생과·레오와를 확인했다. 과거 지급 결과의 텍스트/turns는 재작성하지 않는다.
7. **시장 단위:** 현행/구형 시장의 단품·묶음 보급·매입은 ‘묶음’으로 표시한다. 판매 거절도 실제 재고2이상에서1판매 조건을 말하며 이틀분을 남긴다고 하지 않는다. 가격·거래량·판매 조건은 그대로, 가방의 실제 인원 기반 남은 일수는 유지한다.
8. **보리 출신:** 공연에 와 끝까지 남고 저녁 반 그릇 계약을 맺었다는 기존 만남·탄이 인식표 연결에 맞췄다. 레오의 가족 상실과 현재 애착·가족 선택은 살렸고, 폐허에서 가족 개와 재회했다는 대체 이력만 걷어 냈다. 노트도 일치시켰다.

실제 `buildStoryTurns` 회귀 중 개가 있는 탓에 레오의 두 번째 입장 대사와 결과의 일부를 **보리의 대사로** 추론하는 오류가 드러났다. 같은 장면의 입장4개·두 결과6/2개의 화자를 명시했다. 전역 코퍼스 hash는 갱신하지 않고, 정확한 새 화자 배열을 assert한 뒤 해당 세 배열만 구형 baseline에 투영한다. 원 인용 수·비용/확률/게이트/효과는 유지한다.

Claude에게 위3장면만 부분 수선을 자문했고 실제 성공 응답을 참고했다. 최종 문구·적용·검증은 Codex 판단이다. 부분성공 note의 자문에 있던 미소개 ‘갈림길’은 채택하지 않았고, 레오의 기존 가족 상실은 명시적으로 보존했다.

## 실제 Studio 상태와 남은 확인

수정 전 실제 GET200 **14:34:16.869Z**, title·game:null·360×728/DPR2·loaded/style1792418469886·pendingnull. 수정 후 두 번 GET400으로 ‘Studio 창에서 현재 장면을 받지 못했습니다’가 나왔다. 실제4319 서버의 `__live/status`는 GET200·building/queued false이지만, 이것은 **사용자가 열린 화면에 새 코드를 적용했다는 증거가 아니다**. 최종 현재 화면 보존/loaded/pending/배지 상태는 재확인하지 못했다.
