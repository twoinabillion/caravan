# Player01 — 문자 그대로 읽는 신중한 입문자

첫 실행 하나로 `storyDone=true`, `ending=story_done`, `method=core_transfer`까지 마쳤다. 확정한 신규 제품 버그·서사 모순은 0건이다. 선택 문구를 문자 그대로 읽는 입장에서 의견 후보 2건을 따로 남겼으며, 기존 보고 대조 전이므로 신규 결함 수에 합산하지 않았다.

## 사전 정책과 실행

`policy.cjs`에 먼저 성향을 선언하고 seed `202001`, `pack=fuel`, `reloadAfterChoice=true`로 `run(config,'attempt01')`을 실행했다. 기존 정책을 import하거나 복사하지 않았다. 선택은 현재 공개된 질문·확인·읽기·대화 문구를 우선하며 위협·강탈·공격을 피했다. 이동은 현재 메인 navigation의 공개 목표까지 이어지는 경로를 따랐다. 물자 마련은 실제 거래와 `status.ok`인 모든 현장 행동을 대상으로 했고, 현장 일 이름 정규식이나 임의 탐색 횟수 제한은 쓰지 않았다. 목표 물자량은 출발의 추가 필수조건이 아니었다. 모집이나 사이드 미션을 별도로 찾아가지 않았다.

한계도 있다. 질문/안전 선호는 단순한 공개 label 점수이며, 장면 전체 의미를 이해하는 인간 입문자는 아니다. `route_mid_fork`에서는 ‘서쪽은 안전’이라는 본문보다 동점 선택지의 앞 순서를 따르며 동쪽 능선길을 택했다. 이 선택은 신중함을 완전하게 구현하지 못한 정책 한계다. 정책 선언에는 예보를 근거로 삼는다고 적었으나 실제 decide는 `check.ok`와 공개 경로 거리를 사용했고 `forecast.shortage`를 행동에 반영하지 않았다. 아래의 연료 고갈을 제품의 잘못으로 돌리지 않는다. 성공한 실행을 더 좋은 자원 결과로 바꾸려고 재시도하지 않았다.

수정 재시도·사망·실행 한도·예외는 없었다. 최종 자원은 연료 31.742L, 물 10, 식량 4, 고철 2, 차체 89.66%, 피로 31.82였다. 동료는 처음부터 끝까지 0명이었다. 결과가 서술한 최종 귀환은 수원 중계소이나 엔진의 종료 시점 위치/시계는 서울 D5 14:54다. 종료 후 서사와 이동 시뮬레이션의 층위를 구별하며 이를 이동 누락 버그로 단정하지 않았다.

## 실제 여정과 전편 검토

부산 → 양산 → 밀양 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울. 이동 13회, drive 기록 28회, 탐색 9회, 실제 거래 10회, 현장 행동 3회, 야영 4회였다. 과거 coverage와 비교한 새로운 event-choice 조합은 0개다. 새 성향·새 seed의 독립 실행이지, 미관측 분기를 새로 찾았다는 뜻은 아니다.

전체 53개 선택을 순서대로 진입 본문 → visible/enabled를 포함한 전체 공개 선택지 → 실제 선택 → 결과 → 전후 시간·자원·명단 순으로 읽었다. 원문과 전후 상태는 `attempt01/choices-readable.txt`에 모두 보존했다. 키워드 검색만으로 전편을 읽었다고 판단하지 않았다.

## 생존, 정책 실수와 제품 판단

청주 출발 trace95의 공개 예보는 연료 6L 필요·3L 부족, 평택 출발 trace117은 5L 필요·2L 부족을 표시했다. 정책이 이를 무시하고 `check.ok`만 보고 출발했기 때문에 각각 trace97,122의 고갈 구제를 밟았다. 두 출발점의 `stl`은 null이었다. 구제를 통해 실제 연료를 얻었고, 수원 도착 뒤 물·식량을 구매하고 묽은 죽/숙박으로 밤을 넘겼다. 다음 날 `북문 망루 교대`, `성문 평형추`, 공개 해금된 `성문 추 안쪽 통행패`를 실제 가용 행동으로 수행해 고철을 얻고 재보급했다. 노동 지급을 임의 주입하지 않았다.

정책 오류/불완전성은 위의 예보 미반영 1종과 성향 구현의 경로 동점 처리 1종이다. 실패 시도로 이어지지 않았지만 한계로 남긴다. 결과/성공률을 먼저 읽어 더 유리한 정책으로 바꾸지 않았다. 해당 사건의 소스는 실행과 전편 검토를 끝낸 뒤 후보 확인에만 읽었다. 현재 서사/지급과 예전 paid receipt를 혼동하지 않았다. raw `main` 내용을 실제 목표 공책 화면으로 간주하지 않았다.

의견 2건의 정식 필드는 `findings.json`에 있다. 확정 버그 0, 확정 모순 0이다. O01은 선택 비용의 사전 비교 정보, O02는 선택 label이 포괄하는 의도 범위에 관한 의견이다. 현재 화면에서 별도 안내가 있는지 보지 못했으므로 버튼/가시성 문제로 확정하지 않았다.

## 저장·재생과 검수 한계

53개 선택 모두 paid-result reload 기록이 있고 `loaded=true`, `replayed=true`, `applied=false`였다. 공개 snap의 before/after가 모두 같았다. 마지막 선택 trace178과 재생 trace179는 최종 결과를 읽는 단계이므로 아직 ended=false였고, 이어지는 어댑터의 결과 종료 후 summary/격리 save에서 ended=true·endKind=story_done·story_done 플래그를 확인했다. 마지막 결과 텍스트의 SESSION 표기도 직접 확인했다. 이 검증은 실제 Continue 버튼, 실제 reader cursor, 일반 취소/뒤로 및 브라우저 새로고침 검수가 아니다.

실제 소스 엔진을 Node VM과 격리 메모리 저장으로 실행했다. 사용자 저장, Studio, 실제 브라우저, 서버, 적용 배지는 조작하지 않았다. presentation/audio/타이머는 어댑터가 대체하며 이동은 엔진 tick으로 진행하고 서울 단계도 어댑터가 진입시킨다. 지급 결과 재생 뒤 후속 장면을 닫고 다음 단계로 가는 동작도 어댑터가 처리한다. earned perk는 기본 첫 선택을 자동 처리하는 설계이나 이번에는 동료가 없어 발생하지 않았다. 도로 발견/감속/정지의 실제 시간, 사람의 읽기 반응, 키보드·터치, 시각·크롭·클리핑·음성·모든 분기·실제 배포 환경은 검수하지 않았다.
