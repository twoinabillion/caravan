# player05 — 동해안 지도·풍경·공동체 탐험가

두 번째 시도에서 동해안을 실제로 돌고 본편과 후일담을 끝냈다. seed는 두 시도 모두 202005다. 첫 사망도 그대로 보존했다. 생산 코드나 다른 담당자 산출물은 바꾸지 않았다.

## 정책과 실행

첫 실행 전에 독립적으로 작성한 `policy.cjs`는 바다와 지도, 길가 사람들의 생활을 궁금해하는 성향이다. 공개 지도에 있는 대구 시장에서 준비한 뒤 경주·포항·강릉·속초를 찾아가고, 이후 공책의 본편으로 돌아오기로 했다. 묻기·살피기·도움과 동행을 선호하고, 선택의 결과표·확률·보상표를 읽어 점수를 정하지 않았다. 정착지 행동은 이름으로 노동 목록을 제한하지 않고 모든 `status.ok`를 고려했다. 그래서 국수 좌판도 현장 행동으로 실행됐으며, 이 행동은 실제로 고철을 버는 일이 아니라 지불하는 체험이었다.

공개된 모집 부탁을 따라 민지를 울산에서 돕고, 강우의 대구 경비 인계를 마친 뒤 구미에서 합류했다. 현재 본편·모집 목적지의 탐색에는 임의의 총횟수 제한을 두지 않았다. 일반 새 정차점은 한 번 살피는 기본 취향이었고, 연쇄 장면·본편 회복·모집 단계는 실제 엔진이 열었다. 엔딩을 직접 호출하거나 상태·자원·인물·아이템·확률을 주입하지 않았다.

| attempt01 | D83 대구, `ending=thirst`, `storyDone=false` | 26 / 460 | 238km, 민지 합류 후 대구에서 보급 정책이 반복됨 |
| attempt02 | D12, `ending=story_done`, `storyDone=true`, `method=core_transfer` | 92 / 368 | 830km, 민지·강우와 서울 도착 및 최종 후일담 완료 |

완주 시도 n361에서 공개된 최종 선택 중 ‘집행권을 저항 연대망에 넘긴다’를 골랐다. 코어 보존은 감시 근무 인원 2/3으로 비활성화되어 있었다. n363 남산의 밤, n365 상행 연결 차단을 거쳤고, n367 `seoul_session_reset` 결과에서 부산 하진과 통화한 뒤 수원 외곽 엄마에게 돌아가 할아버지 이야기를 시작했다. 마지막 문장은 `〔 서울까지 400km · SESSION 1 END 〕`다. n368의 유료 결과 재생 확인 뒤 엔진의 지연된 종료가 처리됐고 summary/save에서 본편 완료가 확인된다. 결과를 읽는 동안의 trace after.ended=false는 최종 결과를 먼저 보존하는 지연 종료 단계이며, 이것을 미완주로 판정하지 않았다.

## 실제 여정과 선택 검토

완주 이동 순서는 부산 → 양산 → 밀양 → 양산 → 울산 → 양산 → 밀양 → 대구 → 구미 → 대구 → 경주 → 포항 → 강릉 → 속초 → 강릉 → 대관령 → 원주 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울이다. 첫 대구·구미 왕복은 강우 모집의 공개 부탁을 따른 이동이다. 동해안 일주 뒤에는 내륙으로 돌아와 북부 기록 회복과 공책의 본편을 따라갔다.

두 시도의 모든 실제 선택 118개를 trace 순서대로 읽었다. 각 진입문·모든 선택지의 문구/힌트/표시·활성 상태·고른 선택·전체 결과·시간/연료/식량/물/고철/차체/피로/아이템/동료 명단 전후를 함께 비교했다. 키워드 검색만으로 전체 검토를 대신하지 않았다. attempt01은 앞 13개와 뒤 13개, attempt02는 1–16 / 17–32 / 33–48 / 49–64 / 65–80 / 81–92 순으로 펼쳐 읽었다. 아래는 연결에 대한 검토 메모다.

- 오프닝의 새 부품 수리 → 이름 소개 → 하진의 허락을 받은 이름 기록 → 계기판 배선 표시 → 열쇠 위탁 → 출발은 실제 지불·이후 회상과 이어졌다. 선택한 이름 ‘바다길’도 소개 결과에 유지됐다.
- 양산 스캔을 끝까지 받은 기록, 부모님의 다음 차와 두 작업선, 부모님 영상의 분류 화면 보존, 북부 연락소에서 찾은 분리 절차 두 장, 세 당사자의 정정·서명, 명령 원본과 아빠의 마지막 17분, 엄마의 최근 표식과 재회가 최종 검증키·인간 확인 절차로 이어졌다. 코어의 가족 이송 명령 작성자 고백은 앞서 원본으로 확인한 뒤 나왔다.
- 민지는 임시 도르래로 진단기를 꺼낼 때 옆문 손상을 입었고, 한 구간을 더 간 뒤 자리를 골라 정식 합류했다. 강우는 후임 서연이 시장을 맡는 과정을 거친 뒤 구미에서 군장을 둘 자리를 골랐다. 마지막 결과 칩에는 이 두 합류 방식이 각각 돌아왔다. 기본 자동 퍼크 선택은 별도의 어댑터 동작이다.
- 울산 고래, 제빙 창고의 낮잠, 대구 막창, 구미 제면소, 경주 왕릉 소풍과 첨성대 별, 포항 과메기, 속초의 노인과 폐횟집, 강릉 병원, 대관령 위령비와 강우 반응, 원주의 낮은 목소리, 충주 수몰 마을을 실제로 관측했다. 경주 별자리는 밤, 위령비 반응은 실제 대관령 정차에서 열렸다. 강릉 병원 시간은 아래 별도 문제로 남겼다.
- 최종부는 실제로 연결한 해도·돔·산지기 세 거점의 응답과 강우의 보존 반대를 보여 줬다. 마지막 후일담은 엄마가 중계소에 남아 송신하던 선택, 감천 작업장 열쇠를 맡긴 선택을 이어받았다. 속초 노인의 질문을 전하는 선택지도 코어 앞에 실제로 보였지만, 정책은 함께 온 사람들을 가리켰다. 보인 모든 선택지를 실제로 실행한 것은 아니다.

## 발견·해석·취향

`findings.json`에는 독립적으로 확인 가능한 후보 두 건을 배열로 기록했다. `comp_brake`가 대구 정차 야영 뒤 새벽에 급브레이크를 서술하는 진입 문제, `gw_gangneung`가 한 시간 노동을 서술하고 시계는 0분 흐르는 모순이다. 둘 다 실제 관측 뒤 해당 사건과 소유 코드만 확인했다. 기존 감사 및 다른 담당자와의 중복 여부는 부모 에이전트의 대조 대상이다.

이 성향에서 좋았던 부분은 풍경이 단순 수집 대상으로 끝나지 않고 사람의 생활로 연결되는 순간이다. 경주의 옥수수와 별, 포항의 덤, 강릉의 벽돌, 원주의 낮은 인사가 서로 다른 지역으로 읽혔다. 속초 노인이 관리받지 않고 살아도 되느냐고 묻는 장면은 이후 집행권 결정과 직접 닿았다. 이는 텍스트를 읽은 에이전트의 취향 해석이지 인간 플레이어 재미 통계가 아니다.

반면 지역 장면을 충분히 읽은 뒤에도 본편 기록은 대부분 자동 연쇄로 회수되어, 이 정책에서는 기록을 찾아내는 수고보다 연이어 읽는 밀도가 크게 느껴졌다. 이는 진행 차단이나 전 분기 결함 판정이 아니다. 특히 실제 화면의 읽기 속도·페이지 길이·쉬는 간격을 확인하지 않았으므로 UI의 피로도 문제라고 단정할 수 없다.

## 첫 실패의 정책 오류와 보정

첫 시도는 ‘장거리 준비’를 연료 100 / 식량·물 각각 34라는 장보기 조건으로 만들었다. 대구 탱크는 실제 95에서 더 늘지 않았고 물은 28/28에서 거절됐다. 포화 표시는 장소별로 영구 유지되어, 물이 줄어든 뒤에도 재구매가 막혔다. 식량 목표 34를 채우려는 동안 하루 5 고철의 반복 교대 삯보다 아침·점심 소모가 커졌는데도 가용 현장 행동이 없어지면 곧바로 다음 날까지 야영했다. 식량에 먼저 돈을 쓰고 물을 사지 못하는 우선순위도 겹쳤다. D83 사망은 이 자동 정책의 고집과 공급 루프가 만든 결과다. 일반적인 인간 생존율이나 대구 경제의 필연적 막힘으로 해석하지 않는다.

`retry-policy.cjs`에서는 같은 seed·성격·서사 선택 선호를 유지했다. 장거리 목표를 85 / 14 / 16으로 낮추고, 긴급 식수·식량을 먼저 샀다. 포화 표시는 실제 재고가 줄면 다시 거래를 허용했다. 현재 장터의 가용 행동을 다 쓰면 탐색·이동으로 돌아가며 끝없이 다음 날 노동을 기다리지 않았다. 실제 부족 예보를 읽고 보급 가능한 공개 경로를 우선하되, 이를 모든 정상 이동을 영구 금지하는 별도 하드 게이트로 쓰지 않았다. 경로 위험이 커지면 관광을 접고 본편 방향으로 돌아갈 수도 있게 했다. 결과적으로 네 동해안 목표를 모두 방문하고 완료했으며, 보정에 미래 결과나 추가 자원을 사용하지 않았다.

## 저장·재생과 한계

`reloadAfterChoice=true`로 두 시도 118개 선택 모두에서 격리 메모리 저장→실제 loader→동일 유료 결과 재생을 실행했다. 118건 모두 loaded/replayed=true, applied=false였고, 기록된 공개 상태 before/after는 같았다. 실제 브라우저 새로고침이나 Continue 버튼·읽기 커서·툴 복원·입력/취소 검수는 아니다. 별도 reloadBeforeChoice는 실행하지 않았다.

이 실행은 실제 소스 엔진을 Node VM과 격리 저장에서 돌린 자동 정책 플레이다. 브라우저·Studio·실제 사용자 저장·서버·적용 배지를 조작하지 않았다. 화면·클리핑·크롭·인물 그림·접근성·터치/키보드·오디오·연출·실제 읽기 반응·모든 분기는 검증하지 않았다. UI·오디오 표시 스텁, 접근/도착 타이머 대체, 획득 퍼크의 기본 첫 선택, 모집 제안의 자동 수락 등 어댑터 한계가 있다.

절차상 한계도 있다. 실행 전 공개 지도 정의의 위치를 찾는 첫 `rg`를 03 데이터 파일 전체에 넓게 걸어, 검색 출력에 `gw_gangneung`와 `gw_sokcho`의 결과 일부가 섞였다. 이후에는 D.nodes/D.edges와 공개 예보·행동 API로 범위를 좁혔다. 작성자로서 그 결과를 선택 점수나 재시도 보정에 직접 사용하지 않았다고 진술할 수 있지만, 영향이 완전히 없었다고 증명할 수는 없다. 따라서 완전한 블라인드 감사라고 부르지 않는다. 두 발견의 실제 trace 관측과 후속 소스 확인은 이 제한과 분리하여 제시했다.
