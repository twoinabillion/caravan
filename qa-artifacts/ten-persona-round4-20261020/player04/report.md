# player04 — 회의적인 시민권·증거 중심 조사자

같은 시드202004로 두 번 진행했다. 첫 시도는 정책의 보급 판단 실패로 사망했고, 두 번째는 실제 본편 마지막 후일담까지 완료했다. 이 보고서는 소스 엔진을 격리 저장으로 실행한 자동 정책 플레이 기록이다. 인간 플레이·브라우저·시각·청취·실제 입력 검수가 아니다.

## 성격과 선택 원칙

실행 전에 `policy.cjs`에 성격·공개 정보 기준·`visitGoals=[]`를 선언했다. 현재 보여 주는 기록, 문서, 원본 대조, 시민의 동의와 공개 책임을 우선했다. 숨은 결과·확률·보상·미래 대사로 선택을 최적화하지 않았다. 예고된 본편 목적지를 따라가고, 실제 시장 거래·가용 현장 일·야영으로 유지했다. 정착지의 작업은 `status.ok`를 우선해 모두 후보로 두었다. 모집은 실제 빈 좌석이 있을 때 진행했다.

초기 정책은 `policy-attempt01.cjs`, 보정 후 정책은 `policy.cjs`에 남아 있다. 두 시도 모두 `reloadAfterChoice=true`, 동일 seed202004, 동일 sourceHash `12658023a96f506e4204db5dc0891255cddd5a1880190163b38b4f636114872c`다. 원본 trace/summary/save/coverage는 각 attempt 폴더에 그대로 보존했다.

첫 시도는 청주에서 천안으로 가는 즉시 구간을 감당할 수 있다는 이유만으로 출발했다. trace144의 공개 예측은 연료 여유0L, 보급 점수38이었다. 대전 방향은 연료 여유1L, 보급 점수82였지만 정책이 이를 사용하지 않았다. 천안에0.92844L로 도착한 뒤 온전한 다음 구간을 갈 수 없어 수색과 야영만 반복했고 물이 떨어졌다. 이는 자동 정책의 계획 실패이며 피할 수 없는 게임 소프트락으로 판정하지 않았다.

보정은 공개 관측만 사용했다. 연료 여유가 적거나 식수·식량이 적을 때 감당 가능한 보급 방향을 우선하고, 시장에서 일반 연료 재고를45L까지 구매하도록 했다. 연료가 실제 구간 요구량을 충족하면 별도 예비분 때문에 영구적으로 막지 않았다. 성격·서사 선택 기준·시드는 바꾸지 않았다. 세 번째 시도는 하지 않았다. 자세한 변경 근거는 `retry-notes.md`에 있다.

## 실제 여정과 중요한 결정

완료 경로는 부산 → 양산 → 밀양 → 양산 → 울산 → 양산 → 밀양 → 대구 → 구미 → 김천 → 상주 → 문경 → 충주 → 청주 → 천안 → 평택 → 수원 → 서울이다. 마지막 결정 전 실제 준비 복귀로 수원에 내려왔다가 서울로 다시 갔다. 최종 누적 주행은596km다. 동료는 민지 한 명, 구매한 차량 확장은 없었다. 현장 행동9회, 거래15회, 야영4회, 탐색6회였다. 배달/조달 게시판 계약은 실제로 수락하지 않았다.

부산에서 가족 이름을 허락받아 적었고, 양산에서 스캔을 끝까지 받아 발신 기록을 복사했다. 권위의 외형을 갖춘 임시 행정소에서는 꺼진 태블릿을 지적했다. 부모님의 갈라진 운행표와 증언 전달망을 따라가며 발표 연습 영상의 마지막 문장을 복원했다. 민지의 진단기는 도르래로 회수했고, 능선의 네 사람과 약 상자는 사람 줄과 수레 줄을 나눠 올렸다.

청주에서는 원본을 보관망과 대조하고 검증키의 빠진 절차 두 장을 맞췄다. 세 당사자가 직접 고친 증언 사본을 맡은 뒤 천안에서 명령 원본과 대조했다. 평택에서는 남산 실패와 아빠의 마지막17분을 읽었다. 수원에서 엄마와 재회한 뒤 기록을 여섯 주파수로 보내 달라고 했고, 세 거점의 실제 수락을 되읽어 기록했다.

남산에서 잠길 기록 창구를 먼저 확인했다. 최종 결정을 처음 봤을 때 기록을 열어 두는 보존안은 근무 가능 동료1/3이라 막혀 있었다. trace223에서 실제 `prepare-finale`를 선택해 수원으로 돌아갔다. 이 정책에는 추가 좌석·모집을 연결하는 준비 계획이 없어 바로 재진입했고, 두 번째 결정에서는 가용한 연대망 인계를 선택했다. 이 불필요한 왕복은 정책 한계로 남긴다. 보존 엔딩을 만들려고 동료나 조건을 주입하지 않았다.

최종 인계 결과는 의료·급수 유지와 거점들의 도로/물차 우선순위 다툼을 함께 보여 줬다. 이어 남산의 밤, 상위 실행기 공개, 상행 연결 해제, 새 세션을 모두 읽었다. 부산 부두에 취소 소식을 전하고 하진에게 귀환 여부를 결정하게 한 뒤, 수원 중계소의 엄마에게 할아버지 이야기를 하는 마지막 장면까지 이어졌다.

## 전편 검토와 판정

두 시도의 실제 선택133개를 각각 처음부터 순서대로 읽었다. 매 선택마다 진입문, 관측에 들어온 전체 선택지와 visible/enabled/요구조건, 고른 선택, 전문 결과, 자원칩, 전후 시간·자원·아이템·명단을 연결해서 확인했다. 별도의 준비 복귀 결정1개도 같은 방식으로 읽었다. `full-review.json`은 이 전체 순서와 원문을 모은 검토용 파생 자료다. 본편·모집·능선 구조·야영·소규모 대화·최종 처분·후일담을 모두 포함한다.

확정된 진행 차단이나 자원 중복 지급은 발견하지 못했다. `findings.json`에는 낮은 심각도의 서사 연속성 후보1건을 남겼다. 첫 시도 day12의 민지 반복 야영 대화가8일간 주행 없이 같은 천안에 머문 상태에서도 '오늘 지나온 길'과 함께 덜컹거림을 기억했다. 실제 발생 뒤 해당 문구와 선택 투영 소유자만 소스로 확인했다. 로컬 탐색을 '길'로 읽을 여지도 있어 단정적인 중대 버그로 올리지 않았다. 주 디렉터의 기존 이슈 대조가 필요하다.

취향으로는, 빈칸을 추측으로 메우지 않는 면사무소 기록과 당사자가 직접 고치는 증언 장면이 이 성향의 동기를 잘 이어 줬다. 아빠의 정비 기록 → 엄마의 송신 역할 → 명령 원본 대조 → 인간 확인이라는 연결도 이해할 수 있었다. 거점 인계 뒤 다툼까지 남겨 둔 결과는 공개 책임을 선택하는 방향과 맞았다. 이는 이 자동 정책을 읽은 해석이며 실제 인간의 선호나 재미 통계가 아니다.

정책이 성격을 완벽하게 연기한 것도 아니다. `salvage_claim`에서는 여러 라벨이 같은 점수라 첫 선택인 회수료 지불을 했다. 본문을 깊게 추론하는 인간이라면 다른 입구를 찾았을 수 있다. 준비 복귀 뒤 곧바로 돌아온 것도 자동화의 한계다. 첫 사망·이 선택들·재시도 결과를 제품 결함이나 인간 완주율로 계산하지 않는다.

## 저장·재생 범위와 미검증

실제 선택 뒤133번 모두 엔진 save/load를 실행했고, 같은 유료 결과 재생이 loaded=true/replayed=true/applied=false였다. 각 재생의 전후 스냅샷도 같았다. `build-review.cjs`가 이를 다시 대조한다. 마지막 선택도 trace236에서 효과 재적용 없이 재생했으며, 최종 저장은 flags.story_done=true, ended=true, endKind=story_done이다. 마지막 결과 직후 trace 스냅샷의 ended=false는 후일담 결과를 읽은 뒤 종료하는 엔진 절차 중간 상태이며, 이를 미완주로 오해하지 않았다.

이 검사는 실제 UI Continue, 취소/뒤로 버튼, 페이지 읽기 커서, 포커스, 실제 브라우저 새로고침을 검수하지 않았다. `prepare-finale`는 실제 엔진 복귀 동작이지만 UI 버튼을 눌렀다는 증거는 아니다. `camp-later`는 정책에서 지원했으나 이번 두 실행에서는 사용하지 않았다. `camp-meal`, `camp-repair`, 일반 reload, 게시판/계약 경로도 별도 실행하지 않았다.

어댑터는 화면/소리/접근 애니메이션/타이머를 대체하고, 공개된 획득 perk의 기본 첫 항목을 자동 선택한다. 추적의 숨은 선택지 표시는 엔진 reqVisible 결과이므로 이를 화면에서 봤다고 주장하지 않는다. `main`과 navigation은 엔진 관측이며 공책 실제 문구 투영과 같다는 보장도 없다. 클리핑·크롭·버튼 가시성·화자 초상·음성의 품질은 전혀 확인하지 않았다. 실제 Studio 저장·브라우저·서버·생산 파일은 건드리지 않았다.
