# 승인 이름 인사 — 구현과 검증

Sang이 Studio의 `name-introduction-v1`을 보고 ‘굿굿’으로 승인했다. 이 기록은 이전 고정 이름 초안이 아니라 실제 소스 연결 범위를 설명한다.

## 실제 연결

- 준비에서 이름 필드를 제거했다. 짐 선택·합계·이름이 들어 있던 구형 준비의 이름/짐 복원은 보존했다. 신규 여정은 이름 미정으로 시작한다.
- `D.openingNameIntroduction`은 원래 다섯 사건 배열 **밖**의 짧은 끼움 사건이다. 새 `opening.version:2`에서만 세 버스 수리 성공 결과 뒤, `opening_failed_appeal` 앞에 열린다. 이전 숫자 step 커서는 밀리지 않는다.
- `S.opening.nameDraft`는 미확정 입력이며 `S.name`을 바꾸지 않는다. 이름을 명시적으로 말하면 정규화한 이름과 지급 없는 결과를 같은 opening 소유자에 저장한다. 응답은 그 결과의 이름을 읽는다. 결과를 넘겨야 기존 민원 사건으로 이어진다.
- 공백/보이지 않는 제어문자/8자 초과는 같은 자리에서 안내한다. NFC 정규화 뒤 Unicode 코드포인트로 8자를 검사한다. 입력의 임시 한도64는 IME/분해형 입력을 잘라내지 않기 위한 상한이지 최종 이름 길이가 아니다. 이름은 마크업으로 실행하지 않고 escape한다.
- IME 조합·229·누른 채 반복·묵시적 form submit은 확정하지 않는다. 분리된 옛 폼·다른 여정·다른 reader의 늦은 핸들러도 쓰지 않는다. 앞 대사/기록 복귀 때 입력을 복원하고, 키보드 리사이즈 중 집중된 입력 DOM/캐럿은 유지한다.
- 이름 인사는 시간·물자·보상·게임 RNG를 소비하지 않는다. 수리 결과·비용은 다시 적용하지 않는다. v1의 기존 이름/미정 이름 저장과 이미 이름이 정해진 신규 시작은 새 질문을 끼우지 않는다. 저장 전체 schema는9를 유지한다.
- 기존 프롤로그에는 수리·민원·출발까지 이미 있다. 그 끝에 실제 작업장을 붙이면 사건을 중복하므로, 준비의 버튼을 **역사 프롤로그 미리 읽기**로 명확히 했다. 전체/요약 뒤 같은 준비로 돌아가며 여정 생성·현재 저장 교체는 하지 않는다. 실제 시작은 준비 확정만 소유한다. 기존 메뉴 재시작과 직접 엔진 full/summary/skip 계약은 그대로다.

## 소유자

- `src/02-dom.html`: 준비 이름 칸 제거/미리 읽기 라벨.
- `src/03-data.js`: 도윤의 질문, 이름별 짧은 응답, 원래 민원 장면 유지.
- `src/04a-engine-core.js`: opening v2의 opt-in 상태·draft/확정·reload·legacy 보존.
- `src/07-ui.js`: 기존 사건 reader의 입력·확정·앞 대사·프롤로그 preview 경로.
- `src/01-style.html`의 `passenger-story-reader`: 입력 소유자 추가. 전역 input/기존 composer/모든 !important 경쟁 규칙을 검색한 뒤 이 소유자 안에서만 연결했다. 구형 준비 CSS는 현재 mounted 화면 보존을 위해 남긴다. 그림·장면 높이·도로 renderer·새 raster는 변경하지 않았다.

## 실제 상태와 남은 검수

- 전: 실제4327 GET **12:36:41Z**, `name/packing`, game:null, 360×728, scroll0, loaded/style `1792237587186`, pending:null. 기존 준비 이름 칸이 있었다.
- 후: **12:50:17Z**, 같은 `name/packing`, game:null, 360×728, scroll0. loaded/style는 **1792241150760**으로 바뀌었고 준비 이름 칸은 없었다. 최신 보완은 **pending1792241280355**, applying:false. 작업 중 사용자의 실제 미리보기에 새 버전이 로드됐지만 에이전트가 강제 적용/새로고침하지 않았다.
- 이전 실제4319 Chrome `ERR_BLOCKED_BY_CLIENT` 및 다운로드 권한 미해결 상태를 재시도/다른 주소·브라우저로 우회하지 않았다. 새 게임을 사용자 현재 상태로 대체하지 않았다.
- **새 입력 UI의 실제 crop·텍스트/버튼 배치·모바일 키보드·터치·실제 새로고침은 미검수**다. 기존 Studio 고정 예시 캡처를 새 실제 입력의 증거로 쓰지 않는다. 최종 배지 적용 뒤 동일 준비에서 자연스럽게 수리까지 진행하며 확인해야 한다.
- 사용자 저장·게임 진행·서버·설치·배포·commit/push 조작 없음. UI/대화/입력/저장 지침에 따라 새 상태와 레거시를 분리하고, 입력을 게임 RNG와 비용에서 제외했다.
