# 일반 자원 초반 흐름 검수 — 2026-10-11

## 결론

실제 활성 서버 `http://127.0.0.1:4319/`의 별도 Chromium 컨텍스트에서 오프닝 → 부산 → 양산 → 밀양과 밀양 야영을 검사했다. 일반 자원이 실제로 소모됐고, 검사한 경로에는 막힌 다음 행동·취소 비용·재접속 중복 지급이 없었다. 이번 결과만으로 밸런스를 바꿀 근거는 없어 게임 소스는 수정하지 않았다. 추가한 것은 재현 가능한 검사 도구와 기록이다.

이는 **자동 조작 경로 검사**다. 실제 사람이 한 시간 동안 읽으며 플레이한 결과, 재미·난이도 승인, 실기기 성능·청취 검수가 아니다. 대사 버튼을 하나씩 눌렀지만 턴당 1.5초 대기는 사람의 독해 시간과 다르다. 자원 지급·시간 가속·대사 생략·결과를 보고 선택하는 정책은 사용하지 않았다.

C는 55개 조작/154.58초, D는 21개/55.02초, 야영은 19개/13.75초다. 세 성공 실행에서 JS 페이지 오류는 없었다. C와 D는 선택과 무작위 사건도 달라 탐색 횟수만 통제한 A/B 비교가 아니다. 늦은 도착 화면에서 상점 휴무를 직접 확인했다. 반복 탐색의 시간·피로 부담이 다음 행동에 영향을 준다는 관측이며, 최적 경로나 적정 난이도의 증명은 아니다.

- 양산·밀양 정차 후 재접속: 위치·시각·자원·동료·선택 수·소비 사건 수 보존.
- 행동 선택창 Escape/선택만 하기: 시각·자원 변화 없음.
- 야영 열기·차 안 둘러보기·닫기: 날짜·시각·자원 변화 없음.
- 식사: 식량 1/물 1, 피로 6 감소. 차량 점검: 부품 1, 차체는 취침 전 그대로.
- 준비 후 닫기·재접속·다시 열기: 식사와 점검 완료 버튼이 비활성화된 채 유지.
- 첫 밀양 숙박의 보급과 아침 배급을 합친 결과: 취침 전 대비 식량 동일/물 +1, 차체 82→94, DAY 2 06:30/피로 0. 이후 재접속과 다음 출발 버튼 확인.

## 재현과 증거

```sh
node --test tools/test-first-hour-runner.cjs
python3 tools/qa-first-hour.py --url 'http://127.0.0.1:4319/game?caravan-live=1' --output /private/tmp/caravan-first-hour-new-run --choice-index 0 --explorations 1
python3 tools/qa-first-hour.py --url 'http://127.0.0.1:4319/game?caravan-live=1' --output /private/tmp/caravan-camp-new-run --checkpoint qa-artifacts/first-hour-2026-10-11/route-d/save.json --camp-only
```

항상 새로운 출력 경로를 사용한다. `rev`/`infinite-resources` URL은 거절한다. 체크포인트는 새 컨텍스트에 한 번만 넣는 실제 획득 저장이며 사용자 컨텍스트는 열거나 리셋하지 않는다. Node 4개 검사는 검사 도구의 정적 계약 검사이고 게임 동작 증거는 별도 브라우저 기록이다.

[증거 폴더](../qa-artifacts/first-hour-2026-10-11/)에 성공 실행의 원본 JSON/저장과 선택한 캡처를 보존했다. 원본 JSON의 `captures.file` 전체 목록은 각 실행의 `/private/tmp/caravan-first-hour-20261011-{c,d,camp}`에 있다. 모든 이미지가 증거 폴더로 복사된 것은 아니다. D의 선행 저장은 `calibration-b/save.json`이다. JSON의 체크포인트 절대 경로는 당시 실행 경로를 뜻한다.

초기 A/B 검사는 첫 로드가 추가하는 기술 플래그 `recruit_migration_v2` 때문에 엄격한 플래그 동일성 검사에서 실패했다. 두 실패 보고서와 B 저장을 보존했다. 게임을 고치지 않고, 기존 참 플래그 전부 보존 + 이 기술 플래그만 추가 가능하도록 검사기를 좁혀 C/D를 재검사했다. 다른 새 플래그나 선택 수·사용 사건 수 변화를 허용하지 않는다. 별도 기존 QA의 80MB HTML 중계 시도는 `TargetClosedError`로 진입 전에 실패해 직접 활성 서버로 접속했다. 이를 게임 크래시나 성능 측정으로 분류하지 않는다.

해당 실행 때 로컬 생성 HTML은 79,648,471바이트/SHA256 `fac5e691ab5c6c1c5360cdbc22589de56aba303e35a6a9915cfeb10130b26f8f`였다. 성공 실행은 실제 서버 URL로 접속했지만 응답 전체 바이트 해시를 별도로 검증하지 않았으므로 로컬 해시를 서버 응답 해시로 주장하지 않는다.

후속 첫 동료/일반 구매 검사는 [별도 기록](first-companion-review.md)으로 이어졌다. 아래 미검수 목록은 이 초반 경로 실행 당시의 범위를 뜻한다.

시작 조회 01:46:42UTC: 사용자 화면은 양산 DAY 1 11:22/min682.321, 이벤트 없음, 360×728/DPR2, 연료42/물10/식량14/고철22/차체82, 동료 없음. loaded/style1791680813582, pendingnull. 종료 동일 runId GET은 HTTP400으로 거절돼 종료 상태 보존을 재인증하지 못했다. 실제 사용자 창의 시각 검수는 하지 못했다. 관찰한 이미지는 별도 유한 자원 경로의 캡처이며 사용자 현재 화면으로 대체하지 않는다. 실제 적용·새로고침·진행·새 서버 시작 없음.

다음 우선순위는 처음 보는 플레이어의 30~60분 관찰이다. 다음 목적지를 스스로 찾는지, 탐색을 더 할지 쉬고 갈지 예측하는지, 첫 단서를 자기 말로 설명하는지를 본다. 동료 첫 합류, 부족한 자원에서의 복구, 야외 야영 사건, 비·차 안 음향의 주관적 청취, 전투, 후반 이야기는 이번 경로에서 검수하지 않았다. 낮 도로의 어두운 색감은 스타일 판단 후보이며 시간 계산 오류로 확정하지 않았다(13시에는 `darknessAt=0`, 천체는 해 분기).
