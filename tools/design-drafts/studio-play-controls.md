# Studio 플레이 테스트 도구 · 배치 초안

2026-09-27 Sang 요청: ‘최신 코드 적용’과 ‘처음부터 테스트’를 게임 화면 밖으로 옮기기. 처음에는 배치만 제안했으며, 이후 **“응응”으로 승인받아 구현했다.** 초안은 계속 게임/저장과 분리되어 있다.

## 디자인 계획

- 기존 Studio 색을 사용한다: 바탕 `#0b0c0e`, 도구 영역 `#15171b`, 경계 `#272a31`, 본문 `#f3f5f7`, 보조 `#8c929d`, 새 코드 강조 `#b8f34b`.
- 글꼴은 Studio의 시스템 한국어 고딕 대체 스택. 제목20, 도구 제목/버튼12, 안내11~13px. 게임 UI의 올리브/종이 재질과 혼합하지 않는다.
- 기기 설정 다음, 기기/게임 iframe 바깥에 ‘플레이 테스트’ 한 줄을 둔다. 새 코드 적용은 대기 중에만 강조하고 재시작은 중립색으로 분리한다. 좁은 Studio 패널에서는 제목/상태가 자연스럽게 줄바꿈된다.
- 기존 설정줄에 버튼을 계속 붙이는 안 대신 전용 줄로 나눠 기기 설정과 실행 조작을 구분한다. 게임 메뉴로 숨기는 안은 플레이 UI에 개발 도구가 남으므로 제외했다. ‘처음부터 테스트’는 기존 재시작 확인 절차를 유지한다.

```text
Studio: 게임 미리보기 / STOP 등 기존 도구
기기 · 화면 모드 · 디자인 초안
플레이 테스트                  새 코드 준비됨
[최신 코드 적용] [처음부터 테스트]
테스트 모드 · 자원 무제한
────────────────────────────────────────
            기기 / 게임 화면
```

## 소유권·향후 연결 범위

- 코드 적용은 `tools/dev-live.mjs`의 live shell 버튼, 재시작은 `src/02-dom.html`의 `intro-test-shortcut`과 `src/07-ui.js`의 `startIntroRestart()` 연결이 현재 소유한다.
- Studio에는 이미 `public/index.html`의 기기 설정과 `public/app.js`의 미리보기 연결이 있다. 승인 후 게임 명령을 이 바깥 도구줄로 전달하되 적용 완료/실패·새 코드 대기·동결 상태를 실제 값으로 표시해야 한다. 실제 서버 재시작이나 설치본 갱신은 그때 검증한다.
- 기존 자동 CSS 적용·의도적인 구조 적용·수동 저장 내보내기/가져오기를 보존한다. 확인 결과 기존 테스트 재시작에는 확인·자동 백업이 없었으므로 새 확인창을 붙인다. 같은 동작을 두 번 실행하는 버튼이나 두 번째 게임 iframe을 만들지 않는다. Studio 밖 단독 live 실행의 대체 조작도 빠뜨리지 않는다.

## 초안 범위

- 실제 장면의 논산/시각/추적3/5는 요청 당시 배치 참고값일 뿐이다. 풍경 대신 코드 개략도를 썼으며 현재 게임 화면을 캡처하거나 재현한 것이 아니다.
- radio/details만 사용한다. ‘최신 상태’/‘새 코드 있음’은 예시 전환, 두 버튼은 동작 설명만 펼친다. 실제 적용·초기화·네트워크·스크립트·게임 저장 접근 없음.
- Studio 디자인 초안 목록에 등록하며 선택은 요청 작성만 준비한다. 게임/Studio 런타임 코드를 수정하지 않는다.

## 구현 · 2026-09-27

- 승인 이후 Studio `public/play-controls.js`와 기존 index/styles/app 소유 블록에 구현. 실제 게임 내부의 버튼/CSS는 제거하고, live shell `tools/live-play-controls.mjs`가 기존 하나의 게임 iframe으로만 연결한다. 기기 viewport는 외부 도구줄과 별개이며 기존 기기 맞춤 배율을 사용한다.
- 새 코드/빌드/오류/자원 무한/재시작 가능 상태를 브리지에서 읽는다. parent window·loopback origin·연결 세션·증가하는 명령 순번 검증, 중복/바쁜 상태/STOP 차단. 연결 확인 후에만 단독 실행용 상단 도구줄을 숨긴다. 갤러리와 다른 프로젝트에는 Studio 버튼줄이 없다.
