# 상황에서 시작하는 UI — 2026-09-28 초안

Sang의 요청: 대화·사건·동료 화면이 같은 AI식 카드 모음처럼 느껴지지 않게, 이 게임과 상황에 맞는 여러 prototype을 만든다. 공책을 모든 곳에 복제하지 않는다. 게임 적용 전 Studio에서 논의한다.

## 먼저 정한 방향

화면이 설명하는 대상이 아니라 **지금 상혁이 하고 있는 일**을 중심에 둔다. 대화에서는 상대가 말하고, 옛 영상에서는 남겨진 말이 이어지고, 차 안에서는 함께 탄 사람이 자리를 차지한다. 생활의 구체적인 변화가 개인화를 담당한다. 장황한 속말을 새로 쓰거나 모든 행동을 감상적인 의미로 요약하지 않는다.

| 초안 | 중심 | 실제로 눌러 볼 흐름 |
| --- | --- | --- |
| `situated-talk.html` | 부품 천막에서 마주 보는 사람 | 질문 → 자기소개 → 부탁 → 수락/거절. 부품 분기의 성공 예시는 획득량을 바로 표시 |
| `situated-record.html` | 부모님이 남긴 영상의 마지막 장면 | 복원된 문장 펼침/접기 → 다음에 확인할 곳 → 주행 복귀 설명 |
| `situated-cabin.html` | 달구지 안에 함께 있는 사람 | 혼자/손님 상태 비교 → 약속 확인. 별도 야영 예시 → 15분 함께 듣기/취소 → 바뀐 생활 흔적 |

### 공통으로 남길 것

- 같은 본문 크기, 읽기 순서, 아래쪽 행동 영역, 44px 이상 조작, 명확한 돌아가기.
- 실제 비용·획득량은 결과 이후 바로 보인다. 미래 보상은 선택 전에 공개하지 않는다.
- 이야기의 큰 제목, 반복 상태 배지, 호감도 장식, 가짜 기기 UI, 미확인 거리와 미래 동료를 넣지 않는다.
- 모든 그림은 원래 비율을 유지한다. 사진 위에 작은 글씨를 얹거나 인물 얼굴을 잘라 슬롯을 채우지 않는다.
- 화면 길이는 내용에 맞춘다. 728px를 억지로 채우려고 본문과 복귀 버튼 사이에 빈 공간을 늘리지 않는다. 휴대전화 틀·가짜 하단 메뉴는 넣지 않는다.

### 달라질 것

- **대화:** 차가운 천막 풍경과 읽기 쉬운 어두운 바탕. 질문은 상혁의 말로, 다음 장면은 상대의 반응으로 이어진다. 실제 자기소개 분기에서 `소녀 → 민지`가 바뀐다. 두 선택은 같은 무게로 둔다.
- **영상:** 검은 영상 바탕과 부모님의 원래 그림. “결과/획득/기억됨/갱신” 덩어리를 없애고 복원 문장과 다음 행동을 나눈다. VHS·가짜 재생 시간·파형은 없다. 실제 음성 재생 기능을 약속하지 않는다.
- **차 안:** 기존 빈 조수석 파노라마는 혼자일 때만 쓴다. 손님이 있는 예시에서는 그 사람의 얼굴과 공구함에 관한 짧은 글이 자리를 차지한다. 공책은 약속을 확인할 때만 나온다. 야영 후에는 같은 자리의 한 문장이 실제 선택에 따라 달라진다.

## 자체 검토와 반영

검토 전에는 세 화면 모두 큰 사진 아래 설명과 버튼이 놓여 또 같은 틀로 보일 위험이 있었다. 대화는 짧은 턴과 분기, 영상은 한 번의 종료 화면과 다시 읽기, 차 안은 지속 상태와 사람에게 접근하는 화면으로 역할을 분리했다. 공책과 결과 카드는 복제하지 않았다.

Claude의 focused review: 이름 공개를 선택의 눈에 보이는 변화로 사용하고, 분위기 때문에 실제 획득량을 감추지 말 것. 두 가지 반영. “복원한 말을 끊긴 자리 안에서 읽기”도 반영하되 원래 문장을 고쳐 접합하지 않고 복원된 마지막 부분임을 명시했다. 거리 기반 약속은 현재 경로 거리 근거가 없으므로 N km를 만들어 넣지 않았다. 가방 숫자만 바꾸는 안도 무엇을 받았는지 놓치기 쉬워 바로 읽을 수 있는 한 줄로 대체했다.

- 대화는 `src/03-data.js`의 `meet_scrapyard` → `rq_minji_request`를 발췌한 별도 재현 예시다. 현재 저장을 이동시키지 않는다. 부품 분기는 확률 결과 중 성공 한 가지만 재현하며 이를 바깥 안내에 명시한다. 손상 결과까지 검증했다고 주장하지 않는다.

## 실행 경계 / 검수

독립 HTML/CSS. 스크립트·저장소·게임 함수·iframe·외부 통신 없음. native details와 fragment 링크만 사용한다. 돌아가기 이후 화면은 **복귀 동작 설명**이지 실시간 도로가 아니다. 큰 글씨도 시험 가능하다. Studio 초안 목록에 세 파일을 각각 등록한다. 선택은 요청 작성일 뿐 자동 적용이 아니다.

Product Design의 캡처 기반 시안 흐름은 실제 Studio 브라우저 접근 제한 때문에 수행하지 않았다. 사용자 요청과 저장소의 HTML 초안 흐름에 따라 game-director / frontend-design 방향으로 작업했다. 우회 접속·새 서버·새 게임 시작·래스터 mock 생성은 하지 않았다.

원본 자산 관찰과 정적 코드/링크/출처/대비 검사는 가능하지만 **Studio 화면 안의 시각 검수는 미완료**다. 320·360·480 폭, 큰 글씨, 키보드·터치, 끝 스크롤, 선택 후 초점 이동은 실제 화면 접근이 가능해지면 확인해야 한다. 소스의 정상 파싱을 시각 QA로 간주하지 않는다. 적용 전 Sang과 세 안을 논의하고, 선택한 화면만 게임에 구현한다.

## 승인 후 게임 코드 연결 — 2026-09-28

Sang의 “그럼 적용해줘봐”에 따라 세 초안을 게임 소스에 연결했다. 아래는 **구현·빌드 상태**이며, 위의 독립 초안 검수와 구분한다. 실제 화면 적용과 시각 QA는 아직 대기 중이다.

- 대화/영입, 복원 영상, 야영 대화를 각각 `talk` / `record` / `camp` 표면으로 분리했다. 전투와 인트로는 제외한다. 자기소개 전 민지는 `소녀`, 소개 뒤에는 기존 화자 상태에 따라 `민지`로 표시한다. 기존 턴·선택·확률·효과는 유지한다.
- 영상 헤더는 원래 출처인 `부모님의 발표 연습`. 복원 분기의 끝에 `마지막 문장까지 복원했다.`와 다시 읽기를 표시한다. 본문은 저장된 결과에서 가져오며 분류 화면 저장 분기나 다른 옛 결과에 복원 성공을 덧씌우지 않는다. 전체 대화·선택·결과는 상단 기록에서 다시 읽는다.
- 비전투 결과의 기록/지식/기억 알림을 `남겨 둔 기록`에 모았다. 자원·시간·손상·알 수 없는 다른 변화는 바로 표시한다. 다음 행동은 저장된 목표의 장소·조작·시간·기록 이름을 보존하되 갱신/진행 제목을 반복하지 않는다. 현 장면의 목표는 계속 수원이며, 검증키를 이미 꺼냈다고 표시하지 않는다.
- 동료 화면은 실제 손님/동료만 표시한다. 손님 민지에게 이름·얼굴·공구함·기존 야영 기억을 연결하고 겹치는 소개를 덜었다. 정식 동료의 이야기/능력 접근은 유지한다. 약속은 기존 사이드 미션으로 연결되고 닫기는 기존 오버레이 닫기 경로를 사용한다. 야영의 15분 비용과 취소·보류는 기존 엔진이 담당한다.
- `passenger-story-reader`와 기존 cabin/journey owner를 수정했다. 별도 final/lock 스타일은 추가하지 않았다. 새 색은 새 구조의 속성/클래스가 있을 때만 활성화된다. 선택지는 동일한 강조의 구분되는 바탕을 사용하며, 보상/닫기 단계에서만 황토색 주요 행동을 둔다. 새 래스터 생성·교체는 없다.
- 펼침 상태 두 개는 기존 presentation receipt에 boolean으로 저장한다. summary 클릭 시 즉시 저장하고 이전 장면의 지연 toggle은 무시한다. 현재 결과를 다시 불러와도 효과를 반복 적용하지 않는다.
