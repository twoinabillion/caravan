# 도윤과 첫 인사 — 이름 입력 초안

상태: 2026-10-17 Sang의 ‘굿굿’으로 시각 초안 승인. **실제 입력/저장 소스 연결·빌드 완료, 마지막 보완 적용 및 실제 입력 시각 검수 대기.** [구현·739개 검사·실제 적용 상태](../name-introduction-implementation-20261017.md).

## 승인 후 구현 계획

- 원래 다섯 사건 배열과 숫자 커서를 유지한다. 새 오프닝(version2)에서만 수리 다음에 이름 인사를 별도 끼움 사건으로 연다. 구버전/이미 정한 이름은 그대로 둔다.
- 기존 opening 소유자에 미확정 이름과 확정 결과를 저장한다. 입력 확정 전에는 실제 이름을 바꾸지 않는다. 민원 장면은 확정 결과의 명시적 다음 행동 뒤에 연다.
- 기존 페이지 읽기·자료/앞 대사·모달·CSS 소유자를 재사용한다. 입력은 기존 본문 아래 응답 영역, 확정은 하단 행동으로 배치하고 키보드 리사이즈에서 포커스를 유지한다.
- 긴 프롤로그는 현재 사건까지 이미 서술하므로, 그 뒤에 작업장 사건을 다시 붙이지 않는다. 준비에서 여는 버튼을 ‘미리 읽기’로 명확히 하고 전체/요약 읽기 뒤 같은 짐 선택으로 복귀한다. 실제 시작은 준비 확정에서만 하며 기존 재시작/직접 엔진 full·summary·skip 계약은 유지한다.
- 신규 엔진/실제 UI 핸들러 검사, 전체 회귀·빌드. 실제4319 차단이 풀리지 않았으므로 새 주소나 브라우저로 우회하지 않고 실제 적용/입력 시각 검수는 따로 남긴다.

## 이번에 보여 줄 것

- 준비 화면은 세 짐의 쓰임과 추가량만 비교한다. 이름 칸은 없앤다.
- 기존 `opening_bus_repair`의 세 성공 결과 **뒤**, `opening_failed_appeal` **앞**에서 도윤이 이름을 묻는다. 기존 수리 비용·결과·가족 그림은 유지한다.
- 공구를 챙기는 행동 → 도윤의 질문 → 이름 응답 → 짧은 반응 → 기존 이송 명령서 장면. 출발 결심을 앞당기거나 새 보상을 만들지 않는다.
- 인사 이후의 민원 장면은 실제 첫 문맥만 인용한다. 전체 오프닝을 복제하지 않는다.

## 화면 / 상호작용

- 기존 사건 읽기 화면의 그림 위·본문 아래 구조를 유지한다. 이름 입력만 본문 안의 짧은 응답으로 둔다. 새 캐릭터 생성 화면이나 전면 공책은 만들지 않는다.
- 어두운 항구 `#142027`, 종이 `#ede2c7`, 잉크 `#30372f`, 램프 `#d6b779`. 본문은 UI 글꼴 17px, 큰 글씨 20px. 개인 응답의 작은 제목에만 기존 Journal Hand를 재사용한다.
- 그림은 모든 대화 단계에서 같은 높이·크롭. 본문은 독립 스크롤, 하단 다음 행동은 별도 행. 320px / 큰 글씨 / 낮은 높이에서도 글자를 줄여 맞추지 않는다.
- Studio의 초안 iframe은 스크립트를 실행하지 않는다. 따라서 **읽기 전용 ‘다온’ 예시 + 해시 링크**로 질문/응답/다음 문맥을 비교한다. 임의 이름 입력·키보드·저장 검증 완료로 주장하지 않는다.
- 짐 선택은 네이티브 라디오, 전체 짐은 details. 초안 이동은 링크. 게임·저장·설정·네트워크 전송·자동 적용 없음.

## 초안 시점의 구현 계약 (아래 기록은 초안 당시 상태)

- 준비 이름 필드를 제거하고 미정 이름으로 오프닝 시작. 이미 이름을 정한 기존 저장은 재질문하지 않는다. 기존 ‘나’ 저장의 처리 기준은 실제 migration/오프닝 상태와 함께 결정한다.
- 이름 확정은 명시적 행동. 한글 IME 조합 Enter로 진행하지 않으며, 공백/8자 제한/중복 제출/HTML 삽입/모바일 키보드를 검사한다. 미입력은 같은 자리에서 안내한다. 이름이 ‘나’가 되는 어색한 대사는 만들지 않는다.
- 이름 질문의 진입/뒤로/확정/새로고침/이어가기와 다음 장면을 저장된 사건 커서에 연결한다. 수리 비용을 다시 부과하지 않으며 이미 지급된 결과 문장은 바꾸지 않는다.
- 이름은 텍스트로만 표시하고 조사 처리를 검증한다. 외부로 전송하지 않는다.
- 세 수리 분기, 기존 이름/미정 이름 저장, 결과 재접속, 입력 중 재접속, 확정 후 재접속, 민원 장면까지 실제 엔진과 읽기 파서로 검사한다.

## 검수 기록

- 기존 가족 그림 `opening-bus-family-v3.webp` 원본을 직접 관찰했다. 하진·유나·도윤만 등장하며 이번에 새 그림을 만들거나 편집하지 않는다.
- 구현 전 실제 상태: 12:26:29Z, `name/packing`, game:null, 360×728, scroll0. loaded/style `1792237587186`, pending:null.
- Studio4327의 실제 `디자인 초안` 창에 `name-introduction-v1`을 선택해 열었다. 초안 iframe은 360×728, sandbox는 기존 빈 값 그대로다. 새 문서를 선택할 때 일시적으로 about:blank가 남아 독립 초안 창만 재로드한 뒤 정상 표시를 확인했다. 실제 게임을 재로드하지 않았다.
- 질문→응답→기존 이송표 문맥, 앞 대화/이름 다시 보기, 짐 선택→준비 안내→짐 복귀/인사를 실제 링크로 확인했다. 복귀 뒤 부품 상자 선택도 유지됐다.
- 초안 QA 중 `:has(section:target)`의 기본 질문 숨김 규칙이 `#ask` 복귀도 가리는 문제를 발견했다. 소유 블록에 `:not(:target)`을 넣고 표시 회귀 검사 및 실제 복귀를 다시 확인했다. 게임에 배포된 오류가 아니다.
- 360 기본 질문/응답, 320 큰 글씨 질문/짐 선택/물자 펼침·아래 스크롤을 직접 관찰했다. 버튼은 별도 하단 행에 남는다. 세 인물 얼굴과 그림 높이·크롭이 대화 단계에서 유지된다. [캡처](../../qa-artifacts/name-introduction-v1/)는 **독립 초안 증거**이며 실제 사용자 게임·휴대폰·키보드 QA가 아니다.
- 최종 전체 `npm run test:source` **727/727**, `git diff --check` 통과. 신규 4개 검사는 격리·링크·고정 예시·정확한 짐 수치·CSS 계약을 확인한다. 네이티브 이름 입력/IME/저장/migration/짧은 키보드 viewport는 아직 구현·검수하지 않았다.
- 작업 후 실제 GET 12:32:22Z: `name/packing`, game:null, 360×728, scroll0, loaded/style `1792237587186`, pending:null, applying:false로 동일하다. 이번 초안은 CSS live apply나 구조 적용 대기를 만들지 않았다. 주요 게임 소스와 생성 HTML의 작업 전후 SHA256도 동일하다. 실제4319의 기존 Chrome 차단·다운로드 권한은 재시도/우회하지 않았다.
- 게임 디렉터·UI·대화·입력 지침에 따라 사건 안의 짧은 응답으로 제한하고, 새 입력/저장 통합 계약을 별도로 뒀다. 새 화면을 본 뒤 Sang과 논의하고 실제 연결한다. 기존 준비 이름 칸은 **현재 게임에는 아직 남아 있다**.
