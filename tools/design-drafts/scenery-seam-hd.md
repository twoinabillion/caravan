# 밀양 → 대구 HD 접합 후보

2026-10-10. Sang이 이전 이음새의 화질 문제를 지적하고 고해상도 연결부 제작을 승인했다. 새 후보의 게임 연결이나 전체78구간 완성 승인은 아니다.

## 바뀐 것

- 정본 밀양·대구1024×576 두 장은 바이트·방향·크기·72% 도로 기준선 그대로 보존한다.
- 종전1024px 띠를 세 화면에 펼쳐 약341px/화면을 쓰던 방식 대신, 한 화면당1024px를 배정한 새 연결 지형을 제작했다. 480px·DPR2까지 업샘플링하지 않는다.
- 세로512조각·높이 변형을 없애고 세 그림을 동일한 비례 크기로 투영한다. 접합은 고정된64px/6.25% 공간 겹침이며, 시간에 따른 도시 dissolve나 가림막은 없다.
- 하늘·도로·달구지는 별도. 도시 자체는 역방향에도 반전하지 않는다.
- Studio `scenery-seam-hd-v1` 등록, 이전 도시v3는 비교용으로 남기고 추천에서 내렸다. 초안에는 게임 스크립트·저장 접근·자동 재생이 없다.

## 제작 출처

내장 `image_gen.imagegen`에 필수 정본4장과 실제 도시 끝부분의 QA 참조를 첨부했다. 전체 프롬프트/성공 출력 경로는 `scenery-seam-hd/generation-v1.json`, `generation-v2.json`에 있다. 버전별 마스터·해시·도시 해시·규격은 `provenance-v*.json`에 보존한다.

- v1: 양쪽 도시를 한 참조 보드로 전달. 능선 높이와 알파가 불일치하고 비례 contain 정규화에서1px 투명 열이 생겼다. 보존하되 초안에서 사용하지 않는다.
- v2: 실제 밀양 마지막64px와 대구 첫64px를 그대로 붙인 빈 중앙 템플릿을 생성 도구의 편집 대상으로 전달했다. 도시 정본 자체를 편집하지 않았다.
- 실제 출력1672×941 → 너비1024 비례 축소 →1024×576 sRGB WebP q94/alpha100,124,610bytes. 아트의 샤프닝·색변경·블러·세로 변형·알파 재칠은 하지 않았다.
- 배포 자산: `assets/ui/road-connectors/miryang-daegu-v2.webp`. 실제4319 `/__live/assets` GET에서 목록 노출 확인. 실제 게임 크롭은 미검수/미연결.

## 직접 관찰한 범위

실제4327 Studio 디자인 초안 창에서 새 후보를 선택했다. 독립 예시이며 사용자의 실제 플레이를 재현하지 않는다.

- 360: 첫/끝 접합 정지 화면.
- 480: 첫/끝 접합, 대구 쪽 역방향 재생, 멈춤 전후 같은 풍경 유지, 재개 컨트롤.
- 320: 역방향 첫 접합, 정방향 재생 전후 이동 화면. 글/조작이 겹치거나 가로로 잘리지 않았다.
- 도시·차량·도로는 고정 크기로 유지되고 전환 중 세로 조각 늘이기는 쓰지 않는다.
- 최종 검토 화면은360, 정방향, 재생 꺼짐. OS 모션 감소는 소스 검사만 했으며 실제 설정 전환/물리 기기는 미검수.

순간 캡처들은 전 프레임 동영상/실제 게임 주행 검수가 아니다. iframe read-only 측정 접근은 불가하여 숫자상 pause 위치 동일성을 주장하지 않는다.

## 남은 결함 — 아직 생산 승인 아님

- 생성 도구는 양끝 보호 요청을 픽셀 그대로 지키지 않았다. 알파192 윤곽 기준 왼쪽 능선이 정본 끝보다 약13sourcepx 낮고, 오른쪽은 약1px 차이다. 짧은 겹침에서도 윤곽/색 정밀 정합은 추가 수정 대상이다.
- 하단64행 알파 최솟값249,255 혼재. 하단행 완전255 픽셀0/1024. 큰 투명 구멍은 없지만 완전 불투명 지면 계약을 통과한 것이 아니다. 숨기거나255로 덮어칠해 승인하지 않는다.
- 기존78구간을 새HD표준으로 전수 재제작/승인한 것이 아니다. 대형 랜드마크/정본 도시/고해상도 연결부의 동일 톤 검토, 실제 canvas 캐시·디코딩·감속·사건 정차/재개·도착/재출발·새로고침이 남는다.
- 추가 자산을 내장할 때 기존80MB 상한을 올리지 않는다. 현재 게임 gate/내장 목록에 넣지 않았으며 자산 용량 전략은 적용 전 확인한다.
