## 계획과 범위

Sang의 “그냥 계획하고 바로 수행해”에 따라 새 디자인/기능 대신, 현재 준비 화면 보존 → 앱 백그라운드/복귀의 진행·저장·소리 점검 → 실제 결함 수정 → 기존 AIT 재빌드를 진행했다. 용량 최적화, 별도 APK/IPA 제작, 설치·업로드·배포는 하지 않았다.

## 재현한 결함과 수정

- 기존 lifecycle 소유자는 소리만 중단했다. 실제 UI frame loop는 `document.hidden`/`pagehide`를 검사하지 않았다. 실제 엔진·UI loop·lifecycle 함수를 분리 VM/임시 저장에서 실행하자, 숨김 후 1초 간격 프레임120회 동안 주행1.10582→10.725820000000018km, 게임 시각450.488→494.888분, 연료41.98370372→40.5022237199998L로 변했다. 이는 강제로 재현한 프레임 입력이며 특정 휴대폰의 실측 현상이 아니다.
- `src/07-ui.js`의 기존 loop 소유자에 transient pause와 프레임 시계 초기화를 추가하고, 기존 `src/07e-ui-audio.js` lifecycle에서 호출한다. 숨김/조기 pagehide는 진행·그림·HUD·ambient sync를 차단한다. 복귀 첫 프레임의 dt는0이며 이후 정상 간격으로 재개한다. 처음부터 숨겨진 문서도 다시 표시되면 정상 재개한다.
- lifecycle의 활성 화면 selector `.screen.on`을 실제 DOM의 `.scr.on`으로 맞췄다. UI 배치·그림·물자·게임 저장 schema는 바꾸지 않았으며 pause를 저장 데이터에 넣지 않는다.
- 회귀 검사 `tests/test_app_lifecycle.cjs`: 숨김 프레임, pagehide 선행/숨김 pageshow, 숨김 중 프레임 없음, 초기 숨김 로드, 실제 화면/저장 재개, 열린 modal, 지급된 오프닝 결과 재로드·중복 지급 방지·다음 장면의7경로. 기존 코드에서 처음5경로 실패를 확인한 뒤 수정본7/7 통과.
