## 새로 발견하고 수정한 초기화 오류

수정 전 실제 번들의 load handler에서 `navigator.serviceWorker` 접근 SecurityError가 콘솔에 남았다. opaque iframe에서는 API 속성이 존재해도 getter 접근이 거부된다. 기존 try/catch는 register()만 감싸고 cleanup/controller 접근을 놓쳤다. 이는 이 검수판에서 재현된 선택적 기능 오류이며, 실물 앱이 같은 오류로 종료됐다는 뜻이 아니다.

`src/07-ui.js` 기존 boot 소유자에서 API 접근부터 기존 try/catch 안으로 옮기고 같은 container를 재사용했다. 미지원/접근 거부는 건너뛰며 Toss/file 스킵, 로컬 cleanup 범위, 명시적 ?pwa 등록, online/visible update, 첫 설치/기존 제목 화면의 갱신 계약을 보존한다. 저장/게임플레이/UI/CSS/아트 변경 없음.

- 신규 실제 boot block 검사7/7, 기존 앱 shell 포함11/11. getter/동기 cleanup/controller/등록·update 거부, Toss/file/미지원, 정상 hosted/local PWA, 숨김/online, 타이틀1회 reload 확인.
- 전체 `npm run test:source` **691/691**, 실패0, 약34.1초. `git diff --check`·release gate 통과.
- `npm run build` 성공. HTML106,259,767bytes/SHA256앞12 `e5f141be102b`. 기존 Toss `caravan.ait`88,121,812bytes/`8a56f26caf2e`, 호환2개 동일. RN0.84.0/0.72.6. APK/IPA나 외부 배포가 아니다.
- 수정 후 새 격리 탭에서 최신 번들 타이틀→준비 진입 확인. 기존 serviceWorker 접근 오류는 사라졌다. Chrome 확장 프로그램의 별개 오류는 남았으므로 콘솔 오류0이라고 보고하지 않는다. 전체 밀양 경로는 이번 boot 보강 전의 동일 게임플레이 코드로 검사했고, 새 번들은 부팅/준비 재확인이다.
