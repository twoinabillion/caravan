# Responsive canvas aspect audit — 2026-08-18

## 범위

정비소에서 발견된 “캔버스 가로는 유동인데 높이는 고정되어 달구지가 기기마다 눌리는” 문제와
같은 패턴을 전 게임에서 검색하고, 실제 Chrome 320/390/475px 렌더로 확인했다.

재현: `python3 capture.py`

## 결과

| 단계 | 내부 원본 비율 | 320px | 390px | 475px | 판정 |
|---|---:|---:|---:|---:|---|
| 정비소 달구지 | 128/72 = 1.778 | 1.591 (-10.5%) | 2.197 (+23.6%) | 2.788 (+56.8%) | 심각 |

| 여정 지도 | 고정 원본 없음 | 화면별 재계산 | 화면별 재계산 | 화면별 재계산 | 정상 |

`+`는 원본보다 가로로 더 퍼져 위아래가 눌림, `-`는 원본보다 가늘고 세로로 늘어남을 뜻한다.

## 원인

- `drawSettlementVan()`은 128×72 원본 크롭을 항상 캔버스 전체 `vw×vh`로 강제 확대한다.
- 정비소 캔버스는 `width:100%; height:66px`, 개조 비교는 `width:100%; height:94px`라
  화면 폭만 바뀌고 높이는 고정된다.
- 정착지 내부는 236×306 고정 버퍼를 가변 크기 `stl-town-canvas` 전체에 강제로 확대한다.
- 주행 장면은 표시 비율로 논리 높이를 다시 계산하고, 지도는 표시 크기에 맞춰 좌표를 다시
  투영한다. 이벤트·도착·인물 이미지는 `object-fit:cover/contain`을 사용하므로 같은 왜곡은 없다.

## 권장 수정 순서

1. `drawSettlementVan()`에 16:9 비율 보존 렌더를 넣고 정비소·개조 비교가 같은 함수를 쓴다.
2. 정비소 그림 칸을 `clamp(118px,42%,150px)` 정도로 제한하고 캔버스를 `aspect-ratio:16/9`로 둔다.
3. 개조 비교 캔버스도 `aspect-ratio:16/9; height:auto`로 바꾼다.
4. 정착지 무대는 236:306 비율을 보존하거나, 가변 카메라를 도입해 그림과 터치 좌표를 함께
   변환한다. 단순 CSS 변경만 하고 터치 좌표를 두면 안 된다.
