# GitHub Pages 모바일 브라우저 UI 감사 — 2026-08-13

## 범위

- 화면: 정차 상태의 `길 → 목적지` 콘솔.
- 목적: GitHub Pages를 Safari/Chrome 링크로 열어 주소창과 브라우저 도구막대가 보일 때의 실제 게임 영역 확인.
- 현재 빌드를 390×844, 390×664, 375×553, 412×732 CSS viewport로 실행하고 캡처했다.

## 결과

1. **iPhone 13 전체 높이 390×844 — 양호**
   - 콘솔 높이 389.4px, 도크와 겹치지 않는다.
   - 풍경, 목적지 정보, 카드, 출발 버튼을 한 화면에서 확인할 수 있다.

2. **iPhone 13 Safari 도구막대 390×664 — 개선 필요**
   - 주소창이 약 180px의 세로 공간을 가져간 조건을 근사했다.
   - 콘솔 하단이 도크보다 36px 아래로 내려가며, 겹침을 피하기 위해 내부 패널 스크롤이 생긴다.

3. **iPhone SE Safari 도구막대 375×553 — 심각**
   - 콘솔 하단이 도크보다 약 130px 아래에 놓인다.
   - 출발 버튼과 카드 하단이 도크에 가려져 핵심 행동을 안정적으로 누르기 어렵다.

4. **Android Chrome 도구막대 412×732 — 경계**
   - 콘솔과 도크가 약 2px 겹친다. 화면과 브라우저 UI 변동에 따라 시각적 찌그러짐이 발생할 수 있다.

## 원인

- 목적지 콘솔 높이는 화면 너비에서 결정된다(`aspect-ratio: .94`).
- 브라우저 주소창은 가로폭을 바꾸지 않고 세로 높이만 줄인다.
- 따라서 짧은 세로 화면에서도 콘솔은 동일한 높이를 유지하고, 풍경을 최소 높이까지 줄인 뒤에도 공간이 부족하면 도크 아래로 밀린다.

## 다음 권장 수정

- 높이 740px 이하에서는 목적지 콘솔을 단순히 세로로 찌그러뜨리지 말고 `compact-height` 레이아웃으로 전환한다.
- 풍경 최소 높이, 콘솔 내부 네 구역, 도크가 모두 들어오는 높이를 계산해 콘솔 전체를 균일 축소하거나 카드 영역을 접는다.
- 실제 iPhone Safari에서 주소창 열린/접힌 두 상태와 홈 화면 추가 모드를 마지막으로 확인한다.
