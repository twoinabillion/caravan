# 스토리 이벤트 패널 감사 — 2026-08-15

## 범위

- 화면: `세 겹의 이송표` 첫 장면
- 사용자 목표: 장면을 읽고 다음 장면으로 진행한다.
- 증거: `01-user-live.png`, `02-before-475x948.png`

## Step 1 — 첫 장면 읽기 · 상태: 개선 완료

### 강점

- 장면 이미지, 사건 종류, 위치, 제목, 현재 진행도가 한 화면에서 식별된다.
- 자동 진행 상태와 직접 진행 버튼이 모두 44px 이상의 조작 영역을 가진다.

### UX·디자인 위험

- P1: 256×249 정사각형 내비게이션 버튼 이미지를 약 445×64 영역으로 늘여 써서 금속 면이
  심하게 찌그러진다. 화면에서 가장 큰 조작 요소라 완성도를 직접 떨어뜨린다.
- P1: 현재 장면 본문이 제목 바로 아래가 아니라 380px 높이의 reader 한가운데에 배치되어,
  제목과 본문 사이에 읽기 흐름을 끊는 큰 빈 공간이 생긴다.
- P2: `이야기 · 1/4`, `자동 OFF`, `계속`, `다음 장면 · 2/4`가 두 줄의 넓은 도크에
  흩어져 있어 하나의 진행 조작부로 묶여 보이지 않는다.

### 접근성 위험과 한계

- 스크린샷만으로 키보드 포커스, 진행 상태 알림, 자동 재생 중지 동작은 확정할 수 없다.
- 금속 이미지의 비율 왜곡은 기능을 막지는 않지만 버튼 형태를 불명확하게 만든다.

## 구현 방향

1. 현재 장면을 제목 바로 아래에 배치하고 위·아래 구분선으로 읽기 단위를 만든다.
2. 계속 버튼은 최대 360px로 제한한다.
3. 정사각형 버튼 이미지는 54×54로 원비율을 유지해 물리 키처럼 사용하고, 라벨과 다음
   장면 정보는 별도의 텍스트 열에 정렬한다.
4. 자동 진행, 진행 카운트, 직접 진행 기능은 그대로 유지한다.

## 구현 결과

- 현재 장면 본문을 제목 아래 10px 이내에서 시작하도록 바꾸고, 본문 아래에도 구분선을
  더해 하나의 읽기 단위로 묶었다.
- `계속` 버튼 폭을 최대 360px로 제한하고 가운데 정렬했다. 기존 256×249 버튼 이미지는
  54×54 물리 키로 원비율을 유지하며, 버튼 라벨과 다음 장면 정보는 오른쪽 텍스트 열에 둔다.
- 320×578의 짧은 화면에서도 이미지·제목·본문·자동 버튼·계속 버튼이 한 화면에 들어간다.
- `계속`을 누르면 1/4에서 2/4로 진행되며 자동 진행 설정과 접근성 이름은 유지된다.
