# 길 화면 모바일 압축 점검 — 2026-08-13

## 범위

- 정차 상태의 `목적지` 경로 선택 화면과 `머물기` 행동 화면
- 실제 게임 빌드를 Chromium CSS 뷰포트로 캡처
- 대표 규격: 320×578, 360×700, 375×553, 390×664, 430×739, 480×940

## 결론

길 화면은 430×739 이상에서 정보 계층과 여백이 안정적이다. 360×700과 390×664에서는 기본 조작은 가능하지만 목적지 설명과 경로 사실 카드가 일부 잘리거나 사라져 밀도가 과하다. 375×553과 320×578에서는 하단 도크가 콘솔의 가시 영역을 크게 차지하고, 경로 지도 라벨이 겹치므로 별도의 짧은 화면 규칙이 필요하다.

## 단계별 상태

1. **375×553 · iPhone SE Safari 경로 선택 — 나쁨**
   - 지도 라벨이 겹친다.
   - 목적지 세부정보와 출발 버튼 하단이 첫 화면에서 가려진다.
   - 하단 도크가 장갑 콘솔 위로 올라와 콘솔이 눌린 인상을 준다.

2. **360×700 · Galaxy S24 Chrome 경로 선택 — 보통**
   - 지도, 목적지 카드, 출발 버튼은 조작 가능하다.
   - 목적지 설명과 거리·시간·연료 카드가 콘솔 내부에서 잘린다.
   - 지도 라벨이 가까워 읽기 어렵다.

3. **390×664 · 일반 iPhone Safari 경로 선택 — 보통**
   - 전체 구조는 유지되고 하단 도크와 콘솔은 분리된다.
   - 경로 사실 카드의 하단이 목적지 캐러셀에 먹혀 정보가 불완전하다.

4. **430×739 · iPhone Pro Max 경로 선택 — 좋음**
   - 지도, 장소 설명, 세 개의 경로 사실, 목적지 캐러셀, 출발 버튼이 모두 보인다.
   - 정보 계층과 터치 영역이 안정적이다.

5. **480×940 · 큰 Android 경로 선택 — 좋음**
   - 가장 여유롭고 달구지 배경과 콘솔이 모두 충분히 보인다.
   - 불필요한 늘어짐 없이 기준 레이아웃이 유지된다.

6. **375×553 / 360×700 · 머물기 — 나쁨 / 보통**
   - 375×553에서는 네 번째 행동과 콘솔 하단이 첫 화면에서 가려진다.
   - 360×700에서는 네 행동이 모두 들어가지만 설명 문장이 여러 줄로 눌려 보인다.

## 강점

- 하단 메뉴 버튼과 주요 출발 버튼은 대부분 44px 이상의 터치 높이를 유지한다.
- 430px 이상에서는 장갑 콘솔 이미지와 실제 HTML 정보가 자연스럽게 결합된다.
- 폭이 달라도 HUD, 달구지, 하단 메뉴의 시각 언어는 일관된다.

## 우선 개선안

1. `max-height: 620px`에서 정차 배경 높이를 줄이고 콘솔을 12–20px 위로 올린다.
2. `max-width: 390px`에서 지도 라벨을 두 줄로 분리하거나 선택 목적지 외 라벨을 축약한다.
3. `max-width: 400px`에서는 장소 설명을 한 줄로 제한하고 경로 사실을 한 줄 요약으로 바꿔 캐러셀과 충돌하지 않게 한다.
4. 짧은 화면에서 하단 도크 높이를 조금 줄이되 버튼의 실제 터치 영역 44px은 유지한다.
5. 머물기 목록은 375×553에서 내부 스크롤 가능성을 더 분명하게 표시한다.

## 접근성·검증 한계

- 캡처상 주요 버튼의 터치 높이는 대체로 확보됐지만, 작은 글씨와 겹치는 지도 라벨은 저시력 사용자에게 위험하다.
- 이 점검은 Chromium의 CSS 뷰포트 재현이다. 실제 iOS Safari의 주소창 접힘, 안전 영역, 글꼴 렌더링은 실기기 또는 iOS Simulator에서 최종 확인해야 한다.
