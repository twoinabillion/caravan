# Caravan 모바일 UI 점검 — 2026-08-13

## 범위

- 뷰포트: 360×700, 390×844, 430×932
- 흐름: 길 → 머물기 → 목표 → 지도 → 가방 → 메뉴 → 정착지 → 이벤트
- 방식: 현재 `서울까지400km.html`을 Playwright Chromium에서 직접 실행하고 각 상태를 캡처했다.
- 최초 캡처는 수정 전 상태이며, `after/`에는 2026-08-13 개선 적용 후 같은 상태를 다시 캡처했다.

## 개선 적용 결과

- 390×844의 길 콘솔–하단 도크 간격을 약 85px에서 16.8px로 줄이고, 남는 높이는
  도로·달구지 풍경에 배분했다. 430×932도 약 125px에서 18.9px로 줄었다.
- 480×860처럼 너비 때문에 콘솔이 먼저 커지는 화면은 풍경을 소폭 줄여 하단 도크와
  겹치지 않도록 양방향으로 보정했다.
- 지도 라벨은 현재 위치·선택 지점을 우선하고, 다른 도시 점과 충돌하는 지명은 생략한다.
  하단 범례는 두 줄로 줄여 CRT 안에서 끝까지 보이게 했다.
- 목표·지도·가방의 보조 조작과 정착지의 `달구지로 돌아간다`를 44px 터치 높이로
  맞췄다. 캐러셀 페이지 점은 화면 밀도를 유지하기 위해 표시 크기는 그대로 두고
  실제 누르는 영역을 24×24px로 넓혔다.
- 목표 단계와 가방 상세 설명의 최소 글자 크기를 높였다.
- `tests/test_quality_9_accessibility.py`를 현재 v3 목적지 콘솔 선택자와 도구 화면에 맞춰
  갱신했다. 360×700, 390×844, 480×860, 200% 확대 검증이 모두 통과했다.

적용 후 캡처: `after/360x700-*`, `after/390x844-*`, `after/430x932-*`

## 중복 HUD 제거 후속 개선

- 달구지 아래의 큰 연료·차체·시간 계기판을 DOM에서 완전히 제거했다.
- 연료·차체는 왼쪽 위, 날짜·시간·날씨는 오른쪽 위의 38px 높이 소형 HUD로만 남겼다.
- 확보된 높이로 길·머물기 고철 콘솔을 세로 약 6% 늘리고, 측면 스위치 두 칸을 같은
  높이로 중앙 정렬했다.
- 390×844의 길 콘솔은 357.4px에서 389.4px로 커졌고 도크 간격은 16.9px다.
- 360×700, 390×844, 430×932의 콘솔/페이지 오류와 가로 오버플로는 모두 0이다.

후속 캡처: `hud-compact/360x700-*`, `hud-compact/390x844-*`,
`hud-compact/430x932-*`

## 가방·지도 품질 후속 감사

- 가방 수납칸의 아이콘·수량·단위를 한 덩어리로 재배치하고 선택 칸을 선명하게 표시했다.
- 상세 영역에 선택 수량과 실제 정비 결과(`부품 1개`, `차체 +35/+45`)를 표시한다.
- 정보 확인과 실제 정비 행동을 색과 위계로 구분했다.
- 지도 하단 선택 길과 CTA는 금속 슬롯 안에서 겹치지 않도록 점유 영역을 고정했다.
- 상세 기록: `polish-audit.md`; 전후 캡처: `polish-before/`, `polish-after/`.

## 총평

390px 전후의 일반적인 휴대폰에서 주요 흐름은 동작하고, 가로 스크롤이나 화면 전체
잘림은 보이지 않는다. 길·머물기 콘솔과 목표·지도·가방의 물성도 일관된다. 다만
세로가 긴 기기에서 남는 높이를 풍경에 돌려주지 않아 콘솔과 하단 도크 사이에 큰
빈 공간이 생긴다. 지도와 도구 내부에는 44×44px보다 작은 보조 조작도 남아 있다.

## 단계별 상태

### 1. 길 — 보통

- 캡처: `390x844-01-route.png`
- 360×700에서는 콘솔과 하단 도크가 약 2px 간격으로 붙는다.
- 390×844에서는 약 85px, 430×932에서는 약 125px의 빈 공간이 남는다.
- 세로 여유를 달구지 풍경에 배분하지 않기 때문에 긴 화면일수록 구도가 느슨해진다.
- 좌우 캐러셀 화살표는 28×44px이고 페이지 점은 5×5px라 터치 표적으로 작다.
- 옆 카드가 화면 밖에 잡히는 것은 캐러셀의 의도된 클리핑이며 가로 페이지 오버플로는 아니다.

### 2. 머물기 — 양호

- 캡처: `390x844-02-stay.png`
- 네 개 행동이 한 콘솔 안에 들어가며 텍스트와 CTA의 우선순위가 읽힌다.
- 360×700에서도 중요한 버튼 잘림은 없었다.
- 길 화면과 마찬가지로 긴 기기에서는 콘솔 아래 공간이 남는다.

### 3. 목표 — 보통

- 캡처: `390x844-03-goal.png`
- 목표 단계, 확인 단서, 다음 행동의 구조는 명확하다.
- 도구를 화면 중앙에 놓아 위·아래 검은 여백이 균형을 이루지만, 본문 글자가 작다.
- `지도에서 보기`는 높이 31px, 360px 폭의 `길로 돌아가기`는 약 36px라 권장 터치 크기보다 작다.

### 4. 지도 — 개선 필요

- 캡처: `390x844-04-map.png`
- 전국 경로와 현재/선택 지점의 색 구분은 잘 된다.
- 수도권·영남권처럼 노드가 모인 곳은 지명과 경로가 겹쳐 작은 화면에서 읽기 어렵다.
- 하단 범례 문장이 한 줄에 과도하게 들어가 오른쪽이 잘린다.
- `이 길 선택`은 360px에서 88×38px이고 좌우 도구 탭도 44px보다 작다.

### 5. 가방 — 보통

- 캡처: `390x844-05-bag.png`
- 물·식량·연료, 차체·보급, 수납칸의 정보 구조는 이해하기 쉽다.
- 가죽 수납칸과 숫자의 정렬은 세 뷰포트에서 유지됐다.
- 상세 행동 버튼은 높이 약 35–39px이고 도구 전환 영역은 44×34px라 터치 표적으로 작다.
- 수납 이름과 상세 설명은 작은 폰에서 7–10px 수준이라 장시간 읽기에 부담이 있다.

### 6. 메뉴 — 양호

- 캡처: `390x844-06-menu.png`
- 2열 카드가 360px에서도 겹치지 않고 화면·소리·백업 카드도 자연스럽게 이어진다.
- 버튼 크기와 라벨 구분에 눈에 띄는 모바일 결함은 없었다.

### 7. 정착지 — 보통

- 캡처: `390x844-07-settlement.png`
- 장소 카드, 자원 요약, 동료 반응과 주요 CTA가 한 화면에 들어온다.
- 360px에서는 장소 카드들이 서로 가까워져 배경 인물/핫스폿과 겹치며 밀도가 높아진다.
- 보조 `달구지로 돌아간다` 조작은 높이 38px로 작다.

### 8. 이벤트 — 양호

- 캡처: `390x844-08-event.png`
- 장면 이미지 → 사건 제목/앞 이야기 → 결정의 읽기 순서가 명확하다.
- 두 선택지는 충분한 높이를 가지며 360px에서도 잘리지 않는다.
- 선택지가 두 개뿐인 장면의 하단 여백은 크지만 조작을 방해하지는 않는다.

## 원인

`renderPanel()`이 게임 화면에 `game-viewport-locked`를 추가하고,
`scheduleStoppedStageFit()`은 이 클래스가 있으면 즉시 종료한다. 따라서 이미 존재하는
“남는 높이를 풍경에 돌려주는” 계산이 실제 정차 화면에서는 실행되지 않는다. 콘솔은
화면 너비를 기준으로 정사각형에 가깝게 고정되므로 긴 기기에서 남는 세로 공간이 그대로
빈 공간이 된다.

기존 `test_quality_9_accessibility.py`는 현재 v3 콘솔에 없는 `.route-option`과
`[data-go]` 선택자를 사용한다. 360×700에서 실패한 뒤 예외로 중단되어 새 UI의
390/480px 검증까지 도달하지 못한다. 현재 모바일 회귀 게이트로 신뢰하기 어렵다.

## 권장 수정 순서

1. 긴 화면에서 남는 높이를 정차 풍경에 배분해 달구지와 도로를 더 보여준다. 360×700
   구도는 그대로 두고, 콘솔과 도크 사이 목표 간격을 16–24px로 제한한다.
2. 지도 범례를 줄이거나 두 줄로 만들고, 밀집 지역의 지명 충돌을 완화한다.
3. 지도·목표·가방의 모든 보조 조작을 최소 44×44px의 실제 클릭 영역으로 확장한다.
4. 목표·가방의 최소 본문 크기를 올리고 긴 문장은 단계적으로 줄인다.
5. 접근성 회귀 테스트를 v3 선택자와 실제 도구 조작에 맞게 갱신한다.

## 증거 한계

스크린샷과 DOM 치수로 레이아웃·가독성·터치 표적 위험을 확인했다. 실제 iPhone Safari와
Android Chrome의 주소창 축소, 노치/홈 인디케이터 안전영역, 동적 글자 크기, VoiceOver와
TalkBack 읽기 순서는 별도의 실기기 검증이 필요하다. 이 점검만으로 접근성 준수를 주장하지 않는다.
