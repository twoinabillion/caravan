# Caravan Event / Story UI Review — 2026-08-12

## Audit scope

- Surface: 길 위의 일반 사건, 인물 대사, 선택, 결과 화면.
- User goal: 장면과 인물을 읽고, 예측 정보 없이 행동을 선택한 뒤 결과를 자연스럽게 이어 본다.
- Viewport: 480 × 860 CSS px.
- Evidence: current browser captures from this audit run.

## Steps

### 1. 사건 등장 — needs refinement

![사건 등장](../../tests/shots/story-after/action-minji-01-setup.png)

- Strength: 장면 이미지가 크고 달구지·민지·날씨가 한 번에 보여서 세계관 전달력이 좋다.
- Risk: 제목 아래 본문 한 줄이 화면 중앙의 큰 빈 공간에 고립된다. 하단의 큰 `계속` 버튼 장식은 이미지보다 더 강하게 보여 시선이 끊긴다.
- Recommendation: 이미지, 사건 제목, 현재 대사를 하나의 고정된 읽기 영역으로 붙이고, 진행 버튼은 더 얇은 하단 조작부로 낮춘다.

### 2. 인물 대사 — needs refinement

![인물 대사](../../tests/shots/story-after/action-minji-02-signal.png)

- Strength: 인물 초상과 화자명이 있어 누가 말하는지 분명하다.
- Risk: 작은 초상과 말풍선이 넓은 빈 바닥 한가운데 떠 있다. 위의 장면 이미지 속 민지와 아래 초상이 서로 다른 레이어처럼 보여 연쇄 장면의 생동감이 약해진다.
- Recommendation: 초상, 이름, 대사를 가로형 `무전 기록` 한 덩어리로 만들고 이미지 바로 아래에 붙인다. 장면 컷이 바뀌면 이 영역만 부드럽게 교체한다.

### 3. 행동 선택 — needs refinement

![행동 선택](../../tests/shots/story-after/combat_walker_strike.png)

- Strength: 행동 번호와 이름이 있어 선택 구조 자체는 이해할 수 있다.
- Risk: 사건 정보, 교전 정보, 선택 목록, 페이지 이동이 여러 층으로 겹친다. 네 번째 선택은 접히고 `이전/다음`, `상세 정보`가 경쟁한다. 회색 글씨가 작고 카드가 모두 비슷해 행동의 차이가 약하다.
- Recommendation: 상단 이미지는 유지하고, 제목 아래에는 현재 상황 한 줄만 남긴다. 선택은 화면에 2–4개를 모두 보이게 하며 `번호 + 행동 동사 + 필요한 현재 자원`만 표시한다. 성공 확률이나 미래 결과는 표시하지 않는다.

### 4. 결과 확인 — mostly healthy, needs polish

![선택 결과](../../tests/shots/story-after/action-minji-03-collapse.png)

- Strength: 방금 선택, 실제 자원 변화, 인물 반응의 순서가 명확하다. 미래 예측 없이 이미 일어난 결과만 보여준다.
- Risk: 결과 칩과 대사 사이가 많이 비고, 큰 `길로 돌아가기` 버튼이 다시 화면의 주인공이 된다. `사건 마침`, `자동 진행이 끝났습니다`, 버튼 문구가 같은 종료 의미를 세 번 반복한다.
- Recommendation: 결과 수치와 대사를 한 패널로 모으고 종료 문구는 하나만 둔다. 버튼은 상황에 맞게 `시동을 건다`, `다음 장면`, `길로 돌아간다`처럼 구체적인 동사로 바꾼다.

## Recommended direction

하나의 `사건 기록 장치`가 네 상태를 그대로 유지한다.

1. 상단 40%: 장면 이미지와 컷 번호.
2. 중앙: 사건 종류, 제목, 현재 한 문단 또는 한 인물 대사.
3. 하단: 진행, 행동 선택, 결과 종료가 같은 높이와 같은 위치를 사용한다.
4. 선택 버튼은 일반 `확인`을 쓰지 않고 실제 행동을 적는다.
5. 결과는 발생한 변화만 보여 주고 위험 신호, 만날 인물, 성공 전망 등 미래 정보는 노출하지 않는다.
6. 일반 사건, 대화, 전투가 같은 외곽 규격을 공유하되, 내부 색은 스토리=청록, 위험=적색, 결과=호박색 정도로만 바꾼다.

## Accessibility risks

- 선택 카드의 보조 글씨와 상단 진행 표시는 작은 회색 텍스트라 대비와 가독성 재검증이 필요하다.
- 선택 목록 페이지 이동은 행동 카드를 가리고 흐름을 분리한다. 한 화면 안에 선택을 배치하는 편이 키보드와 터치 모두 단순하다.
- 초점 표시와 스크린리더 읽기 순서는 화면 캡처만으로 확인할 수 없으므로 구현 후 실제 브라우저 검사가 필요하다.

## Verdict

이미지 자산과 이야기 구조는 충분히 좋다. 외곽 틀을 새로 많이 만들기보다, 현재 사건 터미널 하나의 세로 리듬과 버튼 언어를 통일하면 가장 큰 개선을 얻는다.
