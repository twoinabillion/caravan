# 사건·보조 화면 정리 감사

- 일시: 2026-08-15
- 검토 환경: Google Chrome, 390 × 844 CSS px
- 대상: 사건 읽기/선택, 달구지 메뉴, 동료, 설정, 일지, 야영

## 현재 화면 근거

1. `01-event-reading-before.png` — 장면 이미지는 강하지만 컷 번호, 유형·위치·진행률, 자동 진행, 과장된 계속 버튼이 같은 정보를 반복한다.
2. `02-event-choice-before.png` — 선택지는 읽기 쉽지만 선택지 위의 별도 상태줄이 실제 결정에 도움이 되지 않는다.
3. `03-menu-before.png` — 기능은 명확하나 일반 앱 런처처럼 보이고 화면 아래가 비어 있다.
4. `04-crew-before.png` — 인물보다 표와 테두리가 먼저 보여, 동료 화면이 가장 원시적으로 느껴진다.
5. `05-settings-before.png` — 기능은 안정적이나 동일한 사각 패널이 반복되어 위계가 약하다.
6. `06-journal-before.png` — 정보 위계와 기록의 결이 이미 안정적이다. 큰 변경 대상에서 제외한다.
7. `07-camp-before.png` — 달구지 생활이라는 주제와 행동 위계가 이미 잘 맞는다. 큰 변경 대상에서 제외한다.

## 구현 결정

- 주행 배경의 자동 생성 `서울 n km` 표지판을 제거한다. 목적지·노선 정보는 목적지 콘솔에만 둔다.
- 사건에서는 장면, 제목, 본문, 선택, 결과만 남긴다. 컷 번호·위치/유형 메타·진행률·자동 토글·중복 도크 헤더는 보이지 않게 한다.
- 진행 상태 텍스트는 스크린리더용으로 유지한다.
- 메뉴는 기존 아이콘과 색 체계를 유지하면서 밀도와 계층만 정리한다.
- 동료 카드는 초상과 인물 이름을 우선하고 상태·유대를 한 줄의 계기 정보로 정리한다.
- 설정은 화면 편의, 소리, 백업의 세 덩어리를 유지하되 평면적인 폼 느낌을 줄인다.

## 접근성 확인 기준

- 사건 선택지는 기존 버튼과 키보드 포커스를 유지한다.
- 사건 진행 상태는 시각적 장식에서 제거하되 접근성 트리에는 남긴다.
- 메뉴·동료·설정의 터치 대상은 최소 44px을 유지한다.
- 실제 기기별 브라우저 상단 UI와 OS 글꼴 렌더링은 이 로컬 Chrome 캡처만으로 완전히 검증할 수 없다.

3. `02-event-choice-after.png` — 중복 도크 제목 없이 선택 카드가 장면 바로 다음 단계로 보인다. 선택 버튼의 최소 높이와 번호 표식은 유지됐다. 양호.
4. `03-menu-after.png` — 같은 크기의 일반 앱 카드 느낌을 줄이고, 기존 실제 아이콘과 얇은 상태 레일을 사용한 도구 콘솔로 정리했다. 양호.

7. `06-journal-after.png` — 기존 정보 밀도와 기록 위계를 보존했다. 양호.
