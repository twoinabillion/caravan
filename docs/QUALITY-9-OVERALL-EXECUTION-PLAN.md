# 서울까지 400km 전체 품질 9.0 실행 계획

## 1. 목표

현재 가중 품질 기준선은 약 **8.5/10**이다. 목표는 단순 평균 9점이 아니라 아래 조건을 동시에 만족하는 출시 후보를 만드는 것이다.

- 전체 가중 평균 `9.0 이상`
- 핵심 세그먼트인 여행, 전투, 정착지, 서사, UI가 각각 `8.8 이상`
- 안정성 `9.3 이상`
- 어떤 항목도 `8.2 미만`으로 남기지 않음
- 모바일 단일 HTML `35MB 이하` 유지
- 자동 스모크, 골든 루트, 장기 시뮬레이션에서 소프트락 `0건`

## 3. 실행 원칙

1. 이벤트 숫자를 늘리는 작업은 우선하지 않는다. 이미 888개로 충분하다.
2. 플레이어가 선택하기 전에 차이를 이해하고, 선택한 뒤 결과를 확인할 수 있어야 한다.
3. 정착지는 배경 이미지 위에 범용 마커를 얹지 않는다. 그림의 공간과 행동 위치를 먼저 설계한다.
4. 실패는 가능하되 정보 없이 실패하지 않는다.
5. 새 이미지는 기능적 위치와 상태 변화가 정의된 경우에만 추가한다.
6. 수치 조정은 감이 아니라 자동 시뮬레이션 결과를 기준으로 한다.
7. 모든 화면은 한 번에 하나의 주 행동만 가장 강하게 보여준다.

## 4. 우선순위

### P0. 자산 용량과 측정 기반 확보

현재 실행 HTML은 약 `34.67MB`다. 이 상태에서는 정착지 전용 이미지를 안전하게 확장할 수 없다.

#### 작업

- 모든 장면 이미지의 해상도, JPEG 품질, 중복 사용량을 보고하는 빌드 리포트 추가
- 긴 변 기준을 장면 유형별로 `960~1280px`로 제한
- 시각 차이가 거의 없는 중복 장면 통합
- 품질 손실이 작은 이미지부터 JPEG 재압축
- 신규 정착지 이미지 예산을 장면당 `250~450KB`로 제한
- 빌드 경고 기준 `32MB`, 실패 기준 `35MB` 설정

#### 완료 기준

- 콘텐츠 제거 없이 실행 HTML `30MB 이하`
- 이후 전용 정착지 장면 4개를 추가해도 `33MB 이하`
- 장면별 용량 상위 20개가 빌드 출력에 표시됨

### P0. 장기 플레이 시뮬레이터

#### 측정 항목

- 부산에서 서울까지 1,000회 자동 여정
- 경로별 완주율과 평균 소요일
- 연료·물·식량·차체 고갈 시점
- 전투 단계별 성공, 부분 성공, 실패 비율
- 전술 반복 페널티와 읽어낸 틈 사용률
- 동료 영입률과 좌석 병목
- 이벤트 종류별 반복 간격
- 메인 단서 누락과 엔딩 도달 불가 상태
- 저장·복구 후 진행 불가 상태

#### 목표 범위

- 합리적 선택 정책의 완주 가능률 `95% 이상`
- 소프트락 `0/1,000`
- 일반 전투 최종 성공·부분 성공 합계 `65~82%`
- 정보 대응을 정확히 고른 경우 성공률이 무준비 선택보다 `8~20%p` 높음
- 같은 이벤트가 8개 사건 이내 재등장하는 비율 `1% 미만`
- 모든 주요 경로에서 서울 핵심 단서 회수 가능

## 5. 핵심 개발 트랙

### 트랙 A. 정착지 9.0

밀양을 기준 구현으로 삼는다.

#### 대상 순서

1. 대구 돔 시장
2. 무주 터널 장터
3. 대전 연구 공동체
4. 수원 성곽 공동체

#### 정착지별 필수 구성

- 세로형 모바일 전용 허브 장면 1개
- 장소 기능이 그림만 보고도 구분되는 4개 공간
- 달구지 주차를 위한 의도적 빈 공간
- 범용 이모지와 떠다니는 초상 없는 위치 선택
- 행동 전·후가 그림과 문구에 모두 남는 변화 레이어
- 동료 위치가 선택한 장소로 실제 이동
- 현재 선택한 행동 카드만 강조
- 야간에는 닫힌 공간이 그림과 조명에서도 구분됨
- 거래, 정비, 사람, 현장 행동이 서로 다른 UI 구조를 가짐

#### 완료 기준

- 360×800, 480×860, 840×900에서 핵심 그림과 버튼이 겹치지 않음
- 첫 화면에서 5초 안에 갈 수 있는 장소와 주 행동을 파악 가능
- 정착지별 스크린샷만 보고 도시를 구분 가능
- 모든 현장 행동과 숨은 장소 테스트 통과

### 트랙 B. 여행 루프 9.0

#### 출발 전

- 목적지마다 거리, 시간, 연료, 도로 위험, 기대 기회 표시
- 단순 최단거리와 서사·보급 우회 경로를 구분
- 현재 의뢰와 본편 목표에 유리한 경로를 설명하되 정답으로 강요하지 않음

#### 이동 중

- 선택한 경로의 지형과 지역 풍경이 주행 화면에 지속 반영
- 출발 전에 본 위험이 실제 사건으로 돌아옴
- 차량 빌드와 동료 조합이 이동 사건 선택지를 변화시킴
- 중간 선택이 도착 비용, 관계, 정착지 반응에 남음

#### 도착 후

- 무엇을 얻고 잃었는지 짧은 여정 결산 제공
- 경로에서 한 선택이 정착지 첫 대화 또는 가격에 반영
- 같은 목적지라도 진입 경로에 따라 첫 장면이 달라짐

#### 완료 기준

- 목적지 카드마다 최소 하나의 실질적 차별점 존재
- 경로 선택 후 플레이어가 예상하지 못한 무관한 페널티 제거
- 3개 주요 분기에서 선택별 전용 사건 또는 정착지 반응 존재

### 트랙 C. 전투 9.0

#### 구조

- 1단계: 적의 의도와 지형을 읽음
- 2단계: 대응법을 준비하고 틈을 획득
- 3단계: 준비한 정보를 이용해 실행
- 종료: 전술 흐름, 핵심 순간, 손실, 회복 방법 결산

#### 개선

- 모든 전투 선택에 `의도 대응`, `지형 적합`, `소모`, `위험` 중 필요한 정보 표시
- 요약 모드에서도 결과를 바꾸는 핵심 보너스는 숨기지 않음
- 전투별 최소 하나의 비살상·이탈 경로 보장
- 반복 전술 페널티 상한 설정
- 부상은 단순 수치 감소가 아니라 다음 행동·대사·퍼크에 반영
- 적응 난이도는 플레이어에게 보이지 않게 결과를 조작하지 않고 회복 여지만 조정

#### 완료 기준

- 15개 전투·구조·호송 단계 데이터 완비
- 준비 정보가 최종 판정에 실제 반영
- 같은 상태·같은 선택에서 UI 전망과 실제 판정 계산이 일치
- 1,000회 시뮬레이션에서 특정 전술 하나가 항상 우월하지 않음

### 트랙 D. 차량·진행 8.9

#### 빌드 방향

- 생존형: 물·식량·수면 안정
- 정비형: 차체·연료·부품 효율
- 교섭형: 거래·의뢰·정착지 신뢰
- 은밀형: 관측·검문·전투 회피
- 대응형: 구조·전투·동료 보호

#### 개선

- 업그레이드마다 최소 하나의 사건 선택지 또는 경로 변화 연결
- 강한 업그레이드는 비용이나 다른 슬롯과 상충
- 차체 외형 변화가 주행·정착지·작업대에서 동일하게 보임
- 추천 업그레이드는 현재 경로와 자원 문제를 기준으로 설명
- 의미 없는 중간 단계와 동일 효과 업그레이드 통합

#### 완료 기준

- 최소 4개 빌드가 서울까지 완주 가능
- 한 빌드가 모든 상황에서 최적이 되지 않음
- 업그레이드 80% 이상이 UI 수치 외 실제 사건에 영향을 줌

### 트랙 E. 서사·동료 9.0

#### 메인 서사

- 본편 목표가 20~30분 이상 사라지지 않도록 이동 중 재점화
- 부모 기록, 143년 이송, 남산 코어가 중반부터 하나의 질문으로 모이게 함
- 엔딩 선택 전에 동료가 플레이어의 과거 선택을 근거로 의견 제시
- 엔딩 뒤 경로·정착지·동료 선택의 후일담을 짧게 회수

#### 동료

- 각 동료가 낮은 사기, 부상, 전문 분야에서 능동적으로 행동
- 동료 조합별 사건을 기능 보너스가 아니라 관계 변화로 확장
- 합류하지 않은 동료도 소문이나 후속 흔적으로 존재
- 같은 대화에서 관계 수치가 중복 상승하지 않음

#### 완료 기준

- 핵심 동료 6명 모두 첫 만남, 과제, 임시 동행, 두 번째 사건, 합류 이후 회수 보유
- 엔딩에서 최소 4개의 이전 선택이 명시적으로 회수됨
- 본편 설명을 반복하는 대사 비율 감소

### 트랙 F. UI·접근성 9.0

#### 화면 원칙

- 주행: 상태와 다음 길
- 지도: 위치와 경로 비교
- 정착지: 공간과 행동
- 전투: 의도와 대응
- 상태: 상세 수치와 지식
- 일지: 과거 선택과 단서

#### 개선

- 화면마다 가장 강한 버튼은 하나만 유지
- 배경 그림 위에는 위치와 상태에 필요한 표지만 배치
- 장식용 이모지 대신 게임 아이콘 또는 텍스트 표지 사용
- 모든 터치 대상 최소 44px
- 색상 외에 아이콘, 문구, 형태로 위험 상태 구분
- 큰 글자에서 카드 높이와 스크롤 영역 재계산
- 움직임 감소 설정에서 장면 전환과 위치 이동 애니메이션 제거

#### 완료 기준

- 360px 폭에서 가로 스크롤이 필요한 핵심 행동 없음
- 키보드만으로 모든 모달 진입·선택·종료 가능
- 포커스 복귀와 ARIA 상태 테스트 통과
- 중요 정보가 상세 모드를 켜야만 보이는 경우 없음

### 트랙 G. 오디오 8.6

#### 개선

- 부산, 밀양, 대구, 무주, 대전, 수원, 서울의 지역 환경음 차별화
- 전투 의도 경고, 대응 성공, 압박 상승을 서로 다른 짧은 음으로 구분
- 주행 음악은 지역·시간·위험에 따라 레이어만 변화시켜 반복 피로 감소
- 정착지 행동 완료 후 장소 변화에 맞는 생활음 추가
- 음소거와 사용자 설정을 모든 화면에서 유지

#### 완료 기준

- 화면을 보지 않아도 전투 압박 상승과 선택 완료를 구분 가능
- 30분 플레이에서 동일 루프가 과도하게 반복되지 않음
- 오디오 실패가 게임 진행을 막지 않음

## 6. 실행 순서

### 1단계. 기반 잠금

- 자산 리포트와 이미지 예산 도입
- HTML을 30MB 이하로 축소
- 장기 시뮬레이터 기본 구현
- 현재 점수 기준선 JSON 저장

### 2단계. 핵심 공간 전용화

## 8. 하지 않을 작업

- 목적 없이 이벤트 수를 1,000개 이상으로 늘리지 않음
- 모든 노드를 한 번에 전용 이미지로 만들지 않음
- 단일 HTML 35MB 제한을 넘기면서 자산을 추가하지 않음
- 전투 난이도를 단순 체력·실패 확률 증가로 해결하지 않음
- 정착지 배경 위에 범용 이모지와 초상 마커를 다시 배치하지 않음
- 자동 테스트 통과만으로 재미 9점을 선언하지 않음

## 9. 최종 9.0 판정 기준

아래를 모두 만족할 때만 전체 9.0으로 판정한다.

- 실제 플레이어 2명 이상이 도움 없이 서울까지 완주
- 핵심 선택의 이유와 결과를 플레이어가 설명할 수 있음
- 부산, 밀양, 대구, 무주, 대전, 수원, 서울의 화면을 서로 구분 가능
- 정착지 행동이 단순 버튼 목록이 아니라 공간 안의 행동으로 인식됨
- 전투 실패 원인을 결과 화면에서 이해 가능
- 차량 빌드와 경로가 두 번째 플레이를 실제로 바꿈
- 자동 여정 1,000회에서 소프트락 0건
- 전체 스모크와 골든 테스트 통과, 콘솔 오류 0건
- 실행 HTML 35MB 이하
- 재평가 가중 평균 9.0 이상
