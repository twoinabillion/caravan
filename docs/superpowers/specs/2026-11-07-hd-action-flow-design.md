# 고화질 여정 · 행동과 결과

Sang의 “그런 개선점들을 계획해서 개선해줘”를 실행한다. 승인된 세 축은 행동 결과의 가시성, 여행의 리듬, 다음 행동의 명확성이다. 전체 픽셀 전환은 다시 하지 않는다.

## 이번 구현
1. 정비소: 현재 차량을 유지하고 선택한 장착 가능 부품의 차량 외형을 비용 없이 미리 본다. 미리보기는 보유 상태를 변경하지 않는다. 제목·분야·선택 항목·비용의 위계를 정리하고, 잠김 이유를 항목 옆에 보인다. 실제 요구 조건과 기존 결제 버튼을 유지한다.
2. 완료: 이미 결제한 개조 결과는 HD 부품과 차량 전후 비교를 바로 보여 준다. 완료 후 작업을 재현하는 세 번의 필수 클릭은 없앤다. 작업 순서는 선택해서 읽는 기록으로 남기고 한 번에 정비소로 돌아간다. 수리는 같은 화면을 억지로 재사용하지 않고 정비소 안에 실제 내구 전후와 소모·경과 내역을 보여 준다.
3. 야영: 그림 밑에서 방금 한 준비와 다음 행동을 읽을 수 있다. 식사는 이미 마쳤고, 차량 점검은 취침 후 회복을 예약한 것임을 명확히 한다. 불가능한 준비는 자원 부족/차체 양호 이유를 보이며 실행하지 않는다. 동료 대화의 기존 초상과 수동 읽기를 유지한다.

## 제약
- src/07-ui.js와 src/01-style.html의 기존 소유 블록 안에서 구현한다. 새 엔진·의존성·저장 키·생성 이미지는 도입하지 않는다.
- 원문, RNG, 밸런스, 게임 시간, 자원 결제와 paid reader는 기존 엔진이 계속 소유한다.
- 미리보기·탭·결과 닫기·작업 기록 열기는 무료다. 수리 표시는 실제 사후-사전 값으로, 상한과 시간 진행의 영향을 반영한다.
- 야영을 현재 공구질/요리 중인 자동 작업으로 꾸미지 않는다. 실제로 없는 동료를 추가하지 않는다.
- 360/390 모바일, 데스크톱, 짧은 가로, 큰 글씨, 모션 감소에서 다음 버튼에 도달해야 한다.
- 사용자의 연결된 화면을 강제 새로고침하지 않는다. 현재 live clients=0으로 실제 사용자 장면은 확인 불가. 같은 서버의 별도 QA 문맥에서 검증한다.

## 구현 판단
새 그림이나 장면을 늘리기보다 이미 소유한 고화질 자산과 실제 상태를 더 잘 보여 주는 범위로 진행한다. 긴 대화는 기존 reader, 짧은 정비 결과는 비모달 내역으로 나눠 개입과 읽기 사이의 흐름을 가볍게 한다.
