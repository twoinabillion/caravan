## 1. Source ownership

- `seoul_seen` means seeing the skyline, not arriving in Seoul. Future-arrival promises close at `seoul_open`, the paid city-entry result. Test both flags independently. Keepsake returns require a paid handoff flag or exact legacy completion evidence, never `used` alone; do not invent missing legacy choices.

- Story length is not a reason to remove causality. The default reader must retain the question, evidence and answer that earn a turn, not defer indispensable motives to an optional record. Finale meetings use actually connected cells, not a fixed nationwide cast. Watch volunteers must come from the same healthy/mood-qualified roster as the choice gate; a supporting NPC cannot pay a crew requirement. Keep paid receipts and existing ending mechanics intact.

- Optional story callbacks must use the actual acquired item and completed source, not a broad flag reused by a drink, pickup or loan. Planting is not harvest; a physical rooftop action requires the owned upgrade. Paid legacy results stay frozen even when future entry or resource gates are corrected. Protect each intended mechanics delta explicitly in the story-review contract.

- A fatal time boundary also terminates nested owners such as camp conversations: no bond, keepsake, plan, quality callback or note may change the terminal archive after `applyFx` returns. Route warnings project ongoing thirst at midnight as well as scheduled meals, without blocking departure or changing survival thresholds. Arrival-owned `locEvent` scenes have a separate entry path from weighted pools; test the real arrival path when adding a night gate.
- Renderer categories are not narrative provenance. Road echoes use the saved action label/ID; old unknown actions get neutral text rather than an invented favour. Mutable choice callbacks snapshot their lines, retain explicit legacy IDs, and never rewrite already-paid memories. A retained keepsake count requires a completed choice, not event entry. Display rounding belongs in every result consumer (paged, record, combat and field work), never in state or frozen receipts.

- `서울까지400km.html` is generated output. Never edit it directly.
- UI and responsive behavior live in `src/01-style.html`, DOM in `src/02-dom.html`, data in `src/03*.js`, game state and persistence in `src/04*.js`, and rendering/interactions in `src/07*.js`.
- Find every rule for a component before editing it. If a component already has an owning block such as `bag-code-panel-final`, modify that block. Do not add another late `!important` patch.
- Check compiled CSS declarations with a CSS parser, not whitespace-sensitive substring matching. The reading-density check falsely reported a missing gap because delivery retained a space after the colon. Build contents, a live style revision and actual visual/computed verification remain separate evidence.
- Legacy normalizers may support old markup, but they must explicitly exclude current components that have a maintained layout owner.

## 2. Live development

1. Run `npm run dev:live`.
2. Use the actual current preview. In Live Game Studio, its request supplies the Studio URL, preview URL, current scene and a read-only context endpoint for rechecking during that task. Use that origin even if its port differs from 4318; `http://localhost:4173/` is only the standalone default. Preserve the user's browser profile/save and do not open a new tab or server as if it were the same scene. State/text snapshots are not visual QA; explicitly report missing images or unavailable screen access.
3. CSS-only builds replace styles in place and must not reset the current screen, selection, or scroll position.
4. JS, data, structure, and wired-asset builds show `새 코드 준비됨` in Studio's external **플레이 테스트** toolbar (or the standalone live toolbar above the game iframe). Apply them deliberately. On first migration, update Studio and restart the existing live server, then reload the Studio window once; applying game code alone does not replace the already-loaded Studio/live shell. Keep developer controls outside the game HUD.
5. In live mode, a refresh resumes the current save. Road tools such as 가방, 목표, and 지도 should reopen from the captured preview state.
   The goal notebook belongs only to gameplay. Base-screen transitions must synchronously close it without restoring focus to hidden road controls, and stale clicks/queued focus must not reopen it during intro/title. Discard the old view when leaving gameplay but preserve the boot-time record until live Continue can restore it. Regression: `tests/test_quest_screen_lifecycle.cjs`. Do not apply/reload during an unsaved intro cursor merely to verify a fix; stage it and report that runtime check as pending.
