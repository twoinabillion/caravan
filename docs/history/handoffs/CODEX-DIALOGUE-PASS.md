## 재발 방지 장치 (새로 넣은 것)

`npm run lint:dialogue`가 이제 아래를 자동으로 잡는다. 앞으로 대사를 추가할 때
이 세 가지만 지키면 같은 문제가 다시 들어오지 않는다.

1. **주인공 호칭·화계 계약** — `companionVoices[*].addresses.daon` / `daonRegister`가
   비면 실패. 계약표는 `docs/COMPANION-VOICE-BIBLE.md`의 "Addressing Daon" 절.
2. **「당신」·「너」 금지** — 화자가 확정된 짧은 라인에서 검사.
3. **목발 단어 상한** — "만장일치" 8회 등. 넘으면 실패.
4. **인트로 시한 표기** — "스물엿새 안에"가 아니면 인과 순서 검사에서 실패.

## 작성 규칙 (다음 사람에게)

- 특정 동료가 등장·발화하는 문장은 **지우지 말고** `S.party.includes()` 분기로 감싼다.
  이 코드베이스의 표준이며, 미영입 상태용 대체 문장을 함께 쓴다.
- 선택지 조건은 `req` 안에 넣는다. `minParty`를 `req` 밖에 두면 죽은 키가 된다
  (런타임 `G.choiceReq`가 정규화해 주지만 데이터도 맞춰 둘 것).
- 짧은 라인(banter/chats)의 조건 필드는 **`need`**다(`req` 아님). 지원 키:
  `comp/comp2/party/night/rain/wx/up/tired/dog/lowFuel/region/flag/noFlag/knowledge`.
  화자 탑승 여부는 런타임이 자동 검사하므로 별도로 걸 필요 없다.
- 선행 사건을 전제하는 대사는 그 사건의 결과에 플래그를 심고 `needFlag`로 받는다.

## 검수 시 오탐 주의 (실제로 겪은 것)

- 함수형 `text`를 도달 불가능한 상태(예: `minParty:4` 이벤트를 혼자 상태)로 평가하면
  빈 목록·고아 마침표가 나온다. **게이트를 먼저 확인**할 것.
- `needFlags`(복수형) 배열도 엔진이 지원한다(`04c-engine-travel.js`). `needFlag`만
  찾으면 무게이트로 오판한다.
- 덤프를 만들 때 banter의 조건 필드를 `req`로 읽으면 전부 무조건으로 보인다 —
  실제 필드는 `need`다. 이 실수로 한 챕터가 통째로 오탐이 났었다.
